## 三、★ 踩过的坑（新对话必读，能省几小时）

### 坑 1 · PowerShell 读写文本文件会毁掉 UTF-8（最严重）

- **现象**：`Get-Content -Raw` + `Set-Content -Encoding utf8` 之后，全文件中文变成
  `涓滄柟閫嗚浆` 这类乱码，并且被加上 BOM。原因：PowerShell 5.1 的 `Get-Content` 按 ANSI 解码了 UTF-8 字节，
  回写时二次编码 ⇒ **不可逆损坏**。
- **铁律**：**改本项目的任何文件，只能用编辑工具（read/write/edit），或 Node 脚本
  （`fs.readFileSync(f,'utf8')` / `fs.writeFileSync(f, s, 'utf8')`）。绝不允许 PowerShell 的文本管道碰文件内容。**
- **善后**：这次靠一份转换前的备份回滚了。**每批改动前先做一份备份**（`Copy-Item` 复制文件是安全的，不经过文本编码）。

### 坑 2 · 令牌替换会把 `:root` 里的定义本身替换掉（自引用）

- **现象**：批量把 `#2e4527` 换成 `var(--txt)` 之后，`:root` 里那句 `--txt: #2e4527;` 也变成了
  `--txt: var(--txt);` —— **自引用让全站正文色失效**（回退成继承色）。`--dim` 同病。
- **预防**：**做完令牌替换必须立刻检查 `:root` 内是否有 `--x: var(--x)` 自引用。**
  现成的检查：读 `:root` 段，逐条匹配 `--([a-z0-9-]+)\s*:\s*([^;]+)`，若值里含 `var(--同名)` 就是 bug。

### 坑 3 · 正则里的反斜杠在 shell 里被二次转义

- **现象**：把 Node 脚本内联进 shell（`pwsh -Command "node -e \"…\""`）时，
  `/\s/`、`\d`、`.location\.` 这类转义会被 PowerShell 吃掉一层或直接语法报错；
  多行循环、`&&`、引号嵌套都会炸。
- **铁律**：**超过两三行的脚本一律写成临时文件再 `node 文件`**；查改用"包含判断"而不是正则。
  临时脚本用完即删（不要留在工作区）。

### 坑 4 · 只信"解析后的结论"，不信"脚本自己报成功"

- **现象**（0c 反复翻车三次，每次都以为成功了）：
  1. 脚本打印"已写入 3980 行"，但文件里**一个调色板都没有** —— 因为"删除行集合"把刚写入调色板的那一行也删了
     （单行规则的删除区间 `start+1..end` 落到了下一行，而下一行正是某主题块的首行）。
  2. 同一轮里，脚本还把**不止一个主题**合并成一个 span（从"文件前部的单行边框规则"一直拉到主题块尾），
     中段 9000 字符会被一并删掉。
  3. `.loc-effect` 上除 `color` 之外的声明（needle 的 `text-shadow`）在折叠时被丢掉。
- **预防（照抄即可）**：
  - 改写前**先算结构、再重建文本**（把"要保留的行"拼出来），不要"就地改 + 删"混着来；
  - 落盘前核对**四项**：目标产物数量（如 27 个调色板）、括号配平、关键标记出现次数、行数变化方向；
    **不满足就只写临时文件、绝不覆盖正式文件**；
  - 落盘后**再用文件内容复核一次**（本次就是靠这一步发现产物是空的）；
  - 等价性核对：把收口前备份里每个地形的**每条声明值**拿到新文件里找出处，缺失数必须是 0（本次 345 条、缺失 0）。

### 坑 5 · `@media` / `::before` 的解析陷阱

- 注释里出现的 `@media` 字样会被当成真 at-rule；它后面紧跟的大括号在"去注释后的文本"里不存在，
  深度扫描会提前结束，**掩码反向盖住一大片正文**（本次盖住了 9000~43000 字符，正好是全部地形主题）。
- **铁律**：解析 CSS 时**在原文偏移上做**（注释只做"跳过判定"，不要先替换成长度不同的字符串再算偏移），
  并且**先算注释区间、再算 at-rule 区间**，计算 at-rule 时跳过落在注释里的匹配。
- **单行规则**（`{ … }` 写在同一行）必须单独处理：不能假设 `{` 后面就是换行；
  删除区间要避免"start+1 落到下一行"。

### 坑 6 · CSS 层叠的"特异性 + 顺序"（最阴险的一个，用户实测才发现）

- **现象**：0c 收口后**所有地形**的效果文字都变成浅绿。原因：
  - 收口前各地形是 `.location.演唱会 .loc-effect`（特异性 **30**），能压过正文里的
    `.loc-mid .loc-effect { color: var(--dim) }`（特异性 **20**，`--dim` 就是浅绿 `#64805c`）；
  - 收口把它们折成了**变量**，取色规则只剩 `.location .loc-effect`（特异性 **20**，且在正文**前面**）
    ⇒ 同特异性、后者胜 ⇒ 全地形掉回浅绿。
- **修法**：**不给所有规则加特异性**（那是军备竞赛），而是在**文件最末尾**放一条针对正文那条规则的高特异性版本：

```css
.loc-mid .location .loc-effect,
.location.zone .loc-effect,
.location .loc-mid .loc-effect { color: var(--locink); }
```

- **预防（抽成通用检查）**：**把"高特异性规则折成变量"之前，先列出"同属性、同特异性、但排在后面"的所有规则**，
  确认折完之后谁赢。**做法**：解析全文件规则 → 对目标元素构造"假想元素链" → 按
  (特异性, 源码顺序) 选出胜者 → 断言胜者就是新规则。
  ⚠️ 写这个判定脚本时注意：**单行规则、逗号选择器、跨行选择器**都要覆盖
  （本次前两版判定脚本都因为漏了单行规则而**误报**，差点让我去改本来没问题的代码）。

### 坑 7 · 判定"看起来重复"的规则要小心

- `.location.<id> { border-color: rgba(202,152,30,.6) }`（文件前部的 27 条单行边框规则）看着像主题块里
  `border-color` 的重复，**其实是两层不同视觉**（格子描边 vs 主体边框），值也不同。我删过一次，回滚了。
- **预防**：**删"疑似重复"之前，把两边的取值都打印出来对比**；值不同就不是重复。

### 坑 8 · "底色深浅各半"的地形，单一文字色救不了

- 针之山 / 秘封俱乐部的卡面是上深下浅、各占一半，文字跨在分界线上：白字 3.36、黑字 3.51，**都不达标**。
- **结论**：这类必须**给文字垫底衬**（或压暗文字所在的那条带），不能指望换文字色解决。
- 另外：**半透明底色要逐层合成再算对比度**（区域底色 → 卡面底色 → 页面底色），
  否则算出来的对比度会明显偏高（本次第一版测量就高估了幽灵洋馆/魔法风暴等）。

### 坑 11 · 手机端顶栏 / 底部条改起来顺手，但有三处必踩

> 坑 9（变量 vs 后代长手覆写）与坑 10（徽标特异度不能抬高）写在 §二「1 · 卡片渲染统一」里 —— **改卡面先看那两条**。

- **`display: contents` 会"吃掉"容器自己**：手机上把 `.hud` 设成 `display: contents` 后，
  它自己的 `margin-left: auto` / `gap` / `justify-content` 全部失效，位置只由 `.topbar` 的网格决定 ——
  改完要回来看「回合是否真的居中」（`grid-template-columns: 1fr auto 1fr` 的两侧等宽才是精确居中）。
- **可点的块要自己 `pointer-events: auto`**：`.corner-center`（底部中间那块容器）整体是 `pointer-events:none`，
  里面新加的按钮/方块不显式放开就点不到 —— 而且**不会有任何报错**。
- **按钮文案是"图标 + 文字"两段**：`renderControls()` 里任何 `xxxBtn.textContent = …` 都会把
  `.bt-ico` / `.bt-txt` 两段冲成一整段文字（手机上就会漏出全称）。要改文案请只写 `.bt-txt`（见 `switchBtn`）。
- **改术语要全仓库 grep**：一个动作名会同时出现在按钮、日志、状态条、侧栏标记、`index.html` 的玩法速览与
  主页面副标题、`README.md`、三份机制文档里；只改按钮会让口径分裂（`js/ai.js` 与 `docs/历史版本.md` 例外，不动）。

## 五、继续工作时可用的自查手段（都不需要浏览器）

```bash
node --check js/game.js          # 语法
# 结构 + 令牌自查（可临时写成脚本，用完删掉）
#   ① 括号配平、BOM、乱码替换符、中文数量
#   ② 所有 var(--x) 都有定义（排除 JS 注入的 7 个：--cgrad --rot --edx --edy --rr-grow
#      --discard-tail --discard-stagger --discard-slash-angle）
#   ③ :root 内无自引用
#   ④ 关键产物计数（如 27 个调色板 / 7 条公共规则 / 38 个媒体块）
# 卡面等价性核对（阶段 1 建的，见下）
node tools/css-cascade-check.js 旧style.css 新style.css
```

**`tools/css-cascade-check.js`（卡面等价性核对，强烈建议改 CSS 前后各跑一次）**：
不开浏览器、不跑测试，纯静态地把两份 style.css 对**每一类卡面 × 每个状态变体（.sealed / .no-img /
.up / .down …）× 每个断点**算出生效值再逐项比对（简写展开、媒体查询、特异度+源码顺序、`var()` 解析都算）。
当前口径：19 个上下文 × 8 个变体 × 11 个视口 × 16 个被查元素 ＝ **23562 次计算**，一致时打印「差异 0 处」。
它自己也有自检：`--selftest` 会往副本里植入几处改动，**必须**报出差异，否则说明脚本已经瞎了。
`--dump` 打印各断点的生效值基线，`--why <上下文号> <视口号> <选择器> <属性>` 回到某一条值的级联来源。
⚠️ 改卡面时它只证明"没变"，**证明不了"好看"** —— 视觉结论仍以用户实测为准（规则 6）。

**交付话术**（规则 6）：列出**改动文件清单** + **建议用户验证的步骤与现象**；
用"请你实测"而不是"我测过了"。用户会把现象/报错贴回来。

**回滚素材**：`_bak_phase1/`（`style.css` / `game.js` / `card-browser.js` / `deck-page.js` 的**阶段 1 改动前**原件）。
仓库里这些改动**尚未提交**，所以它是那条时间线上唯一的可回滚副本 —— 用户提交后可删。
