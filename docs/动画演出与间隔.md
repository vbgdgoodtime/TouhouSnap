# 动画、演出与间隔（表现层总表）

> 本文件是**表现层（动画 / 演出 / 节奏间隔）的唯一权威口径**：每个演出“长什么样”、时长与间隔常量、悬浮层与 z-index 约定、
> 以及“改时长要同时改哪几处”。**机制本身**（结算口径、时机、边界、与其它机制的交互）见同目录 `docs/现有机制.md`。
> 分工：`现有机制.md` 只保留**演出名**（如「凝聚显形」「分崩离析」）与“走分步版 / 走同步版”的区别；
> 形态、时长、样式类名与关键帧、间隔数值一律写在本文件，改动时只需改本文件与代码。

## 1. 通用口径

- **演出是纯表现、零玩法影响**：不改战力 / 费用 / 格位 / `fieldQueue` / `powerLog`，不触发 `surv`/`phx`/`prot`/`ind`，
  不参与判定、不写对局日志（个别演出另有说明者除外）；演出播不出来时对局照常推进。
- **一律放 body 悬浮层**：`renderZones()` 会重建卡位元素，挂在卡面上的动画会被重建打断、或被 `.mini-card` 的 `overflow: hidden` 裁掉；
  悬浮层元素 `pointer-events: none`，不挡操作、不受盘面重渲染影响。
- **跳过条件**：取不到锚点（元素不存在）或锚点尺寸为 0 → 静默跳过、只留日志；`el.animate` 不可用（如 jsdom 冒烟环境）→ 整段跳过，
  **不给自动化测试加延时**。
- **收尾用 `setTimeout`**，不依赖 Web Animations 的 `finished`——保证一定清理干净、绝不卡住流程。
- **排队式播出**（与 DOM 是否已渲染无关）：`flushBuffFlash`（±N）、`flushRetriggerFx`（早苗再触发）、`flushCostFlash`（改费）、
  `flushHandAdd`（加入手牌）、`flushPendingSwitchFly` / `flushPendingDriftFly`（换边 / 漂移飞行）都在**渲染流程末尾**统一播出。
- **中断保护**：翻牌流程里的分步演出都校验 `state.gen`——重新开局（`state.gen` 变化）立即停止后续步骤。

## 3. 通用演出（多处共用）

**结算前停顿（400ms）**：`revealRound` 在**每张牌结算它自己的揭示之前**先停 400ms，让玩家看清“哪张牌翻开了”。
是否真等由预判 `revealEffectWillChange(...)` 决定（它按“这次结算会不会真的改变盘面”逐键推演）——返回 false 就**不空等**：
键名写错、候选为空、判定落在 `ind` 卡上、目标被 `locNoDestroy` 整条拦下、牌已失去卡牌文字（静海 `mute` 抹除，或被「封印」）、
揭示被「法界」封锁（`noReveal`），都不等。
`shuffleIn` 是特例（条目合法且 `n > 0` 时**恒为 true**）。守矢神社 `repeatReveal` 的第 2 次重复用的是同一道 400ms 停顿。

**战力增减（±N，约 1000ms）**：场上卡发生永久 ±N（收口 `applyPermBuff`：正向 `bf`/`ba`/`bl`/`oc`、`phx` 重生；负向 `de`、`surv` 等）时，
在**效果结算后的那次渲染**里由 `flushBuffFlash()` 播出——正向绿色「+N」、负向红色「−N」：卡面短暂提亮（正向）/ 泛红（负向），
**光环 + 大号数字气泡放 body 独立悬浮层**（不随卡面重建中断），末段约 300ms 渐隐。样式＝`style.css` 的 `.gain-ring` / `.buff-gain-pop`（`.loss` 为负向）。
终局前要先等它播完：`waitBuffFxDone(timeoutMs)`（`playEndHighlights` 的第一步，带超时兜底）。

**分崩离析（摧毁，约 1s）**：`playShatter`——卡面切成 3×2 六块碎片四散 + 旋转 + 末段渐隐，克隆件放悬浮层不受重建影响。
只在**真正离场**的那次摧毁播：`dw` / `dwh` / `dwh2` / `dwb` / `dwc` / `dwOwn` / `delCopy` / 地形 `purge` 实际移除时；
一次结算摧毁多张（`dwh2` / `dwc` / `purge`）时各张各播一次，本键是同步逐张、张与张之间**没有等待** ⇒ 相邻两张的碎裂演出同时起播、**重叠播放**（同「天界摧毁链」的间隔口径）；
`surv` / `phx` / 蕾蒂·地形 `prot` / `ind` 防护与各种移动类**都不触发**。

**凝聚显形（落场生成，1s）**：`placeToken` 落地的卡、分身 `clone`、复活弃牌池、`spawn`/`spawnO`/`spawnS`/`spawnMine`/`ryugyoku` 等生成的 token
打 `justSpawned` → `.spawned-now`：scale 弹入 + 淡青光环。

**滑入（加入手牌，1s）**：`give` 衍生物（极限火花 / 神宝）、`discard.give` 造的石块、开发者「🎯 指定卡牌」加牌打 `justHandAdded` → `.hand-new`。
⚠️ 加入手牌后必须由 `flushHandAdd(side)` **立刻渲染一次手牌**（仅玩家侧）：否则同一同步任务内下一次 `roundStartStage()` 的 `renderAll()`
会重建 `#hand`，带 `.hand-new` 的元素还没被绘制就被替换、动画实际时长为 0；`drawSpell`（回合开始抽法术）不需要该调用，其渲染点后紧跟 `await waitPlayer()`。

**翻牌换面（`flipIn` 0.5s）**：暗牌翻开是**从小到大缩放入场**（不是淡入淡出）：`.played-now` 播 scale `.3 → 1.12 → 1` + 提亮，观感同生成 token 的「凝聚显形」。
白板 / 效果不会变化的卡**不被结算后的同帧重建覆盖**（只有效果确实会变化时才重建），否则动画看不见。

**抽牌入场（0.65s）**：每回合（含第 1 回合）与开局逐张抽牌播“从屏幕右侧滑入”的浏览器原生 CSS 动画（`.hand-drawn`）；
动画期间给 `#hand` 加 `.draw-anim`（`lockDrawAnimScroll`，`overflow-x: hidden`）抑制桌面端横向滚动条。
开局那次由 `playOpening` 驱动（逐张发放初始 3 张，每张之间约 720ms，收尾再停约 500ms）。**卡组设置页**新建一套卡组时，新卡组位也播一次入场动画（`js/deck-page.js` 的 `createDeck()`，无独立时长常量）。

**飞行（移动 / 换边，约 0.26s）**：`flyCardTo(card, srcRect)`——真身已在新格位，克隆卡面做“滑行 + 缩放”飞过去。
使用处：八云紫 `shift` 逐张搬运、`mv`/`fly`/`roam`/`gust` 移动（`flushPendingDriftFly`）、`switch`/`gift` 换边（`flushPendingSwitchFly`）、
AI 的移动（`js/ai.js` 也在下一帧触发同款）。

**法术消散（约 0.52s）**：`playSpellVanish`——克隆卡面上浮 + 放大 + 提亮淡出（body 悬浮层，不受重渲染影响）＋ `spawnSpellSparks`（8 颗淡紫星光，复用 `.energy-star` / `.spell-star` 关键帧）。

**改费卡面揭示（约 2.4s）**：加费 / 减费走 `applyCostMod` 排 `costFlashQueue` → 渲染后 `flushCostFlash()` → `spawnCostReveal`：
场地中央弹出**被改费那张牌的完整卡面**（`.cost-changed` 提亮、`.cost-orb` 变色）+ 顶部来源标签 + 底部三段式横幅
**`费用 旧值(划掉) → 新值`（涨红 / 降绿）** + 「能量消耗 +N，仅本场战斗有效」；时间轴＝弹入 → 抖动 → 停留 → 上浮淡出 + 金色光环脉动，新费用数字单独放大强调。
同一批同卡的费用变化**合并成一次演出**（`flushCostFlash` 内按卡合并 `d`）；被改的卡若在场上 / 我方可视手牌里，卡位另加橙金提亮闪动与侧栏小气泡（`.gain-ring.cost-ring` + `.buff-gain-pop.cost-pop`）。
⚠️ `costDown`（纯狐）/ `costDownP`（星熊勇仪）的减费**不触发**这套演出——它们没有“改费那一刻”的结算点，手牌角标在下一次 `renderHand` 时自然变绿。

**额外能量（两段）**：
- ① 登记段 `playEnergyBookFx`（揭示当刻）：斯塔萨菲雅卡位播卡面金光闪烁（`.energy-card-flash`）+ 金色光环扩散（`.energy-ring`）+ 星光迸发（`.energy-star`）+ 「能量 +1」气泡（`.energy-pop`）与「下一回合生效」小字；
- ② 到账段 `playEnergyGainFx` / `playEnergyFxAt`（下回合开始能量结算时）：锚点换成顶栏能量框（对手侧用侧栏「对手（AI）」信息区），播绿色闪光（`.energy-box-flash`）+ 同款星光 + 「能量 +1」气泡（小字列出来源卡），与绿色「+N」角标同时弹出。

两段都放 body 悬浮层（z-index **9400** 环 / 星光 / 气泡、**9410** 卡面闪光），`pointer-events: none`；卡位或能量框取不到（尺寸为 0）时跳过该段；末回合登记时会跳过登记段（不会生效）。

**洗入卡组（`playShuffleInFx`）**：牌库计数青蓝闪光 + 外扩光环 + 星光迸发 + 「🃏 洗入卡组 ×N」气泡（副行「来源卡 · 牌名 → 你的牌库 / 对手的牌库」）；
样式＝`.deck-shuffle-flash` / `.deck-count-chip` / `.energy-star.deck-star` / `.energy-pop.deck-pop`（复用 `.energy-star` 与 `.energy-pop` 的关键帧）。
锚点：玩家侧＝手牌区「牌库 N」（`#deckCountVal`）；对手侧＝侧栏 `.opponent .mini-stats`（「牌库 N 张」，`#aiDeck`）；取不到锚点或尺寸为 0 时静默跳过、只留日志。

**弃牌（`playDiscardFx`，约 1.6s）**：**任何一种归属组合**（自己弃自己 / 自己弃对方 / 对方弃对方 / 对方弃自己）都**双方可见**——场地中央弹出被弃那张牌的**完整卡面**，随后**从右上到左下**斜切一刀，卡面裂成两半、分离并淡出。

- **结构**（全部放 body 悬浮层 `.discard-reveal`，z-index **9510**、`pointer-events: none`、不受盘面重渲染影响）：
  顶部标签「🗑️ 弃牌 · 谁的手牌 · 来源」→ 卡面块（多张并排）→ 底部说明「「X」「Y」→ 移入谁的弃牌池（现 N 张）」。播放前先清掉可能残留的上一次演出（连续弃牌不叠层）。
- **斜切实现**：用 **`clip-path` 三角**（不是切图）——切线＝右上角 → 左下角，两半分别是 `polygon(0 0, 100% 0, 0 100%)`（上半三角，含左上角）与 `polygon(100% 0, 100% 100%, 0 100%)`（下半三角，含右下角）；
  两半内部各放一份**同一张卡面的拷贝**（像素级重合），故切开后看起来仍是同一张卡裂成两块；另有一张“基准整卡”在切开那一瞬由 CSS 隐去（与两半完全重合，切换不可见）。
- **分离方向**：沿对角线的**垂直**方向——上半三角往**左上**飞、下半三角往**右下**飞，各带轻微旋转（−9° / +9°）与渐隐；斩击层（`.discard-slash-layer`）裁在卡面圆角范围内。
- **斩击线**：一条光刃沿对角线**从右上扫到左下**（`background-position` 扫描 + 白/暖金辉光），只在切开那一刻亮一下；
  其**角度由 JS 按卡面实测长宽比**写入 `--discard-slash-angle`（`atan2(h, w)`），因此在竖长大卡面上也严格贴着“右上 → 左下”那条对角线。
- **时间轴（1.6s）**：`0~17%`（≈0~0.27s）卡面放大弹入落定 → `17%~42%` **停留展示**（让玩家看清是哪张牌，约 0.4s）→ `42.5%`（≈0.68s）斩击线闪一刀、同时裂成两半 → `42.5%~81%` 两半**快速**分离、下沉、旋转、渐隐（约 0.62s）→ `88%~100%` 整层淡出。
  多张同时被弃时**并排**展示并逐张错开 80ms（最多错开 320ms），总时长仍在 1.6s 出头。
- **收尾**：`setTimeout`（**不依赖** Web Animations 的 `finished`）在 1.6s ＋余量后移除整层，一定清理干净。
- **样式**：`style.css` 的 `.discard-reveal` / `.discard-reveal-tag` / `.discard-reveal-inner` / `.discard-card-wrap` / `.discard-face` / `.discard-half-a` / `.discard-half-b` / `.discard-slash-layer` / `.discard-slash` / `.discard-reveal-note`，
  关键帧 `discardRevealFade` / `discardPop` / `discardBaseFade` / `discardHalfA` / `discardHalfB` / `discardSlash`，含 ≤700px 响应式收放。
  卡面复用 `.zoom-card.hand-card`，但**关掉了 `.zoom-card` 自带的 `rise` 动画**（基准卡与两半的拷贝必须严格重合，任何额外位移都会让“切开”露出错位）。

**地形揭晓换场（500ms）**：`revealLocFade(locIdx)`——揭晓时把“未揭示”外观**整列克隆到悬浮层并 500ms 淡出**（快照须在换 `def` 前抓取），下方真实地形随之显形。
边界：某列在第 1/2/3 回合揭晓之前就被卡牌 `xformR`（梅莉）换成真实地形时，该列原定的揭晓整段跳过（`locationRevealStage` 以 `loc.def.id === 'unreveal'` 判断“还没揭晓”）⇒ 不播这段换场演出。

**终局高亮（每区 700ms、区间隔 150ms）**：`playEndHighlights(gen)`——最后一回合全部结算后先 `waitBuffFxDone()` 等 ±N 播完，
再依**左 → 右**依次放大高亮各区域胜方总点数横幅（平局区**跳过**、已破碎的列**跳过**），三个区域全部结束后才 `finishMatch` 弹结算窗；横幅 `.settle-win`（缩放 + 金色光晕）。

## 4. 分步演出与节奏（只在正常翻牌流程里）

翻牌流程 `revealRound` 每张牌结算后都会 `renderZones()`，五个键借此把一次性结算拆成**逐张 / 逐区分步**，让 ±N、生成、摧毁、飞行等演出看得清楚。
`morph` 变身 / `fx` 时机效果 / 落场生成（`settleFieldSpell` 等）**无法 `await`**，一律走**同步版**（`applyEffect` 的对应 `case`：一次性结算、无分步节奏与逐步渲染），两者**盘面结果完全一致**，差别只在节奏。
五个分步键：`shift`（整体右移）/ `gather`（三妖精集结）/ `reviveDiscard`（复活弃牌池）/ `retrigger`（揭示再触发）/ `delCopy`（摧毁己方一张并复制到另两区）。

| 键 | 推进粒度 | 间隔 | 收口函数 |
| --- | --- | --- | --- |
| `shift`（八云紫） | 逐张搬运 | 约 0.3s | `applyShiftReveal`（`peekShiftCard` / `shiftMoveCard` / `flyCardTo`） |
| `gather`（三妖精集结） | 逐区 | 0.5s | `applyGatherReveal`（每区先 `renderZones()` 再结算该区揭示） |
| `reviveDiscard`（四季映姬） | 逐张复活 | 500ms（`REVIVE_STEP_MS`） | `applyReviveDiscardReveal` |
| `retrigger`（东风谷早苗） | 逐张再触发 | 500ms（`RETRIGGER_STEP_MS`） | `applyRetriggerReveal` |
| `delCopy`（绵月丰姬） | 先摧毁、再逐张结算复制体 | 摧毁后 0.3s（`SHATTER_CARD_MS`） | `applyDelCopyReveal`（摧毁与落场由 `delCopyCore` 一次做完） |

- **整体右移 `shift`**：正常翻牌揭示时逐张搬运，每张间隔约 0.3s，并以“滑行 + 缩放”飞行落到最右侧格位（`flyCardTo`）；`morph`/`fx` 等其它结算路径为一次性同步搬运。
- **三妖精集结 `gather`**：按区域顺序推进——第 1 区生成并结算揭示 → 停 0.5s → 第 2 区 → 停 0.5s → 第 3 区 → 停 0.5s；三区都揭示完之后才结算第 ② 步「己方场上已翻开的三妖精 +add 战力」（**再留约 0.5s**），随后才播这张法术的消散演出。被跳过的区域不产生演出，只在日志点名。
- **复活弃牌池 `reviveDiscard`**：逐张推进——捞出一张 → `renderZones()`（播「凝聚显形」）→ 结算“这一张”自身的揭示 → `renderZones()`（让 ±N / 生成 / 摧毁等演出显示出来）→ 停 `REVIVE_STEP_MS`（500）→ 下一张。目的是避免一次性复活一大把牌（连锁揭示叠加、演出互相盖住、极端情况下的渲染压力）。
  ⚠️ 每张的实际观感节奏 =「凝聚显形」入场动画（约 1s，CSS）+ 该张揭示的演出 + **固定 500ms 间隔**；`REVIVE_STEP_MS = 500` 是**纯 JS 计时、没有对应的 CSS 关键帧**，改节奏只改这一个数。
  ⚠️ **连锁例外**：若弃牌池里还躺着另一张四季映姬，她被复活后会**立即再触发一次本效果**——那次走同步版（发生在结算链内部、无法 `await`），那一批牌一次性复活；回到外层循环后仍按 500ms 节奏继续推进。
- **摧毁己方一张并复制 `delCopy`**：单张牌内的两步节奏——先摧毁（播「分崩离析」）并让复制体在另外两个区域落场（播「凝聚显形」）→ 停 `SHATTER_CARD_MS`（0.3s）→ 再逐张结算复制体自身的揭示（每张之后 `renderZones()`）。⚠️ `delCopyCore` 里摧毁与落场是**同一步**（复制体先落地、再等那 0.3s），等待只为让碎裂演出看得清、不影响盘面结果；复制体的揭示走 `resolveRevealInZone`，故目标区是「守矢神社」时照常再加一次（并再停那 400ms）。
- **揭示再触发 `retrigger`**：逐张推进——每张结算后 `renderZones()`，再停 `RETRIGGER_STEP_MS`（500，纯 JS 计时、无 CSS 关键帧）结算下一张。翻牌流程里被再触发的每一张走**共用分派** `resolveRevealInZone` → `resolveCardReveal`（`retriggerOneStaged`），因此它若是 `shift`/`gather`/`reviveDiscard`（乃至另一张早苗）也**照常保留自己的分步间隔**。
- **早苗「揭示再触发」的可见演出**（现仅 5 费「东风谷早苗」的 `retrigger` 使用）：早苗揭示时播一个简单快速的小动画，看得出“她放了一次光环”；在「守矢神社」里打出早苗时其揭示会执行两次（自身 1 次 + 地形 `repeatReveal` 重复 1 次），两次演出**同款、不加文字标记**，靠“光环又亮了一次 + 目标卡又闪了一轮”分辨。
  - 调用点＝`applyEffect` 的 `case 'retrigger'`（翻牌分步版与非翻牌同步版**共用**）里、结算**之前**入队 `queueRetriggerFx`，由 `renderZones()` 末尾的 `flushRetriggerFx()` 播出（口径同 `flushBuffFlash`，排队与 DOM 是否已渲染无关，翻牌流程里每张结算后那次渲染就会立刻播出）。
  - ① 早苗本体光环 `playRetriggerAura`（`RETRIGGER_AURA_MS = 760`）：卡面本体做一次短促提亮脉冲（WAAPI **只动 `filter`**）；光环（两圈扩散环）动态创建到 body 悬浮层（`.retrigger-ring`：z-index **9450**、按卡面 `getBoundingClientRect` 定位、`pointer-events: none`，动画后自行移除；关键帧 `retriggerRingOut`）。
  - ② 每张被再触发的目标卡 `playRetriggerHit`（`RETRIGGER_HIT_MS = 420`）：同为 body 悬浮层的金白闪光环（`.retrigger-hit-ring`，z-index **9440**）+ 卡面短促提亮。**同一刻一起闪**，不是在各自那 500ms 时点分开闪——这样“一组光环 + 一轮闪光”好数。
  - ⚠️ 光环 / 闪光**必须放 body 悬浮层**：挂在卡面本体上会被 `.mini-card` 的 `overflow: hidden` 裁掉外阴影，并与翻面 `.played-now`（`flipIn`）的 `transform`/`box-shadow` 打架，几乎看不见；卡面本体只保留“只动 `filter`”的提亮。元素按卡 id 查找（`miniCardElsById`）；取不到（卡同刻被摧毁 / 被挪走 / 在对方手牌）即静默跳过（另补诊断日志与 `console.log('[retriggerFx] …')` 汇报命中数）。
  - ⚠️ **不额外插入任何等待**：翻牌流程每张结算后本就 `renderZones()`，故 500ms/张 的节奏、守矢神社那 400ms 停顿、“总计 6 次”的账**完全不变**；调快慢只改那几个常量（`RETRIGGER_STEP_MS` / `RETRIGGER_AURA_MS` / `RETRIGGER_HIT_MS`，纯 JS 计时）。`playRetriggerAura` 不区分“第几次”（两次同款）。

**守矢神社「揭示重复触发」（`repeatReveal`）的节奏**：第 1 次照常 → **停 400ms**（与翻牌结算前那道停顿同款）→ 第 2 次「重复」；重复结算完再 `renderZones()`，让 ±N / 生成 / 摧毁等演出看得出“又触发了一次”；停顿后校验 `state.gen`（重新开局即放弃本次重复）。
五个分步键重复时**照常保留各自的间隔**（逐区 / 逐张推进，而不是一次性并发结算）：重复「三妖精集结」逐区生成 → 逐区渲染 → 逐区结算该区妖精的揭示；同理重复八云紫 `shift` 逐张 0.3s、重复四季映姬 `reviveDiscard` 逐张 500ms、重复东风谷早苗 `retrigger` 逐张 0.5s、重复绵月丰姬 `delCopy` 摧毁后停 0.3s 再逐张结算复制体的揭示。⇒ 一次重复的总耗时取决于被重复的那张牌的键（`gather` 约 3×0.5s+、`reviveDiscard`/`retrigger` 按张数 ×0.5s），并与那 400ms 的前置停顿叠加。
含法术：法术的自身揭示结算完并不立刻消散，而是「停 400ms → 重复一次 → 才 `vanishSpell` 消散」（调用点因此排在 `revealRound` 里 `vanishSpell` 之前）；重复时它仍占着那 1 个格位。
⚠️ 本字段与早苗的“再触发”都必须走共用的揭示分派 `resolveCardReveal`（而不是直接 `applyEffect`），否则会静默退化成同步版、把这些间隔全部吞掉。

**天界摧毁链（`shatter`「出现时摧毁另外两块地形」的节奏）**：逐块、左→右（按列下标升序，跳过本列与已破碎列），每块两阶段——①依次摧毁该区的所有卡（顺序＝`fieldQueue`：谁先放谁先碎；每张间隔 0.3s，播「分崩离析」）→ ②等 0.3s（`SHATTER_TERRAIN_MS`）→ 摧毁该地形本身（该列变「已破碎」）；两块之间再等 0.3s（`SHATTER_NEXT_LOC_MS`），即 **卡A →0.3s→ 地形A →0.3s→ 卡B →0.3s→ 地形B**。三个常量 `SHATTER_CARD_MS` / `SHATTER_TERRAIN_MS` / `SHATTER_NEXT_LOC_MS` 均为 300。
⚠️ 300ms **短于**「分崩离析」的动画时长（约 1000ms），相邻几张的碎裂演出会**重叠播放**（观感＝连续爆裂、一口气全碎）；分崩离析是全局共用的摧毁演出（`dw`/`dwh`/`dwb`/`dwc`/`dwOwn`/`delCopy`/`purge` 都用它），不为一处机制单独改短。
整条摧毁链是单例 Promise，正常对局各路径 `await awaitShatterChain()`；开发者「🗻 指定地形」是唯一“不等”的路径（保持同步：启动链条后立刻关窗，逐张摧毁的演出在后台继续）。
其它节奏性口径（哪些阶段变成可等待、`renderZones()` 调用点）属机制管线，见 `docs/现有机制.md` §2「区域「出现时摧毁另外两块地形」效果」段。

## 5. 开局「登场」演出（`gs` 卡专用，约 1.8s）

`restart` 的 ⓪ 阶段若真的触发了带 `gs` 的卡（现仅 7 费「哆来咪」），就在洗完 10 张随机牌 + 登记每回合能量 +1 之后、玩家起手 3 张发放之前播放：

- **形态**：深色径向遮幕淡入 → 完整卡面（复用 `.zoom-card.hand-card` + `cardFaceHTML()`，含费用 7 / 战力 8 / 卡名 / 效果文案与 7 费底色）放大弹入、紫金光环脉冲两下（光环包住整个登场块）+ 14 颗星光迸发（卡面落定那一瞬，约全程 13%＝240ms）+ 轻微抖动 → 停留展示 → 上浮淡出；全程约 1.8s（JS 的 `DUR = 1800` 与 CSS 三处动画时长对齐）。
- **时序**：演完才开始逐张抽初始 3 张 ⇒ 开局洗入的牌从抽牌那一刻起才可能被抽到。触发源＝`runGameStartEffects()` 的返回值（本次真正结算的 `{ side, card, gs }` 列表），没触发时直接 resolve、不额外等待。
- **元素与样式**：放 body 悬浮层 `.gs-reveal`（z-index **9520**，`pointer-events: none` 不挡操作、不受盘面重渲染影响）；星光粒子复用 `.energy-star` 关键帧并追加 `.gs-star`（z-index **9525**）。
  样式类＝`.gs-reveal` / `.gs-reveal-veil` / `.gs-reveal-inner` / `.gs-reveal-tag` / `.gs-reveal-ring` / `.gs-reveal-note` / `.energy-star.gs-star`，关键帧 `gsCardPop` / `gsVeilFade` / `gsRingPulse`，含 ≤700px 与 ≤640px 高度的响应式收放。
- **光环口径**：光环挂在「整个登场块」上（以 `.gs-reveal-item` 作定位基准、`inset: -8px -16px`），脉冲最小幅度＝3px 描边 + 12px 金色柔光（常驻起步），55% 谷底 12px、峰值 22px/12px；幅度最小时也把上下两条文字说明圈在光环里。
- **收尾与跳过**：收尾用 `setTimeout`（不依赖 Web Animations 的 `finished`），保证一定 resolve、绝不卡住开局流程；不支持 Web Animations 时整段跳过（如 jsdom 冒烟测试里 `Element.animate` 不存在）。

| 早苗光环 | `RETRIGGER_AURA_MS = 760` | 关键帧 `retriggerRingOut`（两处必须一起改） |
