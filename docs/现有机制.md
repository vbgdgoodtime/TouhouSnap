## 1. 卡牌效果键（`k`，全部为「揭示」On-Reveal：翻面时结算一次、永久生效）

| 键 | 名称 | 说明 |
| --- | --- | --- |
| `''` | 白板 | 无效果 |
| `bf` | 同区友军增益 | 同区域**你的其他已翻开**卡牌（不含自己）威力 +N |
| `de` | 同区敌方削弱 | 同区域**对方所有已翻开**卡牌威力 −N |
| `ba` | 双方同增 | 同区域**双方所有已翻开**卡牌威力 +N |
| `bl` | 落后自增 | 本区按获胜口径落后时自身 +N（反转区域按"真实点数更高=落后"判定）。**v179 起也作时机效果复用**：由「蕾米莉亚·斯卡蕾特」以 `fx.turnEnd` 每回合末判定（落后即永久 +N、可累积） |
| `dw` | 摧毁 | 摧毁同区**对方已翻开且威力最低**的一张（暗牌与 `un` 占位卡不可选为目标；**v180 起带 `ind`（自身不可摧毁）的卡照常参与判定**——判定落在它身上时**摧毁失败、本次判定结束**，不会改打其他牌） |
| `spawn` | 添加石块 | 揭示：向本区域**双方**各添加 1 张特殊卡（`def.spawn` 指定，当前为石块；放满则不放） |
| `spawnO` | 敌方侧生成 | 揭示：向本区域**对方一侧**添加 1 张特殊卡（`def.spawnO` 指定，当前为厄运；对方该区放满则不放） |
| `clone` | 另两区生成分身 | 揭示：向**另外两个区域**（不含本区）**自己一侧**各添加 n 张特殊卡（`def.clone` 指定，当前为赫卡提亚的分身；该侧放满/未开放的区域跳过） |
| `switch` | 换边 | 揭示：翻开后从自己一侧转移到**对方该区域一侧**（如依神紫苑 −7 战力上对方侧；对方该区已放满则失败、留在原地） |
| `morph` | 变身 | 揭示：把自己变成**对方手牌中随机一张卡的复制体**（原卡留在对方手牌；变身后按新卡的 k 再结算一次其揭示文本；对方手牌为空则不变） |
| `gift` | 送己方最低卡 | 揭示：把本区域**己方战力最低的已翻开卡**（不含自己；并列最低随机选一）换边到对方该区域一侧（对方该区放满则失败） |
| `xform` | 区域变形 | 揭示：把本区域整体替换为目标地形（`def.xf` 指向地形 id，如鬼人正邪→`needle` 辉针城）；**变形＝该地形在本区“出现”**，立即结算其「出现时」效果（v151，如变成虹龙洞 → 双方各 1 张石块） |
| `mv` | 移走 | 揭示：把本区对方已翻开且实时战力最低的卡移到另外两区随机一处（对方该区满员/未开放的地形排除；都不可达则失败） |
| `give` | 加入手牌 | 揭示：把指定特殊卡（手牌衍生物，如废弃列车）加入自己手牌（7 张满则失败；**v177 起由「雾雨魔理沙」使用 → 法术「极限火花」**，此前 v76 起为预留）。**v180 新增 `pool` 写法**：`give: { pool: [SPECIAL 键名…], n }` —— 从池里**不放回随机抽 n 张**（互不相同）加入自己手牌，其余口径与单卡写法完全一致（新卡实例、`justHandAdded` 滑入、满手则失败/只加入放得下的、归属按所属方）；池内缺失条目静默忽略、池空则只记日志。现由**「蓬莱山辉夜」**使用 → 从 5 张**神宝**里随机抽 2 张（细则见 §3「v180 · 神宝」） |
| `shuffleIn` | 洗入卡组（**v184**） | 揭示：把 `def.shuffleIn = { card: 键名, n: 张数, to: 'own' \| 'opp' }` 指定的牌 **n 张**（各自为**新卡实例**）**洗入某一方的牌库**，随后该方**整副牌库重新随机洗一次**。`card` 先查 `SPECIAL` **键名**、查不到再按**卡名**查 `POOL`（两种池都能引用）；`n` 缺省 1、**张数无上限**（牌库没有 7 张上限，「手牌满则失败」不适用）；`to` 缺省 `'own'`＝洗入**自己**牌库，`'opp'`（也接受 `'a'`）＝洗入**对方**牌库（归属按牌的所属方）。**不结算被洗入卡的任何效果**（进的是隐藏区牌库：不翻开、不占格位、不进 `fieldQueue`、不触发揭示/`og`/`fx`/`surv`；日后抽到再打出时按常规流程结算）；日志公开点名 + 轻量演出（牌库计数闪光 + 「洗入卡组」气泡）。**现由「琪露诺」（v184 重做：1 费 / 2 战力）使用** → 向**对手**牌库洗入 1 张「冰块」。细则见下文「洗入卡组（`shuffleIn`）」段 |
| `dwh` | 摧毁最强 | 揭示：摧毁本区对方已翻开且战力最高的一张（**并列最高时在其中随机挑一张**——v177 口径，与 `dwb`「并列最低里随机挑一张」对称、同为“只摧毁一张”；现由 token「废弃列车」与 v177 法术「极限火花」使用；**v180 起 `ind` 卡照常参与“最强”判定与并列随机抽取**：判定落在它身上＝摧毁失败、判定结束） |
| `oc` | 对方同区落牌自增 | 揭示：翻开当回合对方曾在本区域放置过至少一张牌则此牌 +N（永久） |
| `shift` | 整体右移 | 揭示：把己方**最左侧区域**（第 1 列）**已翻开**的卡牌按放置顺序依次搬到**最右侧区域**（第 3 列）己方一侧，直至右侧己方侧填满（占格判定；暗牌不动；现仅八云紫） |
| `roam` | 自身漂移（v158） | 揭示/时机效果：把**自身**移到**另外两个区域**中**随机一处**——目标区必须已开放（`locOpen`，避开锁定的七夕坂等）且该侧空余 ≥ 自身占格数（`occ` 口径）；两个都不可达则失败、留在原地；移动不改变归属/揭示状态/场上放置顺序队列，并播放“滑行+缩放”飞行演出。现仅「幽灵」以 `fx.turnStart` 使用（每回合开始飘一次）；也可作为揭示键使用 |
| `costUp` | 对方手牌加费（v169） | 揭示：让对方**当前手牌**中**随机一张卡**的**能量消耗 +N**（`a` 指定，现 N=1，仅桑尼米尔克）——只作用于被选中的**那一份卡实例**、**仅本场战斗有效**；**每张卡最多涨到 6 费**（手牌里 `cardCost ≥ 6` 的卡不可选，**0 费卡可被选中**），对方手牌为空或全是 6 费则**丢失目标、无事发生**；目标**公开**给玩家（日志点名 + 「费用 +N」气泡落在侧栏对手信息区），该卡费用数字此后**显示红色**；加费不改变印刷费用档位（卡组曲线、`cb` 费用加成、图鉴仍按 `def.c`），只有**实际打出时的能量消耗**按修正值算。细则见下文「费用修正」 |
| `energyNext` | 下回合额外能量（v169） | 揭示：让**自己一方在下个回合**额外获得 N 点能量（`a` 指定，现 N=1，仅斯塔萨菲雅）——**一次性**（结算完即清空，不是每回合都给），在**下一个回合开始**的能量结算（①-2 `grantTurnEnergy`）时并入能量上限与剩余能量，同回合多张/多来源**可叠加**（两张＝+2）；归属按牌的所属方（AI 打出则 AI 自己加）；第 6 回合（最后一回合）翻开时没有“下一回合”，这份额外能量**本局不会生效**（日志说明）。细则见下文「额外能量」 |
| `gather` | 集结（v171） | 揭示：把 `def.gather.group` 阵营（现 `'light'` 光之三妖精）在 `POOL` 里的成员卡（去重，排除 `un`／法术／大体积 `occ>1`）**互不相同地随机分配到三个区域**，**每个区域自己一侧各生成 1 张**（该侧已放满或区域未开放则**跳过该区、不补到别区**）；生成的卡**落地即翻开**、占格位、进放置队列，并**立即结算它们自身的「揭示」**；**在这之后**给自己一侧场上**已翻开**的该阵营卡牌**永久 +add 战力**（含刚生成的；暗牌不参与）。现仅法术「三妖精集结」使用 —— 细则见下文「集结」 |
| `dwb` | 摧毁双方最弱随机一张（v172） | 揭示：摧毁本区域**双方**（敌我混比）**已翻开**卡牌里**战力最低的随机一张**（**并列最低时在其中随机挑一张，不是全删**——与地形 `purge`「并列全删」不同）。排除暗牌、`un` 占位卡与法术；**v180 起带 `ind` 的卡照常参与“双方最弱”判定与并列随机抽取**（抽中它＝摧毁失败、判定结束；抽中其他并列牌则照常摧毁）；本区域存在免摧毁（`locNoDestroy`：地形 `prot`／蕾蒂）时**整条失效、不选目标**；目标带 `phx`/`surv` 时按各自机制处理（回手 +N／改降 N 战力）。⚠️ 因为双方混比，**可能摧毁己方自己的卡**。现仅法术「火神之光」使用 |

| `tkBuff` | 标记卡增幅（**v179**） | 揭示：把**己方**（`def.tkBuff.own: true`）或**全场双方**（缺省）场上带 `def.tkBuff.tk` 标记的**已翻开**卡牌**永久 ±N**（`a`，可为负）——只作用于结算那一刻已翻开的卡（同 `bf/de/ba`），排除 `un` 占位卡与法术；走 `applyPermBuff` 收口（±N 演出 + 战力影响历史按来源记本卡）。⚠️ **一次性永久**加成，与 `og`（在场期间实时生效、源卡离场即失效）是两种机制。**可同时声明 `spawnS` 作前置子句**：先在本区自己一侧落场生成、**再**统一加成，故刚生成的卡也吃到本次 +N。现仅法术「地精的起床」使用（`{ tk:'rock', a:1, own:true }` + `spawnS:{card:'stone',n:1}`：先在本区自己一侧放 1 张石块，再给**己方**场上所有石块永久 +1） |
| `spawnMine` | 己方每区生成（**v180**） | 揭示：给**己方每个区域**（**含此牌所在区域**）自己一侧各生成 `def.spawnMine = { card: SPECIAL 键名, n }` 指定的特殊卡（法术「耀眼之龙玉」→ 3 费/3 战力的「龙玉」）。**逐区独立判定**：该侧**已放满**（`sideRoom < 1`，occ 口径；⚠️ 法术揭示瞬间**仍占本区 1 格**，故本区己方侧因这张法术正好满时 → 该区跳过）或**区域未开放**（`locOpen`，如七夕坂第 5 回合前）→ **跳过该区、不补到别区**，日志逐区点名落场张数与跳过原因。落场走 `placeToken`（落地即翻开、占格位、进放置队列、播「凝聚显形」），**不结算生成卡的揭示**（同 `clone`/`spawnS` 口径）。与既有生成键的配位：`spawn` 本区双方各 n / `spawnO` 只投本区对方一侧 / `spawnS` 只投本区自己一侧 / `clone` 只投**另外两个**区域自己一侧 → **本键三个区域都投（含本区）**。现仅法术「耀眼之龙玉」使用 |

> 🛡️ **摧毁判定与 `ind`（v180 修订：判定式免疫，不是“跳过”）**：`dw`/`dwh`/`dwb` 与地形 `purge` 的**候选/比较集合不变**（仍是“已翻开 + 非 `un` + 非法术”），带 **`ind`（自身不可摧毁，佛体金刚石）** 的卡**照常参与判定**——`dw` 比最弱、`dwh` 比最强、`dwb` 比双方最弱并在并列里随机抽、`purge` 比本区最低，**都把它一起算进去**。一旦判定**落在它身上**：**摧毁失败 + 本次判定结束**（不离场、战力不变、不触发 `surv`/`phx`，**也不会改打其他牌**）。判定落在别的牌上则照常摧毁。`revealEffectWillChange` 用同一套“谁会被判定选中”的口径预判，因此判定落在 `ind` 卡上时不会空等结算前的 400ms。详见下文「自身不可摧毁（`ind`）」段。

> 💤 **游戏开始时（`gs`，v185 新增的**卡级**机制，非揭示键）**：只要**开局时这张牌在自己一方的牌库/起手中**（＝被放进了那 12 张卡组）就触发，**整局永久生效**——现仅 **7 费「哆来咪」**（`gs: { shuffleN: 10, energyAdd: 1 }`）使用。完整口径见下文「游戏开始时（`gs`）」段。

**费用修正（v169，现仅 `costUp`／桑尼米尔克；未来减费同口径）**：卡牌实例可带**本场战斗内**的费用修正，引擎统一收口 `cardCost(card) = def.c + (card.costMod || 0)`：
- **实例级**：修正写在 `card.costMod` 上（配套 `card.costLog` 记账，记 `{ inst, d, src, tag }`，思路同战力台账 `powerLog`），只影响**这一份卡**——牌库/手牌/场上的同名卡互不影响；卡从手牌打出、被移动、被换边、凤凰重生回手都**带着这份修正走**。
- **仅本场战斗有效**：不写回 `def`（`data/cards.js` 不动），也不入 localStorage/卡组存档；那一份卡被摧毁 / 终局离场 / 本局结束即随之消失，新开一局卡实例重建，修正自然归零。
- **只有“实际付出/消耗的能量”按修正值算**：出牌扣能量（`tryPlayAt`）、能否负担（`canPlaceP` / 手牌置灰 / `selectHand`）、撤回暗牌的返还、AI 选牌与扣能量（`ai.js`）全部走 `cardCost`。
- **印刷费用（`def.c`）不变**：卡组曲线与卡组页排序、区域 `cb` 费用加成（如雾之湖「1 费卡 +2」）、图鉴 / 开发者「指定卡牌」的筛选与文案，仍按 `def.c` 判定（避免涨费卡忽然吃不到雾之湖、或从卡组的费用档位里“搬家”）。
- **上限 6 费**：只允许把卡涨到 `cardCost ≤ 6`（故 6 费卡不可再涨，`costUp` 的候选池排除它们）；牌局能量上限也是 6，涨到 7 费等于永久不可打出，故设此上限。**减费暂无来源**，但口径对称——低于印刷费用显示绿色。⚠️ **v185 附注**：`gs.energyAdd`（哆来咪）会把**本局能量上限**提到 7（第 6 回合），但**该费用上限仍保持 6 不变**（用户口径，不因能量变高而放宽）——因此 ≥6 费的牌（含 7 费的哆来咪）都不可再被加费，加费实际只对 ≤5 费的牌有效。
- **界面口径**：费用数字按 `cardCost` 显示，**高于印刷费用=红色、低于=绿色**（与战力数字同款语义；缩略卡 `.mc-cost` 与卡面费用宝珠 `.cost-orb` 各自独立着色，与战力色互不干扰）；放大/详情弹窗补一行「印刷费用 N · 本场战斗费用修正 +N（仅此一份卡有效）」。**演出（v169 修订）**：改费时于渲染后由 `flushCostFlash()` 播放**中央卡面揭示**（`spawnCostReveal`，约 2.4s：弹入 → 抖动 → 停留 → 上浮淡出 + 金色光环脉动）——把**被改费那张牌**以完整卡面弹出（配图/emoji、卡名），下方一条三段式横幅只写**费用变化**：**`费用 旧值(划掉) → 新值`（涨红/降绿）**，顶部标签写明来源（如「☀️ 桑尼米尔克 · 费用操控 · 对方手牌 费用 +1」），底部补「能量消耗 +N，仅本场战斗有效」；这样即便目标藏在**对方手牌**里、玩家平时看不到，也能一眼认出是**哪张卡**被加费、涨到多少（不显示战力，避免与费用混淆）。同一批同卡的费用变化会合并成一次演出（`flushCostFlash` 内按卡合并 `d`）；被改的卡若恰好在场上/我方手牌可见，卡位另加一次橙金提亮闪动（`.cost-changed`）与侧栏小气泡点缀（`.gain-ring.cost-ring` + `.buff-gain-pop.cost-pop`）。
- **遮蔽口径**：被加费的目标**对玩家公开**（日志点名 + 气泡 + 此后「👁️ 查看」里那张牌显示红色费用）；AI 侧不额外提示，但它的 `aiThink` 会按 `cardCost` 判定可负担，因此加费实际会影响它下回合的出牌选择。

**额外能量（v169，现仅 `energyNext`／斯塔萨菲雅）**：揭示让自己一方**在下个回合**多拿 N 点能量，引擎用**登记式**收口：
- **登记**：`addPendingTurnEnergy(side, n)` → `state.pendingEnergyGain[side] += n`；**可叠加**（同回合两张斯塔萨菲雅＝下回合 +2），跨回合不会提前生效。
- **结算点**：下一个回合开始时的 **①-2 能量结算**（`roundStartStage` → `grantTurnEnergy(base)`）——`energyTotal = 基数 + 登记值`、`energyLeft` 同值，并把本次生效的额外值写进 `players[side].energyGain`，**登记值随即清零**（**一次性**：不是每回合都给，与 `grow` 那类“每回合末都触发”的机制区分）。
- **归属**：按**牌的所属方**（`side`）——玩家打出给自己、AI 打出给自己；开发调试「⇄ 切换立场」把牌落到敌方一侧时该牌归属对手，故加的是**对手**的能量。对双方一视同仁。
- **时序**：揭示发生在阶段 ④，此时本回合能量早已结算完，因此效果**不会**对当前回合生效，只影响下一回合；区域字段、格位、`surv`/`phx`/`prot`/摧毁类机制都与本效果无关（非“摧毁”、非放置）。
- **终局边界**：第 6 回合（最后一回合）翻开时**不存在“下一回合”**，这份额外能量**本局不会生效**（仍会登记与记日志，日志会明确提示）；本局结束后登记随 `restart` 清空。
- **界面**：顶栏能量框在额外能量生效的那一回合显示绿色角标 **「+N」**（`#energyBonus`，`players.p.energyGain` 驱动，回合结束随下次结算归零）；日志记「🔋 你本回合获得额外能量 +N（能量上限 X；一次性，仅本回合有效）」。
- **演出（v169，两段）**：① **登记段**（揭示当刻，`playEnergyBookFx`）——在斯塔萨菲雅的卡位上播放卡面金光闪烁（`.energy-card-flash`）+ 金色光环扩散（`.energy-ring`）+ 8 颗星光迸发（`.energy-star`：⭐✨🌟💫 随机角度飞散）+ 「🔋 能量 +1」大号金字气泡与「下一回合生效」小字（`.energy-pop`），表达“这份能量已预约”；② **到账段**（下回合开始能量结算时，`playEnergyGainFx`）——锚点换成**顶栏能量框**（对手侧则用侧栏「对手（AI）」信息区），播放绿色闪光（`.energy-box-flash`）+ 同款星光 + 「🔋 能量 +1」气泡（小字列出来源卡，如多张斯塔萨菲雅会写「斯塔萨菲雅、斯塔萨菲雅」），与绿色「+N」角标同时弹出。两段都放 body 悬浮层（z-index 9400/9410，`pointer-events:none`）不挡操作；卡位/能量框取不到（尺寸为 0）时跳过该段，末回合登记时会跳过登记段（不会生效）。

**游戏开始时（`gs`，v185；现仅 7 费「哆来咪」使用，`gs: { shuffleN: 10, energyAdd: 1 }`）**：**卡级机制**（**不是揭示键**，`k` 仍为 `''`），在**阶段 ⓪ `runGameStartEffects()`** 结算——`restart` 完成建库 / 抽选三块真实地形 / 生成区域后、**第 1 回合开始前**执行，`clearLog` 与开局那条「新对局开始」日志之后、`renderAll` 与 `playOpening`（玩家初始 3 张逐张发放）**之前**。
- **触发条件与持续性（用户口径）**：只要**开局时这张牌在自己一方的牌库/起手中**（＝它被放进了那 12 张卡组）就触发，且**整局永久生效**——之后它被抽到手、被打出、被摧毁、凤凰重生回手都**不回收**已洗入的 10 张牌与已加的能量；开局时它不在牌库（开发调试的空牌库、或没把它编进卡组）则**什么都不发生**。判定按 `牌库 ∪ 起手 ∪ 场上`（对手的 3 张起手在 ⓪ 之前已发，故不能只看牌库），归属按**牌的所属方**（对双方一视同仁；实际只有玩家能通过「卡组设置」自建卡组带它）。每张带 `gs` 的卡各结算一次（正常只能带 1 张，多张则效果叠加）。
- **`gs.shuffleN: N`（洗入 N 张随机牌）**：从**普通卡牌池 `POOL`** 里**不放回随机抽 N 张互不相同**的牌 def，各自以**新卡实例**（`newCard`）洗入**自己一方的牌库**，随后整副牌库重新随机洗一次（复用 v184 的 `shuffleCardsIntoDeck` 收口，逐张加入后由它重洗）。口径：
  - **只取 1~6 费**：0 费「稗田阿求」按 0 费组“暂不进洗牌”的既有口径排除；**7 费及以上（哆来咪自己所在档）不参与**；
  - **完全不碰衍生卡池 `SPECIAL`**：法术 token（火神之光 / 祖母绿巨石 / 绿色风暴 / 水银之毒 / 金属疲劳 / 极限火花 / 耀眼之龙玉 / 蓬莱的玉枝）与普通 token（石块 / 厄运 / 河童 / 幽灵 / 水银 / 祖母绿巨石占位 / 无限生命泉 / 火蜥蜴之盾 / 佛体金刚石 / 龙玉 / 冰块 / 隙间）**都不会被抽到**；
  - **包含 `POOL` 里的法术卡**（三妖精集结 / 镇守大地之石 / 地精的起床）与 1~6 费的全部人物卡（含大体积 `occ:4` 的伊吹萃香）；
  - 排除 `un` 占位卡与**带 `gs` 的卡自己**（避免自我复制）；抽出的牌**允许与你卡组里已有的同名卡重复**（只从卡池抽，不查你的卡组构成）；
  - 张数无上限（牌库没有 7 张上限，「手牌满则失败」的口径不适用）；进的是**隐藏区牌库**——不翻开、不占格位、不进 `fieldQueue`、**不结算被洗入卡的任何效果**，日后抽到手再打出时按常规流程走（与 v184 `shuffleIn` 同口径）；
  - 池子不足 N 张时取手上有的那些（实际 1~6 费共 43 张，正常足够）。
- **`gs.energyAdd: N`（每回合最大能量 +N）**：登记进 `state.energyAddPerTurn[side]`，在**每次回合开始的能量结算**（①-2 `grantTurnEnergy`）里**并入基数**：第 t 回合 = `min(t, 6) + N`（开发调试 = 10 + N）。与斯塔萨菲雅的 `energyNext`（`pendingEnergyGain`，**下回合一次性 +N**）**叠加**（7 + 1 = 8），但它是**本局永久**、不像 `energyNext` 那样结算后清零；`restart` 时随 `state.energyAddPerTurn` 重置。

**时机效果（v55，非揭示；字段 `fx`）**：卡牌 def 可声明 `fx: { turnStart, turnEnd, gameEnd }`，各条目与揭示规格同构（`k`/`a`/`spawn`/`xf`/`give`/`t`，复用 `applyEffect` 结算逻辑；v172 起 `drawSpell` 另可用 `n`/`pool`）。触发时机与顺序：**回合开始**（每回合最先、先于能量/抽牌）、**回合结束**（翻牌结算后、**地形类回合结束效果之后**——v153 起每回合结束时先结算地形 `decay`/`purge`，再结算场上的「回合结束」卡牌效果）、**游戏结束**（第 6 回合阶段全部结束后、结算胜负前）——全场按**场上放置顺序队列**（`state.fieldQueue`：双方卡牌放入场上的先后，谁先放谁先结算）遍历结算带该时机效果的卡。手牌打出/落场特殊卡入队；被摧毁、重置撤回手牌的卡出队（不再触发后续时机）；移动（`mv`/`fly`/`roam`）不变序。**现注册 `fx.turnStart` 的有两张卡**：「幽灵」（v158：`{ k: 'roam' }` → 每回合开始若可能就随机飘到另一区域）与「帕秋莉·诺蕾姬」（v172：`{ k: 'drawSpell', n: 1, pool: [...] }` → 每回合开始从帕秋莉法术池随机抽 1 张法术加入手牌，见下文「帕秋莉法术池」段）。**现注册 `fx.turnEnd` 的有 1 张卡（v179）**：「**蕾米莉亚·斯卡蕾特**」（`fx.turnEnd = { k:'bl', a:3 }` → **每回合结束**若其所在区域落后就**永久 +3 战力**：判定走 `zoneEff` 本区比较口径（含 `dbl`、反转区按负值），**每回合末各判一次、可累积**；第 6 回合末同样结算并计入终局；结算点在 ⑤-0 地形类回合末效果**之后**，故读到的是本区已被地形改动过的实时威力；**「回合结束」不受 v160「刚登场跳过当回合」的限制**，她翻开的当回合末就会判一次）。**v160 口径**：「回合开始」效果只结算**本回合开始前就已经在场上**的卡——地形「出现时」在①-0 当回合生成的卡（如幽灵洋馆的幽灵）**跳过当回合**的回合开始效果、**从下一回合起**才结算（入队时记录 `fieldTurn` 与当前回合比对，跳过时记一条日志）；回合结束 / 游戏结束不受此限。

**区域变形（`xform`，现仅 鬼人正邪 → 辉针城、灵乌路空 → 聚变反应炉）**：揭示把该区域 def 整体换成目标地形（含 `max`/`inv`/图标/名称）。原为限张地形时隙间格位随上限变 4 自动消失、可继续放牌；任一方现卡数超过目标上限则变形失败；**变形等同于该地形在本区“出现”（v151）：目标地形的一次性「出现时」效果（spawn 等）立即结算一次**，与地形揭晓共用 `runLocAppearEffect`——例：把本区变成虹龙洞就立刻双方各生成 1 张「石块」（该侧已满则少放并在日志注明）；本区原本就已经是目标地形时不重复结算；`purge`/`minTurn` 等按新地形从变形起生效。

**持续效果（`og`，卡级机制，原「在场光环」；v179 起支持两种匹配口径）**：定义＝此牌翻开后**持续存在**的效果（一次性结算的对偶，与「揭示」互补）。**源卡只要已翻开且仍在己方场上**（任一区域），己方场上**符合匹配条件**的卡牌威力常驻 +N，按全场计算（不受目标卡所在区域/回合限制）；**实时动态**——源卡被摧毁/凤凰重生回手/换边离场即消失，已加成不残留；**不进永久 buff 台账**（`powerLog`），但会作为一行**持续效果**显示在卡牌「战力影响历史」里（`powerHistoryRows` 第 3 段，判定与 `cardAuraBonus` 完全一致，保证“合计 = 场上当前威力”）。两种匹配口径：

| 写法 | 匹配对象 | 使用者 |
| --- | --- | --- |
| `og: { tk, add }`（v55） | 己方场上带该 `tk` 标记的 token（token 用 `tk` 标记种类） | 比那名居天子（`tk:'rock'` → 己方**石块** +2） |
| `og: { cost, add }`（**v179**） | 己方场上**印刷费用 `def.c`** 恰为该值的卡牌——**含特殊卡 token**（口径同「雾之湖」的费用加成 `cb`：**被加费只改 `cardCost`、不改变印刷费用档位**的判断；**法术无战力、不吃任何战力加成**故不受影响） | 克劳恩皮丝（4 费/4 战力 → 己方**所有 1 费卡牌** +1，含 1 费 token 如石块/祖母绿巨石占位） |

> 两种写法可同时存在于同一张卡上（互不冲突，满足任一即计入）；`og` 只由 `cardAuraBonus` / 战力影响历史读取，**没有** `applyEffect` 分支（不是一次性结算、不产生 `k` 效果、也不触发任何演出与摧毁类机制）。

**防摧毁（`surv`，卡级防护；现仅灵乌路空 `surv:2`）**：带 `surv: N` 的卡被任何“摧毁”指向时（`dw`/`dwh`/区域回合末 purge 等）**不会离场**，取而代之**永久降低 N 点战力**（每次触发再降 N、可多次；若在聚变反应炉中反复成为全场最低会被反复降低）。被替代时不离开场上放置队列（后续时机仍可结算/继续判定）；仍可被增益等正常影响；与 `un`（绝对不可动）不同——它只是“摧毁被替换”，其余照常。

**凤凰重生（`phx`，卡级机制；现仅藤原妹红 `phx:2`）**：带 `phx: N` 的卡被任何“摧毁”指向时（`dw`/`dwh`/区域回合末 purge 等）**不会消失**——从场上移除后**返回自己手牌**并**永久 +N 战力**（每次触发 +N），可反复“摧毁→重生→再打出”并持续成长；重生瞬间从场上离开（移出放置队列），再次打出时重新暗出/翻面入队；手牌已满 7 张则重生失败、按原样被摧毁。与防摧毁 `surv` 的区别：`surv` 留在场上降战力、`phx` 离场回手并成长。

**区域免摧毁（`prot`，现两个来源：卡级持续机制「蕾蒂」，与 v164 起的地形字段「睡鼠神祠」）**：**地形带 `prot`（睡鼠神祠）时**，该区域（**双方**）所有在场卡牌均无法被摧毁——引擎在任何“摧毁”指向结算前查 `locNoDestroy(locIdx)`（第一优先判地形字段），本区 `dw`/`dwh`（applyEffect）与回合末摧毁 `purge`（reactorPurge）直接失效、不选目标，防摧毁 `surv` / 凤凰重生 `phx` 也不会触发；保护含双方已翻开人物卡与落场 token（石块/厄运/分身等）以及此后在该区落下的任何卡；地形随 `xform`/`collapse` 被换掉即失效。**卡级 `prot`（蕾蒂）**：带 `prot` 的卡翻开后、仍在自己某区域场上期间，同样让该区域双方免摧毁（`locNoDestroy` 第二优先：遍历双方该列找“已翻开且仍在场”的 `prot` 卡）。两者可叠加但结果相同；防护按源卡所在区域实时判定：蕾蒂被移去其它区域 → 原区域立即失效、新区域立即生效；**同区换边（switch/gift 类把她在本区换到对方一侧）仍在同一区域，因保护的是敌我双方，效果不变**；源卡真正离场才全场失效。

**自身不可摧毁（`ind`，卡级持续机制；**v180 新增**，现仅「佛体金刚石」`ind: true`）**：带 `ind` 的卡在**它自己**在场期间，**摧毁判定落在它身上时会失败**——它是**判定式免疫**（不是“被剔出候选池”）：`dw`（比最弱）/`dwh`（比最强）/`dwb`（比双方最弱、并列随机抽一张）/地形 `purge`（比本区最低）在**决定“谁是目标”时都把它一起算进去**，一旦选中它：
- **①摧毁失败 + 本次判定结束**：它不离场、战力不变，**不会改打其他牌**（结算点 `indestructibleBlock`，日志记「…的摧毁判定落在「佛体金刚石」上，但它自身不可摧毁 → 本次摧毁失败、判定结束（不改打其他牌）」）。例：聚变反应炉里本区只有**金刚石 6 力 + 辉夜 8 力**时，本区最低是 6 力的金刚石 → 判定落在它身上 → 摧毁失败 → **辉夜存活**、金刚石也留在场上（⚡ 日志只出现“摧毁失败”那一条，不会去杀 8 力的辉夜）。
- **②不触发** `surv`（防摧毁改降战力）/ `phx`（凤凰重生回手）等“被摧毁时”的替代机制——它连“被摧毁”这一步都没走到。
- **并列池的随机口径**：`dwb`/`dwh` 在并列里**随机抽一张**，`ind` 卡**照常在这张池子里**——抽中它＝失败、判定结束；抽中别的并列牌则照常摧毁（不是“先把它排除再抽”）。
- **范围与区别**：**只保护它自己**——同一区域的其他卡（含对方卡）照常可被摧毁。与 `prot` 的**区域免摧毁**不同：`prot`（蕾蒂／睡鼠神祠）在**任何判定之前**就整条拦掉效果、保护**本区双方全部**卡牌；`ind` 不改判定的对象集合，只是“它打不死”。也不是 `surv`（后者被点名后**永久 −N 战力**，`ind` 被点名后**什么都不发生**）。
- ⚠️ **非“摧毁”类效果照常对它生效**：战力增减（`bf/de/ba/bl/dwb`/`deAll`/地形 `grow`·`decay`·`dice`·`rally`·`gamble`）、移动（`mv`/`roam`/`gust`/`fly`）、换边（`switch`/`gift`）、回手（`phx` 自身触发）等一律不受 `ind` 影响。
- **预判一致**：`revealEffectWillChange` 按同一口径算出“这次会被判定选中的是谁”，若结果是 `ind` 卡则**不产生变化** → 不会空等结算前的 400ms 停顿。

**终局离场（`leave`，卡级机制；现仅稗田阿求）**：带 `leave: true` 的卡在**游戏结束时**（第 6 回合全部阶段后、结算胜负前）**从场上消失**——它不是“摧毁”，**不触发任何摧毁相关机制**（不会触发防摧毁 surv / 凤凰重生 phx / 各类摧毁文本），永久 buff 与卡牌一起离开、不计入终局结算。若其离场使该区放满加成等实时判定变化，按既有规则自动刷新。

**大体积占格（`occ`，卡级机制；现仅伊吹萃香 `occ:4`）**：带 `occ:N` 的卡单卡占据 N 个格位（普通卡为 1）。`occ:4` 占满区域全部 4 格：**只能放进最大可放数为 4 且己方该区没有任何卡**的区域；放置/在场期间该侧视为已满（不能再落其它卡、spawn/移入等按占格口径判定；放满加成 fill 按占满 4 格计算）；卡面渲染为放大覆盖整侧 2×2；被摧毁（含反应炉等）、移走、换边、撤回或离场后自动腾出这些格位。引擎统一用 `sideUsed`/`sideRoom` 计占格，避免误用 `zone.length`。**交互口径**：换边（依神紫苑 `switch` / 因幡帝 `gift`）落到对方侧时按对方侧空余 ≥ 移入卡占格判定——对方侧被萃香占满（空余 0）则无法换边；`mv` 等把卡移往另一侧时同样要求目标侧空余 ≥ 该卡占格数（大体积卡只能移入完全空出且上限足够的一侧，即对方该区已有任何卡时萃香不能被移过去）。

**分身（`clone` 效果键，现仅赫卡提亚 → 赫卡提亚的分身）**：揭示时向**另外两个区域**（不含本区）**自己一侧**各放 1 张分身（该侧放满或区域未开放则跳过该区，两区都放不下则失败）。分身落地即翻开、占格位、进入放置队列；其战力按本体**揭示时 `cardPower`（基础+永久 buff）快照**对齐（差值记在分身的 buff 上，本体随后的增减不影响分身），分身自身之后可被增益/削弱独立修改；分身无其它效果。

**换边（`switch` 效果键，现仅依神紫苑）**：揭示后**立即把自己从一侧转移到对方该区域一侧**——翻开时若在己方一侧则消失并落到对方该区（反之同理，本规则下任何卡都在自己一侧翻开，故统一为“翻开后换到对方一侧”）；转移后卡牌归属对方（`card.side` 更新），作为对方已翻开卡参与结算（−7 战力计入对方该区），占对方一个格位，场上放置顺序不变；对方该区已放满则**换边失败、留在自己一侧**（负战力将继续计入己方）。

**变身（`morph` 效果键，现仅二岩猯藏）**：揭示时从**对方手牌随机取一张**，把自身整体替换成该卡的**复制体**（原卡仍留在对方手牌；名称/费用/威力/图标/效果/配图全部变为目标卡）。变身后**重新触发新卡的效果文本**：若新卡带 `k`（揭示）立即按其结算一次（若新卡也是变身卡则不二次变形，防死循环）；持续 `og` / 每回合移动 `fly` / 时机效果 `fx` / 防摧毁 `surv` 等由新 def 实时驱动自动生效。对方手牌为空则变身失败、保持原样。**大体积目标限制**：若随机目标是占多格的大体积卡（如萃香 occ:4），仅当**本区域 max 恰为其占格数**且**己方该区（明牌+暗牌合计）有且仅有变身者这一张卡**时才可变身，否则变身失败、保持原样（防止变身后与其他卡共存导致占格超限）。

**送己方最低卡（`gift` 效果键，现仅因幡帝）**：揭示时把本区域**己方战力最低的已翻开卡**（不含自己；多张并列最低则随机选一张）**换边**到对方该区域一侧——目标占对方一个格位、归属变对方、该卡的持续效果按新归属方生效（如把天子换边过去，会改为给新一方石块 +2）；对方该区已放满则换边失败；本区没有其他已翻开的己方卡则无事发生。

**整体右移（`shift` 效果键，现仅八云紫）**：揭示时把己方**最左侧区域**（第 1 列，下标 0）**已翻开**的卡牌**按放置顺序依次**搬到**最右侧区域**（第 3 列，下标 2）己方一侧，直到右侧己方侧**填满**为止——按占格 `occ` 判定（右侧空余 ≥ 该卡占格数才搬，右侧放满即停止）；**只搬已翻开的卡**（暗牌、`un` 卡不动）；不改变归属、揭示状态、场上放置顺序队列；移动后各区域总点数/放满加成实时重算；施放者本牌若在最左侧也会被一起搬。**演出（v78→v79）**：正常翻牌揭示结算时逐张搬运、每张间隔约 0.3s，且每张以**滑行+缩放飞行演出**落到右侧格位（`peekShiftCard`/`shiftMoveCard`/`flyCardTo`/`applyShiftReveal`）；morph/fx 等其它结算路径为一次性同步搬运。

**法术（`spell`，卡级机制；v170）**：`def.spell === true` 的卡是**法术**——**只具有能量花费（`def.c`）与「揭示」效果（`def.k`）**：数字侧写 `spell: true`（战力记 `p: 0`，不要再声明 `og/surv/phx/prot/occ/fly/fx/clone` 等其它卡级机制，也不要用 `bl/oc/switch/morph/roam` 这类对自身生效的键）。口径：

- **无战力**：`cardPower` / `cardPowerIn` 对法术**恒为 0**；**卡框不显示战力**（**v178 起**卡面右上角的战力位只显示一个 **「✦」星标**——不再写「法术」二字；悬停该星标有 `title="法术 · 无战力（揭示后消散）"` 提示，手牌/图鉴/卡组页/放大视图与场上缩略卡同款）；不吃阵营 `aff` / 费用 `cb` / 全区 `all` / 持续 `og` 任何加成；**任何位置都不受战力增减**（`applyPermBuff` 对法术直接跳过——手牌里不会被打 buff，场上揭示瞬间也不会被 ±N，地形 `gamble`/`dice`/`grow`/`decay`/`rally` 同样不作用于它），因此也不进战力影响历史。
- **占位（暗牌与揭示瞬间）**：作为暗牌放置**需要一个空位**——`occ` 恒按 1 计，出牌走 `sideRoom` 判定（能因此把一侧堵满、也会影响对方 `switch`/`gift`/`mv` 的落位判定）；**揭示瞬间法术本身仍占 1 个格位**（因此会参与“该侧是否已满”与放满加成 `fill` 的判定，**它自己的生成类效果也可能因本侧满而放不下**），格位到「揭示效果结算完之后」才腾出。它的“已放置”照常让 `oc`（对方同区本回合落过牌）触发、照常进 `playerMoves`/`aiMoves` 与场上放置顺序队列。⚠️ **v179 唯一例外**：`spawnS` 的 `fill: true` 写法（法术「镇守大地之石」）为达成“**消散后正好铺满**”，改为**先消散自身、再按空位铺满**（在 `applyEffect` 的 `case 'spawnS'` 内显式调用 `vanishSpell`；随后 `revealRound` / `settleFieldSpell` 里那一句调用会因“卡已不在场上”自然跳过，不重复记日志或播动画）——即把自身那 1 格也让给生成的卡。
- **消散（在且仅在揭示效果结算完之后）**：`vanishSpell` 把它从所在区域移除、移出放置队列、腾出格位，并播**消散演出**（克隆卡面上浮淡出 + 淡紫星光，`playSpellVanish`/`spawnSpellSparks`）与一条日志。**这不是“摧毁”**：不走 `phoenixRevive` / `surviveDestroy`、不查 `locNoDestroy`、不播分崩离析、不触发任何摧毁类文本；**不返手、不返牌库**（一局就这一份）。区域「揭示后吹飞」（`gust`）会因该卡已不在本区而自然跳过。
- **全面免疫（避免白费一次指向）**：`dw`/`dwh`（最弱/最强）、`mv`（对方最弱）、`gift`（己方最低）等**“按威力选目标”的效果不选法术**；`bf`/`de`/`ba` 等增减**跳过法术**（也不计入“影响 N 张”）；二岩猯藏 `morph` **不以法术为变身目标**（变身后会立刻消散，语义混乱）；回合末 `purge` 也不把法术列入摧毁候选。
- **两种池子**：① **角色池（`POOL`）法术**——可入卡组（`js/deck-page.js` 按印刷费用档展示）、可被图鉴查看、**会被玩家兜底牌库与 AI 随机曲线抽到**（AI 的法术估值 **v173 起**改为按效果推演，见 §6 AI 策略条）；② **衍生物池（`SPECIAL`）法术**——由 `give` **塞入手牌**（仍需手动打出，走正常翻牌流程；**v177 起**：雾雨魔理沙 → 极限火花），或由 `placeToken`/`clone` **落场生成**：**等同手打一张**，先结算它自身的揭示、随即消散（`settleFieldSpell`，同步结算、无 400ms 停顿与翻牌演出）。衍生法术在开发者「🎯 指定卡牌」里**可以加入手牌**（其余衍生卡仍仅可查看）。
- **费用修正照常**：法术有能量花费，故 `costUp`（桑尼米尔克）可以给它加费，`cardCost`/卡面费用着色与「印刷费用 → 现在」提示照旧。

**集结（`gather` 效果键；v171，现仅法术「三妖精集结」）**：`def.gather = { group: 阵营键, add: 强化值 }`（现 `{ group: 'light', add: 1 }`）。揭示分**两步**，顺序固定：

1. **随机分配生成**：从 `POOL` 里取出 `g === group` 的成员卡（**去重**；排除 `un` 占位卡、法术（`spell`）、大体积卡（`occ > 1`）——见 `gatherMembers`），**随机排列**后**按区域顺序**（左→中→右）分配：三个区域**自己一侧各生成 1 张**，因此**三张互不相同**（成员多于 3 张时随机取 3 张；少于 3 张时靠后的区域分不到、日志写明）。生成走 `placeToken`：**落地即翻开、占一个格位、进入场上放置顺序队列**并播「凝聚显形」演出。
   - **“若可能”＝跳过**：某区域该侧**已放满**（`sideRoom < 1`）或**区域未开放**（`locOpen`，如七夕坂第 5 回合前）→ **跳过该区，不把这一张补到别的区域**，日志列出被跳过的区域与原因。
   - **生成后立即结算它们自身的「揭示」**（v171 口径，与地形 `spawn.reveal` 同款）：按**落场顺序**同步结算（无 400ms 停顿与逐张翻牌演出），故抽到桑尼米尔克会当场让对方手牌随机一张 +1 费、露娜·切露德会当场削弱同区对方已翻开卡、斯塔萨菲雅会给**施法方自己**下回合 +1 能量（揭示在阶段 ④ 结算，能量在下回合 ①-2 到账）。
2. **在这之后强化己方**：给自己一侧**场上已翻开**的该阵营卡牌**永久 +add 战力**（走 `applyPermBuff` 收口：±N 演出 + 战力影响历史按来源记这张法术卡名）。**含刚生成的那几张**（它们落地即翻开）；**只算自己一侧**（对方场上的同阵营卡牌不动）；**暗牌不参与**（同 `bf/de/ba` 的增减目标口径——翻面后错过本次结算）。若己方场上没有已翻开的该阵营卡，这一步无事发生并记日志。

**与法术占位的交互（重要）**：因为法术在揭示期间**仍占 1 格**，若这张「三妖精集结」正好是某区域的**第 max 张**（例如该区自己一侧本就 3 张、法术是第 4 张），那么该区**自己一侧已满 → 这一区的三妖精被跳过**（法术要等揭示效果结算完才腾出格位），另两区照常；法术随后按法术口径自行消散。

**分步亮相（v171，只在正常翻牌流程里）**：在阶段 ④ `revealRound` 结算「三妖精集结」时走**异步分步演出** `applyGatherReveal`——按**区域顺序**推进：**第 1 区的妖精生成并结算揭示 → 停 0.5s → 第 2 区 → 停 0.5s → 第 3 区 → 停 0.5s**（相邻两次揭示的间隔约 **0.5 秒**，每区先 `renderZones()` 播「凝聚显形」再结算该区揭示并重渲染，故 ±N 气泡/削弱/能量星光是一区一区地弹出来）；三区都揭示完之后**才**结算第 ② 步「己方场上已翻开的三妖精 +add 战力」（并再留约 0.5s 让 ±N 演出可见），**随后才播放这张法术的消散演出**（`revealRound` 在揭示结算完后紧跟着 `if (isSpell(card)) vanishSpell(...)`）。被跳过的区域不产生演出，只在日志里点名。其它结算路径（`morph` 变身、`fx` 时机效果、落场生成的衍生物法术 `settleFieldSpell`）走**同步版**（`applyEffect` 的 `case 'gather'`：一次性生成 + 结算，无 0.5s 节奏与逐步渲染），两者口径完全一致。中断保护同 `applyShiftReveal`：重新开局（`state.gen` 变化）时立即停止后续步骤。

**它与既有机制的关系**：生成的卡是**普通人物卡实例**（不是 token），有独立 `id`/`buff`/揭示，之后可被增益/削弱/摧毁/移动正常影响；`oc`/`bl`/`gamble` 等按“它们自己也是本回合落场/翻开”的既有口径处理（`gamble` 对“落场即翻开”的卡不追溯）；`decay`/`grow`/`dice`/`rally`/`purge` 照常作用于它们；AI 的落子估值 **v173 起**会按 `gather` 的实际生成推演：用**成员平均战力**代表三区各生成的那 1 张（引擎是随机取 3 张，AI 取期望近似），并计入随后的「己方场上已翻开同阵营 +add」。

**帕秋莉法术池（`drawSpell`，时机效果；v172，现仅「帕秋莉·诺蕾姬」）**：**帕秋莉·诺蕾姬**（**v172 重做**：原 2 费 / 2 战力 `bf +2` → **3 费 / 2 战力**，`k` 变为白板、只带时机效果 `fx.turnStart`）在**回合开始时**从**帕秋莉法术池**随机把 1 张法术加入自己手牌。口径：

- **池**：写在帕秋莉的 `fx.turnStart` 条目里 —— `{ k: 'drawSpell', n: 1, pool: [SPECIAL 键名…], t }`，卡级 `spellPool: [键名…]` 作兜底；池内现为 **5 张 1 费法术**（火神之光 / 祖母绿巨石 / 绿色风暴 / 水银之毒 / 金属疲劳，清单见 `docs/现有特殊卡牌.md`），**只有 `spell: true` 的条目会被采用**（非法术条目一律忽略，防数据写错）。
- **随机、可重复**：每回合独立随机，**同一张法术可能连续几回合都抽到**（不洗池、不做不放回管理）。
- **加入手牌**：由 `newCard(TOKENS[key])` 生成**新的卡实例**并打 `justHandAdded` 标记（渲染后播“滑入”演出 `.hand-new`）；**手牌满 7 张则本次加入失败、无事发生**（同 `give` / `phx` 回手的既有口径，只记一条日志说明）。
- **归属**：按**牌的所属方**（与 v169「额外能量」同口径）——玩家打出给自己、AI 打出给自己；被 `gift`/`switch` 换边到对方一侧后，按换边后的**新归属方**抽给那边。
- **时机（重要）**：`fx.turnStart` 在每回合的 **①-1（全场回合开始效果）**结算，早于能量结算与抽牌，因此抽到的法术**当回合出牌阶段就能用**；而帕秋莉本回合是在**阶段 ④** 才翻开的，按 **v160 口径**「刚登场的卡跳过当回合的回合开始效果」，**她从翻开的下一回合起**才每回合抽 1 张（与「幽灵洋馆」的幽灵当回合不游走同一逻辑）。
- **抽到的法术**照常走 v170 的「暗出 → 翻牌揭示 → 自行消散」流程（1 费能量；作为暗牌占 1 格；揭示瞬间仍占格；消散后腾出格位并播消散演出）。5 张法术与它们的 token **不入牌库、不出现在图鉴的人物卡档**（只在图鉴**「衍生卡牌池」**、帕秋莉的「衍生卡牌」面板里可见；**v178 起衍生卡自成一层的卡池**，见 §6「图鉴与「指定卡牌」的两层筛选」），开发者「🎯 指定卡牌」可把法术加入手牌便于验证（v170 起对法术 token 的既有口径）。
- **AI**：AI 抽到帕秋莉时同样每回合抽法术（对双方一视同仁）；**v173 起** AI 对法术的估值改为**按效果推演**——影子盘面会真的结算它自己的揭示（`de`/`bf`/`dwb`/`spawnS` 等对盘面的影响都计入），因此这些法术在 AI 手里**不再一律滞留**（只有推演结果会把局面变差时才选择不出，例如 `dwb` 火神之光推演出会摧毁自己那张最弱牌）。
- **5 张法术各自的效果键**：**`dwb`**（火神之光：摧毁本区**双方**已翻开、战力最低的**随机一张** —— 并列最低在其中随机挑一张；排除暗牌／`un`／法术；受 `locNoDestroy`（地形 `prot`／蕾蒂）保护时整条失效；目标带 `surv`/`phx` 时按各自机制处理；⚠️ **可能摧毁己方自己的卡**）、**`spawnS`**（祖母绿巨石：在本区**自己一侧**生成 1 张 **1 费 / 3 战力**的同名占位卡，本侧放满则失败），以及**复用既有键**的三张：绿色风暴 = `bf +1`（该区已翻开友方 +1）、水银之毒 = `spawnO`（1 费 / −1 战力的「水银」落**对方一侧**，口径同「厄运」）、金属疲劳 = `de −1`（该区已翻开敌方 −1）。绿色风暴／金属疲劳只作用于**结算那一刻已翻开**的卡（同 `bf`/`de` 口径），法术自身免疫战力增减故“含不含自己”结果相同。


**洗入卡组（`shuffleIn` 效果键；v184）**：`def.shuffleIn = { card, n, to }` —— 揭示时把指定牌 n 张**洗入某一方的牌库**，并把该方**整副牌库重新随机洗一次**。这是继「进手牌」（`give`）、「落场」（`spawn`/`spawnO`/`spawnS`/`spawnMine`/`clone`）之后**第三种“牌的去处”**：进**牌库**（隐藏区）。口径：

- **写法**：`card` 先按**衍生池 `SPECIAL` 的键名**查（如 `'stone'`），查不到再按**卡名**在人物池 `POOL` 里找（如 `'琪露诺'`）——即人物卡与 token 都能引用（`findCardDefByKey`）；`n` = 张数，缺省 1，每张都是**全新的卡实例**（`newCard`，`costMod` 自然为 0、不继承任何既有费用修正）；`to` 缺省 `'own'` = 洗入**施放方自己**的牌库，`'opp'`（也接受 `'a'`）＝洗入**对方**牌库。
- **可作揭示，也可作时机效果**：与其它效果键一样，本键走的是同一条 `applyEffect` 分支 —— 既可写成卡牌的揭示（`k: 'shuffleIn'`），也可挂到 `fx` 时机效果上（如 `fx.turnStart = { k: 'shuffleIn', shuffleIn: { card: 'stone', n: 1 } }`，结算逻辑完全相同）。
- **张数无上限**：牌库不是手牌，**没有 7 张上限**，「手牌满则失败」的既有口径**不适用**；开发调试的空牌库洗入后同样会变得可抽。牌库张数也不影响终局结算（终局只看场上）。
- **重洗范围 = 该方整副牌库**（含原本尚未抽到的所有牌）：实现为 `shuffleCardsIntoDeck(side, def, n)` —— 逐个 `newCard` + 打 `side` 归属 + `deck.push`，最后就地 `shuffle(deck)`（Fisher-Yates）。`drawOne` 从**队尾** `pop`，所以重洗之后“下一张会抽到什么”**立刻改变**；牌序本来就纯随机（v139），重洗不引入新的公平性问题，只改变后续抽牌分布。
- **不结算被洗入卡的任何效果**：它进的是牌库——**不翻开、不占格位、不进场上放置顺序队列**（`fieldQueue`），也不触发揭示 / 持续 `og` / 时机 `fx` / `surv` / `phx` / `prot` / `ind` 等任何机制，更不进战力影响历史（`powerLog`）。日后被 `drawOne` 抽到手牌、再被**暗出翻开**时，才按该卡的常规流程结算（与开局洗牌同口径）。因此**带效果的卡也能被洗入**，只是效果要等它被打出才发生。
- **归属对双方一视同仁**：按**牌的所属方**（`side`）决定落进谁的牌库——玩家打出给自己、AI 打出给 AI；被 `switch`/`gift` 换边后按**新归属方**结算（同 v169 额外能量 / v172 抽法术的口径）。
- **公开与演出**：日志点名「把 N 张「X」洗入了谁的牌库，并重新洗了一次牌（现牌库 M 张）」（洗入对手时走红色 `danger` 提醒，与 v169 加费公开、摧毁类日志同款）；随播轻量演出 `playShuffleInFx`——**牌库计数闪光 + 外扩光环 + 星光迸发 + 「🃏 洗入卡组 ×N」气泡**（副行写「来源卡 · 牌名 → 你的牌库 / 对手的牌库」），锚点＝玩家侧手牌区「牌库 N」（`#deckCountVal`，**v184 新增**的常驻计数）、对手侧侧栏「牌库 N 张」（`#aiDeck`）；取不到锚点或尺寸为 0 时静默跳过、只留日志。
- **与其它机制的边界**：非“摧毁”/非放置/非增减类 —— 与 `locNoDestroy`、`surv`/`phx`/`prot`/`ind`、区域字段（`purge`/`grow`/`decay`/`dice`/`rally`/`gamble` 等）、格位（`sideRoom`/`occ`）、放满加成全无交互；被洗入的实例也不参与 `un`/法术那套“不可操作/无战力”判定（它还没上场）。
- **预判**：`revealEffectWillChange` 的 `shuffleIn` 分支在「条目合法且 `n > 0`」时**恒为 true**（牌库张数与抽牌顺序一定会变，不像 `give` 会因满手落空），因此照常走结算前的 400ms 停顿与翻牌演出；键名写错时不空等、只记一条日志。
- **首个使用者（v184）**：本键与**重做后的「琪露诺」（1 费 / 2 战力）**同版落地——写法为 `k: 'shuffleIn'` + `shuffleIn: { card: 'ice', n: 1, to: 'opp' }`，效果是**向对手的牌库洗入 1 张「冰块」**（token，1 费 / 0 战力白板，见 §3）；被洗入的冰块只是**稀释对手牌库 + 占用其手牌位**（对手抽到一张 0 战力白板，其手牌满 7 张后还会因「手牌满不抽牌」卡住后续抽牌），它自身的“效果”要等对手把它抽出并暗出翻开时才按普通白板卡结算。原「1 费 / 1 战力 · `bf +1`（同区你的其他已翻开卡牌 +1）」的旧款式自此**只由 v183 的「莉莉霍瓦特」保留**（她未被改动，两者不再同款）。标签取自 `KIND_LABEL.shuffleIn`「揭示 · 洗入卡组（自己或对手的牌库，并重新洗牌）」，`kindTags` 与「衍生卡牌」面板（`tokenLinksForDef` 读 `shuffleIn.card`）都已接上。

**区域「出现时」效果（字段 `spawn`，入口 `runLocAppearEffect`）**：地形“出现”时给双方各生成卡牌，两种写法（v165 起）：① `{ card: SPECIAL 键名, n }` 生成**指定特殊卡**（虹龙洞→石块、幽灵洋馆→幽灵）；② `{ cost, n }` 从 **`POOL[cost]` 随机抽人物卡**生成（妖精神社→随机 1 费卡；**每张独立随机抽取**，双方可能拿到不同的卡；池内 `un` 与大体积 `occ>1` 卡排除）。两种都走 `placeToken`：**落地即翻开、占格位、进入场上放置顺序队列**并播“凝聚显形”演出。**是否触发揭示由 `spawn.reveal` 决定（v166）**：缺省 = 不触发（只吃持续 `og` / 时机 `fx` / 防摧毁 `surv` 等实时机制，同 v158「幽灵」口径）；`reveal: true` = 生成后**立即结算这些卡自身的「揭示」效果**（如妖精神社抽到「大妖精」当场给同区双方已翻开卡 +1）——结算顺序＝**落场顺序**（生成时先你方后敌方、同 n>1 按生成先后），按各卡**当前所在区域**结算，属**同步结算**（同 morph/fx 非翻牌路径口径，无 400ms 停顿与逐张翻牌演出，但 ±N 气泡/战力影响历史/日志照常）；摧毁型揭示（`dw`/`dwh`）开启该开关后会**在生成当刻当场生效**。触发时机三处：**①地形揭晓**（`locationRevealStage`）、**②区域被 `xform` 变成该地形**（v151）、**③开发者「🗻 指定地形」替换该列**（v150，可勾选关闭）。

**区域「翻开时」效果（v156，字段 `gamble`）**：与「出现时」（地形被揭晓/变形的那一刻，一次性）区分——这是**卡牌在地形里被翻开的那一刻**逐张触发的效果，引擎入口 `runLocRevealEffects`，由阶段 ④ `revealRound` 在每张暗牌 `revealed = true` 之后、该卡自身「揭示」结算**之前**调用。现仅驹草赌场 `gamble: 1`：该卡**永久随机 +1 或 −1 战力**（`Math.random() < 0.5` 各半），走 `applyPermBuff` 收口（±N 气泡演出 + 战力影响历史按来源记地形名），并记一条日志（赌涨绿色 `sys`、赌跌红色 `danger`）。口径：①只作用于“在本区被翻开”的卡——落地即翻开的落场 token（石块/厄运/分身）与已翻开后被移入本区的卡（`mv`/`fly`/`shift`/换边）不参与，地形出现前已在本区翻开的旧卡不追溯；②±N 先于自身揭示效果，故 `bl` 落后判定/`oc` 等按博彩后的威力算；③`morph`（变身重新触发新卡揭示）与 `fx` 时机效果不是“翻牌”，不经过本入口；④被摧毁回手后再打出（如妹红 `phx`）会**重新博彩**，永久 buff 可累积；⑤非“摧毁”，带 `surv`/`phx`/`prot` 的卡照常参与。

**区域「回合结束崩塌」效果（v163，字段 `collapse: { cards, to }`）**：每回合翻牌结算后，在**地形类回合结束效果的最后一步**（`locCollapseEffects`，早于场上 `fx.turnEnd` 卡牌效果）检查——若本区域**双方总卡牌数** ≥ `cards`（**按“张数”计**：大体积卡 `occ` 也算 1 张，暗牌与落场 token 都算；隙间不在 `zone` 数组里故不算），则把本区域地形**整体换成 `to` 指定的地形**：`state.locs[j].def` 换上新地形 → `refreshLocHeader` 刷新列名/图标/效果文案/配色 → **变形＝该地形在本区“出现”**（v151 口径：立刻结算目标地形的「出现时」效果 `runLocAppearEffect`，如冥界无 `spawn` 则空操作）→ 记一条红色日志。口径：①**已放卡不移动、不增删**（与地形揭晓/`xform` 一致）；②换掉之后本区不再带 `collapse` 字段，故**只会崩塌一次**（后续回合不再重复判定）；③防御：任一方占格数超过目标地形上限时不崩塌（并记日志）；④崩塌后的新地形从**下一回合**起按其规则参与（同一回合不再触发新地形的回合结束类效果）；⑤与「出现时」「区域变形」的区别：触发源是**本区卡牌数量**而不是地形被揭晓/被 `xform` 指定。

**区域「揭示后吹飞」效果（v162，字段 `gust`）**：与「翻开时」（`gamble`，在自身揭示**之前**）配对——入口 `runLocAfterRevealEffects`，同一张牌在阶段 ④ 里**自身揭示效果结算完之后**才结算：现仅魔力风暴 `gust: true`，把该牌「若可能」**移动到另外一个随机区域**（移动核心 `moveCardToRandomZone` 与 `roam` 效果键共用：目标区须已开放 `locOpen` 且该侧空余 ≥ 占格数 `occ`；两个都不可达则留在原地并记日志）。口径：①只作用于“**本回合在该区被翻开**”的卡（走 `revealRound` 的那些暗牌）——已翻开的旧卡、落地即翻开的落场 token（石块/厄运/分身等）、被移入本区的卡（`mv`/`fly`/`shift`/换边）都不受影响，地形出现前已在本区翻开的旧卡不追溯；②因为发生在自身揭示**之后**，本次揭示的结算结果不受影响（与 `gamble` 相反）；③若该卡自身的揭示效果已经把它挪出本区（如八云紫 `shift` 把卡搬到最右区），则**不再吹**；④换边类（`switch`/`gift`）换的仍是同一区域，故照常被吹到另一区（归属已变，按新归属方该侧空位判定）；⑤移动不改变归属/揭示状态/场上放置顺序队列，移动后各区域总点数与放满加成实时重算，并播放“滑行+缩放”飞行演出（`flushPendingDriftFly`）；⑥非“摧毁”，带 `surv`/`phx`/`prot` 的卡照常被吹。

**回合结束结算顺序（v153：先地形、后卡牌）**：每回合翻牌结算后，先执行 **⑤-0 区域（地形）回合结束效果**（`runLocTurnEndEffects`）——① 战力成长/衰减（`locTurnEndPowerEffects`：`grow` 成长 +N，如寺子屋；`decay` 衰减 −N，如间歇泉：本区双方所有已翻开卡牌永久 ±N）→ ② 定时掷骰（`locDiceEffects`：`dice: {turn,n}`，如骰子赌桌在指定回合末让本区**所有卡牌各自**随机永久 ±N）→ ③ 定时加成（`locRallyEffects`：`rally: {turn,add}`，如演唱会在第 5 回合末让本区**双方所有已翻开卡牌**永久 +add）→ ④ `purge` 回合末摧毁（`reactorPurge`，存在免摧毁 `prot` 时跳过）→ ⑤ 崩塌（`locCollapseEffects`：`collapse: {cards,to}`，如幽明结界在双方总卡牌数 ≥6 时把本区变成冥界）；**再执行 ⑤ 全场「回合结束」卡牌效果**（`runTurnEndEffects` → `resolveTimedEffects('turnEnd')`，按 `fieldQueue` 放置顺序）。因此地形总是先改动盘面：本区先被 ±N（或被摧毁），随后结算的 `fx.turnEnd` 卡读到的是**改动后的实时威力**（`cardPowerIn`）。同一块地形只带 `grow` / `decay` / `dice` / `rally` / `purge` / `collapse` 其中一个字段（`grow` 与 `decay` 同带则相互抵消），各类效果不共存；**崩塌放在地形类效果的最后一步**——本回合先按原地形结算，崩塌后的新地形从**下一回合**起按其规则参与。第 6 回合同样先跑 ⑤-0 / ⑤ / ⑥，再进入 ⑦ 游戏结束效果与终局结算（成长/衰减/掷骰结果计入终局点数）。

**地形揭晓系统（v74，开局流程；代码入口 `locationRevealStage`）**：开局按 `pick` 权重抽定三块真实地形（互不相同）预存于 `state.locPlan`，场上三列先一律以「未揭示」占位地形（`EXTRA.unreveal`，id `unreveal`：max 4 / 无效果 / 样式同无名之丘）展示；第 **t 回合开始时揭晓第 t 列**（t=1/2/3 → 左/中/右）：①换上真实地形（max/加成/反转/purge/grow/decay/gamble/dice/rally/gust/collapse/prot/minTurn 等字段与列头配色即时生效）；②结算该地形「出现时」生成（`spawn`：如虹龙洞给双方石块、妖精神社给双方各 1 张随机 1 费人物卡）；③此前已放卡**不移动、不增删**。未揭示列可正常放牌（上限 4；列下提示「🃏 第 N 回合揭晓」）。**限张超限口径**：若揭晓成上限 <4 的地形（迷途竹林 max 2）而某侧已放超过上限（仅第三列可能：前两回合每侧至多放 3 张），不摧毁不移走、卡保留原格位——隙间只铺在“空置的不可用格位”，数量 = 4 − max(已放数, 上限)（放 3 张 → 1；放满 4 张或大体积卡占满 → 0；见 `buildZoneChildren` 渲染规则），此后该侧按已满处理。**换场演出（v98→v99）**：揭晓时把“未揭示”外观整列克隆到悬浮层并 **500ms** 淡出（`revealLocFade`，v99 由 700ms 调短），下方真实地形随之显形。

**换边演出（v96）**：`switch`（依神紫苑）与 `gift`（因幡帝送己方最低卡）换边时，与移动同款播放“滑行 + 缩放”克隆飞行（`flyCardTo`，通过 `pendingSwitchFly`/`flushPendingSwitchFly` 在换边后的渲染时触发，约 0.26s）。

**卡级“每回合移动一次”（`fly: true`，现仅射命丸文）**：该牌**已翻开且仍在己方场上**时，每个出牌阶段可把它移到另一区域一次——点该卡进入"选择目标区域"，再点目标列移动；目标必须未满且已开放（不点不放能量）；每回合一次（`flyMoved` 记录），下回合重置；**v173 起 AI 也会使用该能力**（困难 / 噩梦档：移动走同一套估值，只有确实能改善局面才走一步并播同款飞行演出；普通档仍不使用）。**演出（v89）**：移动时播放与八云紫 `shift` 同款的“滑行 + 缩放”飞行克隆动画（`flyCardTo`）。

## 4. 绝对不可操作卡（`un: true`，目前仅隙间）

- 无能量（c=0）、无战力（p=0），**不可移动、不可被摧毁、不可被任何效果修改**；
- 引擎防护点：区域加成 `aff/cb/all` 对它为 0；`bf/de/ba` 不会给它加/减 buff；`dw` 不可选为目标；`purge`（反应炉）不会波及它；
- 界面层它只是灰色静态格位（≋ 隙间），本就不会进 zone 数组——`un` 是数据级的保险。

## 5. 数值与比较口径（读卡力/总点数都走这里）

- `cardPower` = 基础威力 + 永久增益（buff）
- `cardPowerIn` = cardPower + 阵营加成(aff) + 费用加成(cb) + 全区修正(all)；**un 卡恒等于自身**
- `zoneTotals` = 已翻开卡的 cardPowerIn 之和 + 放满加成(fill)
- `zoneEff` = zoneTotals × dbl，`inv` 反转取负 —— 胜负/领先/总点数决胜统一用该口径
- 区域效果按类型区分口径：**倍率 / 终局类**（`dbl` 等）只乘进**结算用的总战力**、**不改卡牌自身数字**；**阵营 / 费用 / 全区加成型**（`aff`/`cb`/`all`）则算作卡牌的**实时威力**，会显示在卡面右上角与“战力影响历史”里
- 暗牌口径：暗牌不显示不计入总点数（翻面后计入）；揭示增减（bf/de/ba）与 dw 只作用于结算时已翻开的卡牌；**AI 估值的信息口径分档（v173）**：普通 / 困难档只按**已翻开**的牌估值（**不看你的暗牌**，对暗牌取乐观口径），噩梦档才 `includeHidden` 全量可见（能读到暗牌战力）
- **法术（v170）**：`cardPower` 与 `cardPowerIn` 对 `spell: true` 的卡**恒为 0**（不吃基础战力以外的任何加成，也不吃增减）；它占格按 1 计（`occOf` 归一），因此**影响 `sideRoom`／放满加成 `fill` 的判定**，但不给本区总点数贡献任何点数
