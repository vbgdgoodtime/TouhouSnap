# 现有机制（引擎总表）

> 本文件是**引擎机制的权威口径**：流程管线与阶段挂点、卡牌效果键、卡级机制、区域字段总表与各机制口径、数值口径、其它已实装系统。
> 地形 / 人物卡 / 特殊卡各自的清单见同目录 `现有地形.md` / `现有人物卡牌.md` / `现有特殊卡牌.md`；
> **动画、演出与节奏间隔**（演出形态、时长常量、各种停顿与间隔、悬浮层与 z-index）统一写在同目录 `动画演出与间隔.md`——
> 本文档只留**演出名**（如「凝聚显形」「分崩离析」）与“分步版 / 同步版”的区别，不写时长与样式细节；
> 一局结构、牌库与抽牌、胜负与赌注见 `docs/GAME_REFERENCE.md`；历史变更记录见 `docs/历史版本.md`（该文件暂时停用、不再追加）。

## 1. 卡牌效果键（`k`，全部为「揭示」On-Reveal：翻面时结算一次、永久生效）

| 键 | 名称 | 说明 |
| --- | --- | --- |
| `''` | 白板 | 无效果 |
| `bf` | 同区友军增益 | 同区域你的其他已翻开卡牌（不含自己）威力 +N |
| `de` | 同区敌方削弱 | 同区域对方所有已翻开卡牌威力 −N。⚠️ 目标在带 `noDown` 的区域（蓬莱药局）→ 该次 −N 被拦下、战力不变，日志写“另有 N 张因本区「免减攻」被拦下” |
| `ba` | 双方同增 | 同区域双方所有已翻开卡牌威力 +N |
| `bl` | 落后自增 | 本区按获胜口径落后时自身 +N（反转区域按“真实点数更高＝落后”）；也作时机效果，由「蕾米莉亚·斯卡蕾特」以 `fx.turnEnd` 每回合末判定（落后即永久 +N、可累积） |
| `dw` | 摧毁 | 摧毁同区对方已翻开且威力最低的一张（暗牌与 `un` 占位卡不可选为目标；带 `ind` 的卡照常参与判定，判定落在它身上＝摧毁失败、本次判定结束、不改打其他牌） |
| `spawn` | 添加石块 | 揭示：向本区域双方各添加 1 张特殊卡（`def.spawn` 指定，当前为石块；放满则不放） |
| `spawnO` | 敌方侧生成 | 揭示：向本区域对方一侧添加 1 张特殊卡（`def.spawnO` 指定，当前为厄运；对方该区放满则不放） |
| `clone` | 另两区生成分身 | 揭示：向另外两个区域（不含本区）自己一侧各添加 n 张特殊卡（`def.clone` 指定，当前为赫卡提亚的分身；该侧放满/未开放的区域跳过） |
| `delCopy` | 摧毁己方一张并复制到另两区 | 揭示：在本区域自己一侧**已翻开**的卡里（候选＝不含自己 / 法术 / `un` 占位卡，含落场 token；暗牌不算）**随机摧毁一张**，只有它**真的被摧毁离场**时，才把它的**复制体**分别放到另外两个区域自己一侧各 1 张（该区未开放 `locOpen` 或该侧空余 `<` 占格数 `occ` ⇒ 跳过该区、不补别区）。⚠️ **摧毁失败就不生成复制体**：本区免摧毁（`locNoDestroy`：地形 `prot`／蕾蒂）⇒ 整条失效、不选目标；目标带 `ind`（判定落在它身上＝摧毁失败、判定结束）/ `phx`（回手并翻倍）/ `surv`（不离场、改永久 −N）⇒ 按各自机制结算且都不算被摧毁。真被摧毁 ⇒ `recordDestroy` 进归属方摧毁池（照常喂纯狐 `costDown`）＋播「分崩离析」。复制体＝被摧毁那张牌的**完整副本**：同一个 `def`（含 `og`/`fx`/`surv`/`phx`/`ind`/`occ` 等卡级机制）＋实例级状态照抄（永久修正 `buff` 与台账 `powerLog`、卡级封印 `muteP`、费用修正 `costMod`）——与 `clone`（白板 token、只快照战力）刻意不同；落地即翻开、占格位、进放置队列（`fieldTurn`＝本回合 ⇒ 其「回合开始」时机效果当回合不结算）、播「凝聚显形」并**立即结算它自身的揭示**（走 `resolveRevealInZone` ⇒ 目标区是守矢神社时**照常结算两次**——⚠️ 这是与落场 token / `reviveDiscard` 复活牌这两类“落地即翻开”的刻意差别：那两类走同步 `applyEffect`、**不**加倍；白板复制体没有揭示可结算，照跳）；不经 `revealRound` ⇒ 不参与 `gamble`/`gust`。现仅 6 费 / 0 战力「绵月丰姬」使用 |
| `switch` | 换边 | 揭示：翻开后从自己一侧转到对方该区域一侧（如依神紫苑 −7 战力上对方侧；对方该区放满则失败、留在原地） |
| `morph` | 变身 | 揭示：把自己变成对方手牌中随机一张卡的复制体（原卡留在对方手牌；变身后按新卡的 `k` 再结算一次其揭示文本；对方手牌为空则不变） |
| `gift` | 送己方最低卡 | 揭示：把本区域己方战力最低的已翻开卡（不含自己；并列最低随机选一）换边到对方该区域一侧（对方该区放满则失败） |
| `xform` | 区域变形 | 揭示：把本区域整体替换为目标地形（`def.xf` 指向地形 id，如鬼人正邪→`needle` 辉针城）；变形＝该地形在本区“出现”，立即结算其「出现时」效果（如变成虹龙洞 → 双方各 1 张石块）。⚠️ 任一方占格数 > 目标地形 `max` 时变形失败（只记日志、什么都不变），故目标 `max: 4` 的地形实际不会失败。使用者五位：鬼人正邪（6 费，→辉针城）、灵乌路空（3 费，→聚变反应炉）、「天文密葬法」（3 费法术，→虚假之月）＝`extraRound` 延长回合唯一的“变出”手段、「星之仪式」（4 费法术，→守矢神社）＝`repeatReveal` 地形唯一的“主动变出”手段、「法界之火」（3 费法术，→法界）＝`noReveal` 封锁揭示唯一的“主动变出”手段 |
| `xformR` | 区域随机变形 | 揭示：把本区域地形整体换成地形池里随机另一个地形，并立刻结算目标地形的「出现时」效果（现仅 1 费「梅莉」使用）。候选＝`LOCATION_POOL` 里除本列当前地形以外的全部地形（可与另外两列当前地形重复；`EXTRA`「未揭示」/「已破碎」不入候选）。不做上限防御：抽中“上限放不下本区已放卡”的地形（如迷途竹林 `max:2` 而某侧已放 3 张）照常变形，已放卡不移动、不增删、不摧毁，隙间只铺在空置的不可用格（与 `xform` 超限则变形失败刻意相反）。换地形 → `resetLocGaps` 清隙间 → `refreshLocHeader` 刷列头 → `runLocAppearEffect` 结算「出现时」效果（无 `spawn` 则空操作）→ `syncRoundTotal`；落地即全量生效，含同一回合末的 `grow`/`decay`/`dice`/`rally`/`purge`/`collapse`/`gap`。可能变出特殊地形：「虚假之月」→ 本局总回合数当场变 7（已进入第 7 回合则锁定为 7）；「天界」→ 照常启动 `shatter` 摧毁链（`revealRound` 在本张牌结算后 `await awaitShatterChain()` 补等，不抢时序）。已破碎的列一律跳过（同 `xform`/`xformTurn`/`collapse`/开发者「指定地形」四路）。非摧毁/非增减/非放置：本键不改战力与格位、不触发 `surv`/`phx`/`prot`/`ind`、不进 `powerLog`/`fieldQueue`；落在带 `mute` 的区域（「静海」）或自身已被封印时，被 `applyEffect` 入口守卫拦下（不变形、只记一条日志）。可换掉“尚未揭晓”的列：候选只看“除当前地形以外”，而「未揭示」是 `EXTRA` 占位地形、不在 `POOL` 里 ⇒ 候选仍是全部真实地形；把梅莉打到尚未揭晓的列（第 1/2/3 回合揭晓之前）并翻开时，她当场把该列变成随机真实地形，而 `locationRevealStage` 以 `loc.def.id === 'unreveal'` 判断“还没揭晓” ⇒ 该列原定的揭晓此后整段跳过（`locPlan` 预存的地形不再出现、也不播换场演出）。⚠️ 在「守矢神社」里翻开会被执行两次（资格＝翻开那一刻的快照）⇒ 一次揭示连换两次地形；被「东风谷早苗」`retrigger` 再触发时同理。无需附加字段（候选口径写死在共用收口 `randomLocCandidates`，与 `xformTurn` 共用）。不复用 `xform`+`xf:'random'`：`def.xf` 是地形 id 字段（`js/ai.js` 的 `case 'xform'` 拿它查表投影），`xf` 永远只放真实地形 id。触发时机：翻牌揭示结算（阶段 ④ `revealRound`）逐张触发，与 `xform` 同一时点（`gamble` 之后、法术消散与 `gust` 之前）。代码入口：`applyEffect` 的 `case 'xformR'` / `revealEffectWillChange` 的 `xformR` 分支 / `randomLocCandidates` |
| `mv` | 移走 | 揭示：把本区对方已翻开且实时战力最低的卡移到另外两区随机一处（对方该区满员/未开放的地形排除；都不可达则失败） |
| `give` | 加入手牌 | 揭示：把指定特殊卡（手牌衍生物，如废弃列车）加入自己手牌（7 张满则失败；由「雾雨魔理沙」使用 → 法术「极限火花」）。`pool` 写法 `give: { pool: [SPECIAL 键名…], n }`：从池里不放回随机抽 n 张（互不相同）加入手牌，其余口径同单卡写法（新卡实例、`justHandAdded` 滑入、满手则失败/只加入放得下的、归属按所属方）；池内缺失条目静默忽略、池空则只记日志。现由「蓬莱山辉夜」使用 → 从 5 张神宝里随机抽 2 张（详见 §3「神宝」） |
| `shuffleIn` | 洗入卡组 | 揭示：把 `def.shuffleIn = { card: 键名, n: 张数, to: 'own' \| 'opp' }` 指定的牌 n 张（各自新卡实例）洗入某一方牌库，随后该方整副牌库重新随机洗一次。`card` 先查 `SPECIAL` 键名、查不到再按卡名查 `POOL`；`n` 缺省 1、张数无上限（牌库没有 7 张上限，「手牌满则失败」不适用）；`to` 缺省 `'own'`＝自己牌库，`'opp'`（也接受 `'a'`）＝对方牌库（归属按牌的所属方）。不结算被洗入卡的任何效果（进隐藏区牌库：不翻开、不占格位、不进 `fieldQueue`、不触发揭示/`og`/`fx`/`surv`；日后抽到再打出时按常规流程结算）；日志公开点名 + 轻量演出（形态与锚点见《动画演出与间隔.md》§3「洗入卡组」）。现由「琪露诺」使用 → 向对手牌库洗入 1 张「冰块」。详见下文「洗入卡组（`shuffleIn`）」段 |
| `discard` | 弃牌 | 揭示：把 `def.discard = { n, to, pick, card, cost }` 指定的牌从手牌移出，放进该牌归属方的弃牌池（`discardPile`：先进先出、入池的是牌本体）。⚠️ 与「摧毁」分工：摧毁只作用于场上、弃牌只作用于手牌，两者互不重叠——弃牌不是“摧毁”：不触发 `surv`/`phx`/`prot`/`ind`、不进 `powerLog`、不改战力、不动区域字段与格位。`to` 缺省 `'own'`＝弃自己手牌，`'opp'`（也接受 `'a'`/`'enemy'`）＝弃对方手牌（归属按牌的所属方，对双方一视同仁）；`card` 按卡名（或 SPECIAL 键名）筛选、`cost` 按印刷费用 `def.c` 筛选（数字＝恰好 / `{min,max}` 区间含端点），两者都不写＝该方整副手牌都是候选；`n` 缺省 1、`'all'`＝命中多少弃多少，候选不足则弃掉手上有的那些、一张都没有则无事发生。`pick`＝`'random'`（缺省）候选里随机 / `'right'` 最右侧起 / `'left'` 最左侧起 / `'maxCost'`＝取印刷费用 `def.c` 最高的那些、并列最高时在其中随机弃一张（同 `dw`/`dwh`/`dwb` 的“并列里随机挑一张”，比的是印刷费用而非 `cardCost`）（候选保持手牌顺序，位置＝玩家看到的手牌左右位置；可与 `card`/`cost` 筛选叠加；`n:'all'` 时位置无意义）。现由「莉莉黑」（1 费 / 3 战力）使用 → 丢弃自己最右侧 1 张手牌；「小野塚小町」（3 费 / 5 战力）使用 → 丢弃自己手牌中印刷费用最高的一张。`give` 可选子句：弃牌真的发生之后，每弃掉 1 张就给施放方自己加入 `give.n`（缺省 1）张 `give.card`（SPECIAL 键名）的新卡实例到手牌（手牌衍生物口径：`justHandAdded` 滑入、手牌上限 7 张照常约束、仍需手动暗出）；`powerFromCost: true` ⇒ 衍生物战力＝那一张被弃牌的印刷费用 `def.c`（不是 `cardCost`，差额走 `applyPermBuff` 记在该实例上），现由「姬虫百百世」（2 费 / 2 战力）使用 → 随机弃自己 1 张手牌，并加入 1 张战力＝该卡费用的「石块」。公开：日志点名被弃的牌 + 双方可见的弹出被弃牌完整卡面与斜切两半演出（任一归属组合都一样；形态与间隔见《动画演出与间隔.md》§3「弃牌」）。详见下文「弃牌（`discard`）」段 |

**费用修正（加费 `costUp`／桑尼米尔克；减费来源 `costDown`／纯狐、`costDownP`／星熊勇仪）**：卡牌实例可带本场战斗内的费用修正，引擎统一收口 `cardCost(card) = max(0, def.c + (card.costMod || 0) − (def.costDown || 0) × 双方摧毁池合计张数 − (def.costDownP ? def.costDownP.n × 己方场上已翻开且实时战力 ≥ min 的卡数 : 0))`（`max(0, …)` 下限只对这两类减费卡生效）：
- 实例级：修正写在 `card.costMod` 上（配套 `card.costLog` 记账 `{ inst, d, src, tag }`，思路同战力台账 `powerLog`），只影响这一份卡——牌库/手牌/场上的同名卡互不影响；卡从手牌打出、被移动、被换边、凤凰重生回手都带着这份修正走。
- 仅本场战斗有效：不写回 `def`（`data/cards.js` 不动），也不入 localStorage/卡组存档；那一份卡被摧毁 / 终局离场 / 本局结束即随之消失，新开一局卡实例重建，修正归零。
- 只有“实际付出/消耗的能量”按修正值算：出牌扣能量（`tryPlayAt`）、能否负担（`canPlaceP` / 手牌置灰 / `selectHand`）、撤回暗牌的返还、AI 选牌与扣能量（`ai.js`）全部走 `cardCost`。
- 印刷费用（`def.c`）不变：卡组曲线与卡组页排序、区域 `cb` 费用加成（如雾之湖「1 费卡 +2」）、图鉴 / 开发者「指定卡牌」的筛选与文案仍按 `def.c` 判定。
- 上限 6 费：只允许把卡涨到 `cardCost ≤ 6`（6 费卡不可再涨，`costUp` 的候选池排除它们）；牌局能量上限也是 6，涨到 7 费等于永久不可打出，故设此上限。⚠️ `gs.energyAdd`（哆来咪）会把本局能量上限提到 7（第 6 回合），但该费用上限仍保持 6 不变——因此 ≥6 费的牌（含 7 费的哆来咪、8 费的纯狐）都不可再被加费，加费实际只对 ≤5 费的牌有效。
- 减费来源（`costDown`）：与加费对称但不写实例字段——`def.costDown` 是卡级持续机制，减费额＝`costDown × 双方摧毁池张数`（实时动态值，不落 `card.costMod`、也不进 `costLog`，故没有“费用 ±N”演出）；下限硬性为 0 费（`Math.max(0, …)`）。现仅 8 费「纯狐」（`costDown: 1`）使用；另一条同族减费来源 `costDownP: { min, n }`（现仅 6 费「星熊勇仪」）＝`n × fieldPowerCount(card.side, min)`，数的是**此牌归属方自己三个区域里已翻开、`cardPowerIn ≥ min` 的卡**（区域加成 / 持续 `og` / 永久增益都算；暗牌、法术与 `un` 占位卡不算），同样实时、同样不写实例字段、同样下限 0 费。
- 界面口径：费用数字按 `cardCost` 显示，高于印刷费用=红色、低于=绿色（同战力数字语义；缩略卡 `.mc-cost` 与卡面费用宝珠 `.cost-orb` 各自独立着色，与战力色互不干扰）；放大/详情弹窗补一行「印刷费用 N · 本场战斗费用修正 +N（仅此一份卡有效）」，`costDown` 卡另加一行「费用随摧毁递减（每张 −N）：本场战斗中双方已有 X 张牌被摧毁 → 能量消耗 −Y（已减到最低 0 费）」（`costDownNote()`），`costDownP` 卡另加一行「费用随场上高战力卡递减（每张 −n）：你的场上已有 X 张已翻开、战力 ≥ min 的卡牌 → 能量消耗 −Y」（`costDownPNote(card)`）。改费演出（中央卡面揭示 `spawnCostReveal`，横幅只写费用变化 `费用 旧值(划掉) → 新值`，涨红/降绿）见《动画演出与间隔.md》§3「改费卡面揭示」；同一批同卡的费用变化合并成一次演出（`flushCostFlash` 内按卡合并 `d`）。⚠️ `costDown` / `costDownP` 的减费**都不触发**这套演出（它们没有“改费那一刻”的结算点，手牌角标在下一次 `renderHand` 时自然变绿）。
- 遮蔽口径：被加费的目标对玩家公开（日志点名 + 气泡 + 此后「查看」里那张牌显示红色费用）；AI 侧不额外提示，但它的 `aiThink` 会按 `cardCost` 判定可负担，故加费实际会影响它下回合的出牌选择。

**牌库费用战力互换（`swapDeck`／稀神探女）**：`k: 'swapDeck'`（**无附加字段**）——揭示把**施放方自己牌库剩下的牌**的「实际费用」与「实时战力」互换。这是唯一一条同时动到**费用**与**战力**两个收口的机制：
- **基准＝当前生效值**：费用读 `cardCost(card)`（含 `costUp` 加费与 `costDown` 减费）、战力读 `cardPower(card)`（`def.p` + 永久 `buff`）⇒ 一张已被加过费、或带着永久增益的牌会把那份修正一起卷进交换。
- **落点＝实例级**：费用走 `applyCostMod(card, d, src, tag, silent)` 写 `card.costMod` + `costLog`（`silent` ＝只改值 + 记账、**不排**「费用 ±N」演出，因为整副牌库逐张弹中央卡面会拖垮节奏），战力走 `applyPermBuff` 写 `card.buff` + `powerLog`（来源记本卡）。两者都**只影响这一份卡实例、仅本场战斗有效**：不动 `def`、不入卡组存档，随实例走出牌 / 回手 / 复活 / 换边。
- **边界**：新费用 = `clamp(当前战力, 0, 6)`（上限 6 与 `costUp` 同款）、新战力 = **当前费用本身、不夹上限**（8 费的纯狐会换出 8 战力）。⚠️ 下限 0 也由本键自己夹：`cardCost` 只在 `costDown` 分支里 `Math.max(0, …)`，负费用会让出牌**反而回能量**，故负战力卡换出的负费用必须夹成 0。实例：纯狐 8 费/16 战力 → 6 费/8 战力、哆来咪 7 费/8 战力 → 6 费/7 战力、依神紫苑 5 费/−7 → 0 费/5 战力、冰块 1 费/0 → 0 费/1 战力、幽灵 0 费/1 → 1 费/0 战力。
- **参与范围＝牌库里的全部牌**：法术、落场 token、0 费卡、负战力卡都参与。法术照常参与但战力恒 0（`cardPower` / `applyPermBuff` 对 `spell` 直接归零）⇒ 它只换到 0 费、拿不到那几点战力。
- **快照、归属与档位**：只作用于**结算那一刻**已在牌库里的牌（此后经 `shuffleIn` / 哆来咪 `gs` 洗入的牌不参与）；作用于**施放方**的牌库（玩家打出＝自己的、AI 打出＝AI 自己的，对双方一视同仁）；**不改印刷档位**——`cb`（雾之湖）、`og.cost`（克劳恩皮丝）、`spawn.cost`（妖精神社）、`discard.cost`、图鉴与卡组页排序仍按 `def.c`。
- **反复触发是有损的**：以**当前值**为基准再换一次（「东风谷早苗」`retrigger`、「守矢神社」`repeatReveal`）——只有两值原本都落在 0~6 且非负时才会换回原样；被夹取过的（纯狐 ①6/8 → ②6/6、依神紫苑 ①0/5 → ②5/0）**不复原**。纯狐的 `costDown` 交换后**继续叠加**（写下的 6 费会随双方摧毁数继续往下减）。
- **不触发**：`surv`/`phx`/`prot`/`ind`、摧毁判定、格位与 `fieldQueue`、区域字段——非摧毁 / 非放置；也不写 `playerMoves`/`aiMoves`。
- **界面**：费用数字按新 `cardCost` 着色（高于印刷＝红、低于＝绿，同 `costUp` 语义）；战力走永久 `buff` ⇒ 卡牌「战力影响历史」多一条来源「稀神探女」的记录；日志只写**张数**（不列牌名，避免公开对手牌库内容）；演出 `playDeckSwapFx` ＝牌库计数闪光 + 星光迸发 + 「⇄ 交换 ×N」气泡，锚点与跳过条件同「洗入卡组」（玩家侧 `#deckCountVal`、对手侧侧栏对手信息区，取不到则静默跳过、只留日志），见《动画演出与间隔.md》§3「洗入卡组」。
- **预判**：`revealEffectWillChange` 的 `swapDeck` 分支＝牌库非空即为 `true`（照常走 400ms 停顿与结算后重渲染）。

**额外能量（现仅 `energyNext`／斯塔萨菲雅）**：揭示让自己一方在下个回合多拿 N 点能量，引擎用登记式收口：
- 登记：`addPendingTurnEnergy(side, n)` → `state.pendingEnergyGain[side] += n`；可叠加（同回合两张斯塔萨菲雅＝下回合 +2），跨回合不会提前生效。
- 结算点：下一个回合开始时的 ①-2 能量结算（`roundStartStage` → `grantTurnEnergy(base)`）——`energyTotal = 基数 + 登记值`、`energyLeft` 同值，并把本次生效的额外值写进 `players[side].energyGain`，登记值随即清零（一次性，不是每回合都给，与 `grow` 那类“每回合末都触发”的机制区分）。
- 归属：按牌的所属方（`side`）——玩家打出给自己、AI 打出给自己；开发调试「⇄ 切换立场」把牌落到敌方一侧时该牌归属对手，故加的是对手的能量。对双方一视同仁。
- 时序：揭示发生在阶段 ④，此时本回合能量早已结算完，因此不会对当前回合生效，只影响下一回合；区域字段、格位、`surv`/`phx`/`prot`/摧毁类机制都与本效果无关（非“摧毁”、非放置）。
- 终局边界：最后一回合翻开时不存在“下一回合”（判据读 `roundsTotal()`——无虚假之月为第 6 回合、有则为第 7 回合；有虚假之月的局里，第 6 回合翻开的这份会在第 7 回合正常到账），这份额外能量本局不会生效（仍会登记与记日志，日志会明确提示）；本局结束后登记随 `restart` 清空。
- 界面：顶栏能量框在额外能量生效的那一回合显示绿色角标「+N」（`#energyBonus`，`players.p.energyGain` 驱动，回合结束随下次结算归零）；日志记「你本回合获得额外能量 +N（能量上限 X；一次性，仅本回合有效）」。
- 演出（两段：揭示当刻的登记段 / 下回合能量结算时的到账段，形态与锚点见《动画演出与间隔.md》§3「额外能量」）：卡位或能量框取不到（尺寸为 0）时跳过该段，末回合登记时会跳过登记段（不会生效）。

**游戏开始时（`gs`；现仅 7 费「哆来咪」使用，`gs: { shuffleN: 10, energyAdd: 1 }`）**：卡级机制（不是揭示键，`k` 仍为 `''`），在阶段 ⓪ `runGameStartEffects()` 结算——`restart` 完成建库 / 抽选三块真实地形 / 生成区域后、第 1 回合开始前执行，`clearLog` 与开局那条「新对局开始」日志之后、`renderAll` 与 `playOpening`（玩家初始 3 张逐张发放）之前。
- 触发条件与持续性：只要开局时这张牌在自己一方的牌库/起手中（＝它被放进了那 12 张卡组）就触发，且整局永久生效——之后它被抽到手、被打出、被摧毁、凤凰重生回手都不回收已洗入的 10 张牌与已加的能量；开局时它不在牌库（开发调试的空牌库、或没把它编进卡组）则什么都不发生。判定按 `牌库 ∪ 起手 ∪ 场上`，归属按牌的所属方（对双方一视同仁）。⚠️ **⓪ 必须跑在双方初始 3 张发放之前**：那时两副牌库都还是完整的 12 张；`gs.shuffleN` 的重洗消耗的随机数个数 = 牌库张数 − 1，先抽掉某一方的 3 张会让重洗吃掉的随机数个数变少、洗出另一副顺序（联机两端座位互为镜像，见 `docs/联机对战.md` §5）。每张带 `gs` 的卡各结算一次（正常只能带 1 张，多张则效果叠加）。
- `gs.shuffleN: N`：从普通卡牌池 `POOL` 里不放回随机抽 N 张互不相同的牌 def，各自以新卡实例（`newCard`）洗入自己一方的牌库，随后整副牌库重新随机洗一次（复用 `shuffleCardsIntoDeck` 收口）。只取 1 费及以上（`POOL[0]` 当前是空桶；7 费「哆来咪」自己因带 `gs` 被排除，故不会洗出第二张哆来咪；8 费「纯狐」可以被洗入）；完全不碰衍生卡池 `SPECIAL`（法术 token：火神之光 / 祖母绿巨石 / 绿色风暴 / 水银之毒 / 金属疲劳 / 极限火花 / 耀眼之龙玉 / 蓬莱的玉枝；普通 token：石块 / 厄运 / 河童 / 幽灵 / 水银 / 祖母绿巨石占位 / 无限生命泉 / 火蜥蜴之盾 / 佛体金刚石 / 龙玉 / 冰块 / 隙间）；包含 `POOL` 里的全部法术（镇守大地之石 / 阴阳玉 / 三妖精集结 / 地精的起床 / 妖精大战争 / 天文密葬法 / 生神停止 / 法界之火 / 星之仪式）与全部 1 费及以上的人物卡（含大体积 `occ:4` 的伊吹萃香，8 费组也参与）；排除 `un` 占位卡与带 `gs` 的卡自己（`randomPoolCards` 里 `if (!d || d.un || d.gs) continue;`），抽出的牌允许与你卡组里已有的同名卡重复（只从卡池抽，不查卡组构成）；张数无上限（牌库没有 7 张上限，「手牌满则失败」不适用），进的是隐藏区牌库——不翻开、不占格位、不进 `fieldQueue`、不结算被洗入卡的任何效果，日后抽到手再打出时按常规流程走（与 `shuffleIn` 同口径）；池子不足 N 张时取手上有的那些（实际 1 费及以上共 60 张，正常足够）。
- `gs.energyAdd: N`：登记进 `state.energyAddPerTurn[side]`，在每次回合开始的能量结算（①-2 `grantTurnEnergy`）里并入基数：第 t 回合 = `min(t, 6) + N`（开发调试 = 10 + N）。与斯塔萨菲雅的 `energyNext`（`pendingEnergyGain`，下回合一次性 +N）叠加（7 + 1 = 8），但它是本局永久、不像 `energyNext` 那样结算后清零；`restart` 时随 `state.energyAddPerTurn` 重置。
- 与「能量上限 6」的关系：普通局基数上限是 6，单靠基数打不出 7 费牌；哆来咪自己的 `energyAdd: 1` 让本局第 6 回合达到 7 点，因此它只有在第 6 回合才打得出来（第 1~5 回合它在手牌里是置灰的）。⚠️ 「每张卡最多涨到 6 费」的 `costUp` 上限不受此影响，仍以防“涨费后永远打不出”为准。
- 交互与收口：`gs` 不经过翻牌流程——不是 `k`（揭示键），`applyEffect` 不处理它、`revealEffectWillChange` 无需分支；不进 `powerLog`、不触发 `surv`/`phx`/`prot`/`ind`，也不动区域字段与格位口径。结算函数：`runGameStartEffects()` → `applyGameStartEffect(side, card, gs)`（日志两条：`💤 …洗入 N 张，牌库 12 → 22 张…` 与 `🔋 …本局每回合最大能量 +N…`），随机候选取自 `randomPoolCards(n)`。
- 界面与分档联动：玩家牌库计数「牌库 N」（`#deckCountVal`）开局渲染即显示 22；顶栏能量框的 `/ 总数` 随之显示 2 / 3 / 4 / 5 / 6 / 7（手牌上方那排能量条按“当前可用能量”逐条画，7 点画 7 条、不补灰色占位；开发调试的 10 点同款）；放大 / 详情弹窗的 `kindTags` 会标一行「游戏开始时 · 在卡组中即触发（洗入 10 张随机牌、每回合最大能量 +1）」；卡池有 `7` 费档，故遍历卡池处动态取费用档键（`game.js` 的 `POOL_COST_KEYS`，供 `findCardDefByKey` / `gatherMembers`；`buildDeckCards` 按曲线用到的档位建桶）、`card-browser.js` 与 `deck-page.js` 的 `allPoolDefs()`，图鉴 /「指定卡牌」/ 卡组设置页的费用筛选档为「6 费+」（＝按 `def.c >= 6` 过滤；档内顺序仍由 `orderDefs` 决定＝费用↑ → 战力↑ → 卡名字典序）；玩家兜底曲线 `DECK_CURVE` 与对手曲线 `AI_DECK_CURVE` 都不含 7 费，故哆来咪只能由自建卡组带入（AI 抽不到、也不受本机制影响）；卡面底色统一走 `gradOf(def)` → CSS 变量 `--cgrad`（`GRADS[费用档]`，或该卡自定义的 `cg`）——`game.js` 的 `GRADS` 含 `7` 档（深紫罗兰 `#3a2565 → #c9a6ff`），取不到色值时退到 `BACK_GRAD` 深蓝灰；日后新增任何费用档都要照此补一条 `GRADS[档位]`。
- 开局「登场」演出（`gs` 卡专用）：`restart` 的 ⓪ 阶段若真的触发了带 `gs` 的卡，就在洗完 10 张随机牌 + 登记每回合能量 +1 之后、玩家起手 3 张发放之前播放一段「凸现」演出；**演完才开始逐张抽初始 3 张**，因此开局洗入的牌从抽牌那一刻起才可能被抽到。触发源＝`runGameStartEffects()` 的返回值（本次真正结算的 `{ side, card, gs }` 列表），没触发时直接 resolve、不额外等待；形态、样式类名与关键帧、响应式收放、跳过条件见《动画演出与间隔.md》§5「开局「登场」演出」。

**时机效果（`fx`，非揭示）**：`fx: { turnStart, turnEnd, gameEnd }`，条目与揭示规格同构（`k`/`a`/`spawn`/`xf`/`give`/`t`，复用 `applyEffect`；`drawSpell` 另用 `n`/`pool`）。时点：回合开始＝每回合最先、先于能量/抽牌；回合结束＝翻牌结算后、地形类回合末效果（`decay`/`purge`）之后；游戏结束＝最后一回合（无虚假之月第 6 回合、有则第 7 回合）全部阶段后、结算胜负前。遍历按场上放置顺序队列 `state.fieldQueue`；手牌打出/落场特殊卡入队，被摧毁、重置撤回手牌的出队（不再触发后续时机）；移动（`mv`/`fly`/`roam`）不变序。已注册 `fx.turnStart` 两张：幽灵（`{ k: 'roam' }`：每回合开始若可能就随机飘到另一区域）、帕秋莉·诺蕾姬（`{ k: 'drawSpell', n: 1, pool: [...] }`：每回合开始抽 1 张法术入手，见下文）；`fx.turnEnd` 三张：蕾米莉亚·斯卡蕾特（`{ k: 'bl', a: 3 }`：每回合结束若其所在区域落后就永久 +3 战力，判定走 `zoneEff` 本区比较口径（含 `dbl`、反转区按负值），每回合末各判一次、可累积，第 6 回合末同样结算并计入终局；结算点在地形类回合末效果之后，读到的是已被地形改动的实时威力；不受「刚登场跳过当回合」限制，翻开当回合末即判一次）、无限生命泉（神宝 token，`{ k: 'bf', a: 2 }`）、茨木华扇之臂（4 费 / 10 战力，`{ k: 'dwOwn' }`：每回合末随机摧毁本区自己一侧一张实时战力低于它的已翻开卡，见 §1 的 `dwOwn` 行）。「回合开始」只结算本回合开始前就已在场上的卡：地形「出现时」当回合生成的卡跳过当回合、从下一回合起才结算（入队记 `fieldTurn` 比对当前回合）；回合结束/游戏结束不受此限。

**手牌回合结束（`fx.handEnd`；现仅 1 费稗田阿求）**：由阶段 ⑥ `runHandEndEffects()` 结算，排在阶段 ⑤-0 地形类回合末效果 → 阶段 ⑤ 全场 `fx.turnEnd` 之后，逐个检查双方手牌里仍在手上的牌自己的 `def.fx.handEnd`。与 `fx.turnEnd` 分工＝区域不同、互不串场：`turnEnd` 只结算场上的牌（按 `fieldQueue` 顺序）、`handEnd` 只结算回合结束时仍在手牌里的牌（按手牌顺序，双方一视同仁）；同一张牌两种时机都写则各在自己的区域各结算一次。口径：
- ① 两个子句都要成立：「回合结束」且此牌仍在手牌中——打到场上（或被弃、被交换、被洗走等任何不在手牌的情况）后不再触发，只记一条 `sys` 日志。
- ② 每回合末各结算一次、含最后一回合末（阶段 ⑥ 在阶段 ⑦ 终局结算之前）；手牌不计入终局总点数，只影响该方弃牌池；同方手里 2 张就各弃 1 张（各是各的条目与日志）。
- ③ 唯一动作＝`k: 'discard'`：走 `discardFromHand`（第 5 参数 `onlyCard`：先按 `spec` 过滤、再收窄到触发的那一张实例，同名双卡不会互相误伤）⇒ 弃进该牌归属方的弃牌池、播完整弃牌演出（双方可见；见《动画演出与间隔.md》§3「弃牌」），入池元数据 `pileKind`/`pileTurn`/`pileBy`/`pileLoc: null`/`pilePower` 同既有弃牌。
- ④ 不是摧毁：不触发 `surv`/`phx`/`prot`/`ind`、不改战力、不动区域字段与格位（`sideUsed`/`sideRoom`/`fill`）、不进 `powerLog`/`fieldQueue`。
- ⑤ 不是揭示键：`k` 仍为 `''`，`applyEffect` 与 `revealEffectWillChange` 不需要新分支；`kindTags` 输出标签「手牌回合结束 · 仅当此牌仍在手牌中时触发」。
- ⑥ 使用者稗田阿求（1 费 / 4 战力）：`fx: { handEnd: { k: 'discard', discard: { self: true }, t: '…' } }`，卡面＝回合结束：若此牌依然在手牌中，则自动丢弃。
- ⑦ 其它键的 `handEnd` 暂未实装：只记一条 `sys` 日志。

**区域变形（`xform`；现仅鬼人正邪 → 辉针城、灵乌路空 → 聚变反应炉）**：揭示把该区域 def 整体换成目标地形（含 `max`/`inv`/图标/名称）。限张地形的隙间格位随上限变 4 自动消失、可继续放牌；任一方现卡数超过目标上限则变形失败；变形等同于该地形在本区「出现」：目标地形的一次性「出现时」效果（`spawn` 等）立即结算一次，与地形揭晓共用 `runLocAppearEffect`（该侧已满则少放并记日志）；本区原本已是目标地形则不重复结算；`purge`/`minTurn` 等按新地形从变形起生效。

**持续效果（`og`，卡级机制）**：此牌翻开后持续存在的效果（一次性结算的对偶，与揭示互补）。源卡已翻开且仍在己方场上（任一区域）时，己方场上符合匹配条件的卡牌威力常驻 +N，按全场计算（不受目标卡所在区域/回合限制）；实时动态——源卡被摧毁/凤凰重生回手/换边离场即消失，已加成不残留；不进 `powerLog`，但作为一行持续效果显示在「战力影响历史」里（`powerHistoryRows` 第 3 段，判定与 `cardAuraBonus` 一致，保证合计＝场上当前威力）。两种匹配口径：

| 写法 | 匹配对象 | 使用者 |
| --- | --- | --- |
| `og: { tk, add }` | 己方场上带该 `tk` 标记的 token（token 用 `tk` 标记种类） | 比那名居天子（`tk:'rock'` → 己方石块 +2） |
| `og: { cost, add }` | 己方场上印刷费用 `def.c` 恰为该值的卡牌，含特殊卡 token（口径同「雾之湖」的 `cb`：被加费只改 `cardCost`、不改变印刷费用档位；法术无战力、不吃战力加成故不受影响） | 克劳恩皮丝（4 费/4 战力 → 己方所有 1 费卡牌 +1，含 1 费 token 如石块/祖母绿巨石占位） |

> 两种写法可同时存在于同一张卡上（互不冲突，满足任一即计入）；`og` 只由 `cardAuraBonus` / 战力影响历史读取，没有 `applyEffect` 分支（不是一次性结算、不产生 `k` 效果、也不触发演出与摧毁类机制）。

**区域倍率（`mul`，卡级持续机制；现仅 5 费「丰聪耳神子」`mul: 2`）**：与持续 `og` 同族的**实时派生**效果，但作用点不同——`og` 改的是**单张卡的战力**，本键改的是**区域的结算总点数**：源卡已翻开且仍在自己某区域场上期间，把它**所在区域自己一侧**的总点数整体 ×mul。唯一收口＝`cardZoneMul(side, locIdx)`（由 `zoneTotals` 调用 ⇒ 一切读总点数的口径自动覆盖），零状态、没有结算时点。

- **作用点与范围**：`zoneTotals(side, j)` ＝ 该侧已翻开卡的 `cardPowerIn` 之和 ＋ 放满加成 `fill`，算完**整体** ×mul ⇒ `fill` 一起被翻倍；⚠️ 只乘总点数，**不改任何单张卡的战力**（卡面右上角数字、「战力影响历史」面板、`bf`/`de`/`reset` 等增减口径全不受影响，面板「合计＝场上当前威力」照旧成立）。
- **只乘源卡所属的那一侧**：她在哪一列就翻倍那一列的己方总点数，对方一侧完全不受影响；被 `switch`/`gift` 换边到对方一侧后按**新归属方**结算（改为翻倍新一方的那一侧）。与地形 `dbl` 的分工：`dbl` 是地形效果、**双方**同乘；本键是卡面效果、只乘一侧，两者可叠加（顺序＝先乘本键，再乘 `dbl`，反转区域 `inv` 最后取负）。
- **源卡口径同 `og`**：已翻开且仍在场上才生效（暗牌不算；被摧毁 / `phx` 回手 / 移出本区立即失效）；失去卡牌文字（封印 ∪ 静海，判据 `cardMuted`）⇒ 该来源整条失效；不写 `powerLog`、不排队 ±N 演出、不进摧毁池。
- **多个来源各乘一次**：同区两张同名卡（自建卡组两张 / 绵月丰姬 `delCopy` 的复制体 / 四季映姬 `reviveDiscard` 复活）⇒ ×4，乘法叠加、不封顶。
- **按字面严格 ×2**：总点数为 0 ⇒ 仍 0（她自己是 0 战力，单独在场不改变数字）；为负（如被 `switch`/`gift` 换到你这一侧的依神紫苑 −7）⇒ **更负**（反转区域 `inv` 的比较照常按负值处理；`noDown` 免减攻拦的是“减攻”、不拦倍率）。
- **生效面（全部经 `zoneTotals`）**：区域横幅与领先着色、终局逐区胜负与三区总点数决胜及结算行、翻牌先后（`currentLeaderSide`）、卡牌 `bl`（落后自增，含蕾米莉亚 `fx.turnEnd` 的每回合末判定）；`js/ai.js` 简单档的 `hypotheticScore` 直接读引擎 `zoneTotals(..., true)`，故那一档会看到翻倍后的点数。⚠️ AI 新引擎的影子盘面按自己的 `mdPower` 估值、未收录本机制（只影响 AI 排序，引擎结算照常）。
- **与其它机制无交互**：非摧毁 / 非增减 / 非放置——不触发 `surv`/`phx`/`prot`/`ind`、不改格位口径（`sideUsed`/`sideRoom`/`fill` 的判定本身）与 `fieldQueue`；也不受区域 `noDown`（免减攻）影响（倍率不是“减攻”）。卡面带「持续」标记（`cardHasOngoing`）⇒ 会被 3 费法术「生神停止」（`mute has:'ongoing'`）与「静海」（区域抹除）一并处理。
- **界面**：区域横幅显示翻倍后的数字（悬停横幅提示「含持续倍率 ×N」）；终局结算行在该侧被翻倍时标注「（你方/对手总点数×N）」；`kindTags` 输出「持续 · 此区域己方战力 ×N」（故不会显示成「白板」）。

**防摧毁（`surv`，卡级防护；现仅灵乌路空 `surv:2`）**：带 `surv: N` 的卡被任何摧毁指向时（`dw`/`dwh`/区域回合末 `purge` 等）不会离场，改为永久降低 N 点战力（每次触发再降 N、可多次；在聚变反应炉中反复成为全场最低会被反复降低）。被替代时不离开放置队列（后续时机仍可结算/继续判定）；仍可被增益等正常影响；与 `un`（绝对不可动）不同，只是摧毁被替换。⚠️ 该卡所在区域带 `noDown`（蓬莱药局）时替代的 −N 被拦下 → 不离场、也不降攻（`surviveDestroy` 内有专分支与专属日志）。

**凤凰重生（`phx`，卡级机制；现仅 2 费「藤原妹红」`phx: true`，2 费 / 2 战力）**：带 `phx` 的卡被任何摧毁指向时（`dw`/`dwh`/区域回合末 `purge` 等）不会消失——从场上移除后返回自己手牌，并**按本体战力翻倍**（口径与揭示键 `x2` 共用同一收口 `doubleCardPower`：增量＝翻倍前的 `cardPower`＝印刷威力 + 永久增益，**不含**区域加成与持续光环；本体战力 0 ⇒ 不产生变化、为负 ⇒ 更负），可反复「摧毁→重生→再打出」并逐次翻倍（2 → 4 → 8…）；重生瞬间离开场上（移出放置队列），再次打出时重新暗出/翻面入队；手牌已满 7 张则重生失败、按原样被摧毁。⚠️ 翻倍发生在**离场之后** ⇒ 该次翻倍不受区域 `noDown`（蓬莱药局）约束。与 `surv` 区别：`surv` 留场降战力，`phx` 离场回手并成长。

**妖精大战争（`dwc`；现仅 3 费 · 法术 · 无战力的妖精大战争使用，`dwc: { cost: 1 }`）**：揭示时摧毁双方场上所有印刷费用恰为 `cost` 的牌（缺省 `cost = 1`）。与 `dw`（敌方最弱）/`dwh`（敌方最强）/`dwb`（本区双方最弱随机一张）的关键差别：①按费用筛（不是按威力）②范围是双方三个区域 ③命中的牌全摧毁（无并列随机）。实现＝`applyEffect` 的 `case 'dwc'`（逐区结算段，与 `reactorPurge` 同源）。

- 范围与顺序：三个区域（左 → 中 → 右），每区先己方后对方（`zones[j]` 己方 concat 对方）；双方都打——⚠️ 可能摧毁己方自己的 1 费牌。
- 候选口径：已翻开 + 非 `un` 占位卡（隙间）+ 非法术；暗牌不可被提前摧毁（同 `dw`/`dwh`/`dwb`/`purge`）。
- 含落场 token：石块（虹龙洞/天子）、冰块（琪露诺洗入对手牌库后被打出）、祖母绿巨石占位、水银（水银之毒）印刷费用都是 1，照常被扫掉。
- 按印刷费用筛（`def.c`，不是 `cardCost`）：口径同 `discard.cost`/`og.cost`/区域 `cb`/图鉴分档——被桑尼米尔克加过费的 1 费牌照常命中；被 `costDown` 减费的 8 费纯狐仍不是 1 费牌。
- 逐区免摧毁保护：某区为睡鼠神祠（地形 `prot`）或有蕾蒂（卡级 `prot`）时 `locNoDestroy(j)` 为真 → 该区整区跳过（不选目标、也不触发 `surv`/`phx`），其余区域照常。
- 逐张防护/替代链条：`ind`（自身不可摧毁）→ `phx`（回手并翻倍）→ `surv`（改永久 −N、不离场）→ `recordDestroy`（真正离场，进其归属方摧毁池）→ 分崩离析演出 → 出区 → 出放置队列。⚠️ `ind` 走 `continue`（逐张跳过，同地形 `purge`）：某张打不死不影响同区其它该费用牌；不像 `dw`/`dwh`/`dwb` 那样判定落在 `ind` 上就结束（那三个只挑一张，本键是全清）。
- 没有并列随机：命中的牌全部摧毁（`dwh`/`dwb` 只在并列里随机挑一张；地形 `purge` 是并列全删——本键同样全删，只是按费用筛而非按本区最低筛）。
- 非增减/非放置：不进 `powerLog`、不动区域字段，格位由出区自然腾出；`gamble`/`gust` 只作用于本回合在 `revealRound` 里翻开的牌，被本效应摧毁的牌已离场故不参与；法术自身结算完仍自行消散（进放逐池，`pilePower` 记 0）。
- 与摧毁池、`costDown` 联动：真正离场的牌照常进摧毁池（侧栏「己方/对手特殊牌池 → 摧毁池」可查），因此会给纯狐的 `costDown` 推进减费计数——一口气摧毁几张就一次降几费（双方摧毁池合计）。
- 预判：`revealEffectWillChange` 的 `dwc` 分支逐区排除 `locNoDestroy` 后，任一区域存在「该费用 + 已翻开 + 非 `un` + 非法术 + 非 `ind`」的牌即返回 true，否则跳过结算前的停顿。
- 日志逐区一条（记被摧毁时的实时战力）；图鉴标签 `KIND_LABEL.dwc`。
- ⚠️ AI 未收录：`js/ai.js` 无 `dwc` 分支，按认不出的法术估值（打出后效果照常结算）。

**区域免摧毁（`prot`；来源＝卡级「蕾蒂」与地形字段「睡鼠神祠」）**：地形带 `prot`（睡鼠神祠）时，该区域（双方）所有在场卡牌均无法被摧毁——任何摧毁指向结算前查 `locNoDestroy(locIdx)`（第一优先判地形字段），本区 `dw`/`dwh`/`dwc`（`applyEffect`）与回合末 `purge`（`reactorPurge`）直接失效、不选目标，`surv`/`phx` 也不触发；保护含双方已翻开人物卡与落场 token（石块/厄运/分身等）以及此后在该区落下的任何卡；地形随 `xform`/`collapse` 被换掉即失效。卡级 `prot`（蕾蒂）：带 `prot` 的卡翻开后、仍在自己某区域场上期间，同样让该区域双方免摧毁（`locNoDestroy` 第二优先：遍历双方该列找已翻开且仍在场的 `prot` 卡）。两者可叠加但结果相同；按源卡所在区域实时判定：蕾蒂被移去其它区域 → 原区域立即失效、新区域立即生效；同区换边（`switch`/`gift`）仍在同一区域、保护的是敌我双方故效果不变；源卡真正离场才全场失效。

**自身不可摧毁（`ind`，卡级持续机制；现仅佛体金刚石 `ind: true`）**：带 `ind` 的卡在它自己在场期间，摧毁判定落在它身上时会失败——判定式免疫（不是被剔出候选池）：`dw`（比最弱）/`dwh`（比最强）/`dwb`（比双方最弱、并列随机抽一张）/地形 `purge`（比本区最低）决定谁是目标时都把它一起算进去，一旦选中它：

- ① 摧毁失败 + 本次判定结束：不离场、战力不变，不会改打其他牌（结算点 `indestructibleBlock`）。例：聚变反应炉里本区只有金刚石 6 力 + 辉夜 8 力时，本区最低是金刚石 → 摧毁失败 → 辉夜存活。
- ② 不触发 `surv`（改降战力）/`phx`（回手）等被摧毁时的替代机制——它连被摧毁这一步都没走到。
- 并列池随机口径：`dwb`/`dwh` 在并列里随机抽一张，`ind` 卡照常在池子里——抽中它＝失败、判定结束，抽中别的并列牌照常摧毁（不是先排除再抽）。`dwOwn` 的池不是“并列”而是**全部比自己弱的己方已翻开卡**（同样在池里随机抽一张，`ind` 卡照常在池里）。
- 范围与区别：只保护它自己，同区其他卡（含对方卡）照常可被摧毁。`prot` 在任何判定之前就整条拦掉效果、保护本区双方全部卡牌；`ind` 不改判定的对象集合，只是它打不死。也不是 `surv`（被点名后永久 −N，`ind` 被点名后什么都不发生）。
- ⚠️ 非摧毁类效果照常对它生效：战力增减（`bf`/`de`/`ba`/`bl`/`dwb`/`deAll`/地形 `grow`·`decay`·`dice`·`rally`·`gamble`）、移动（`mv`/`roam`/`gust`/`fly`）、换边（`switch`/`gift`）、回手（`phx` 自身触发）一律不受 `ind` 影响。
- 预判一致：`revealEffectWillChange` 算出这次会被判定选中的是谁，若结果是 `ind` 卡则不产生变化 → 不会空等结算前的停顿。

**费用随摧毁递减（`costDown`，卡级持续机制；现仅 8 费纯狐 `costDown: 1`）**：带 `costDown: N` 的卡不需要打出、也不需要翻开——只要还在手牌或牌库里，其实际能量消耗就随本场战斗的摧毁进度实时下降：本场战斗中双方每有一张牌被摧毁，此牌能量消耗 −N（现 N=1）。

- 计数来源＝摧毁池：只算真正离场的那次摧毁——`dw`/`dwh`/`dwh2`/`dwb`/`dwc`/`dwOwn`/`delCopy`/地形 `purge` 把牌实际移出场上时各计 1 张（一次摧毁多张的 `dwh2`/`dwc`/`purge` 按实际离场张数各计 1 张）；即 `destroyCount()` ＝ `pileOf('p','destroy').length + pileOf('a','destroy').length`（双方合计）。摧毁失败一律不计（`phx`/`surv`/`ind`/地形 `prot`·蕾蒂），其它离场方式也不计（`discard`、法术消散、终局 `leave`、撤回手牌、移动 `mv`/`fly`/`shift`/`roam`/`gust`、换边 `switch`/`gift`）。
- 实时动态：读的是当前池子合计，纯狐还没抽到手之前双方被摧毁的牌也一并计入；每多一张被摧毁的牌，手牌/牌库里的纯狐费用立刻再降 N——没有结算挂点、也不写任何状态。
- 下限 0 费：`cardCost` 用 `Math.max(0, …)` 收口，不会出现负数费用。
- def 级判定、实例级呈现：减费不写 `card.costMod`、不改 `def.c`（印刷费用恒为 8）——卡组页/图鉴/费用档筛选/区域 `cb` 费用加成一律仍按 8 费判定；只有实际打出扣的能量、能否负担（`canPlaceP`/手牌置灰/`selectHand`）、撤回暗牌的返还，以及 `Game._dbg().handP` 走 `cardCost`。
- 与 `costUp` 叠加：`cardCost = max(0, def.c + costMod − costDown × 摧毁数)`——桑尼米尔克给纯狐加费同样生效（记在实例 `costMod` 上），两者互不覆盖；因 `cardCost ≥ 6` 的牌不可再加费，纯狐只有减到 ≤5 费时才可能被加费。
- 不是摧毁/非增减/非放置：不触发 `surv`/`phx`/`prot`/`ind`、不动区域字段与格位、不进 `powerLog`/`fieldQueue`；也没有结算时点，不是 `gs` 那类开局结算一次的效果。
- 与能量上限的关系：普通局每回合能量＝`min(回合数, 6)`（上限 6），8 费单靠基数打不出来，靠本机制上桌（双方累计被摧毁 ≥2 张 → 6 费可打出；≥8 张 → 0 费）；配合哆来咪（`gs.energyAdd` 每回合上限 +1、第 6 回合 7 点）或斯塔萨菲雅（`energyNext` 下回合 +1）能更早打出。
- 收口：`cardCost(card)`（费用唯一读法）/`destroyCount()`（紧挨 `pileTotalOf`）/`costDownNote(def)`（放大视图说明行）/`kindTags` 持续标签/`data/cards.js` 的 `costDown=` 字段说明。`js/ai.js` 未收录本机制（对手曲线只到 6 费，正常拿不到纯狐）。

**费用随场上高战力递减（`costDownP`，卡级持续机制；现仅 6 费星熊勇仪 `costDownP: { min: 10, n: 2 }`）**：带 `costDownP` 的卡不需要打出、也不需要翻开——只要还在手牌或牌库里，其实际能量消耗就随**自己场上**的高战力牌实时下降：自己场上每有一张**已翻开**、**实时战力 ≥ `min`** 的卡，此牌能量消耗 −`n`（下限 0 费）。

- 计数来源＝自己场上：只算**此牌归属方**（`card.side`：玩家＝你、AI＝它自己，对双方一视同仁）**三个区域**里**已翻开**的卡，战力按 **`cardPowerIn` 实时判定** ⇒ 区域加成（`aff`/`cb`/`all`）、持续光环 `og`、永久增益 `buff` 全部计入。四种不计：**暗牌**（翻面后才算）、**法术**（战力恒 0，够不到阈值）、**`un` 占位卡**（隙间）、**对方场上的卡**（含被 `switch`/`gift` 换边过去的）。只看张数，不看是哪张、也不要求同名。
- 实时动态：`fieldPowerCount(side, min)` 每次读盘面，没有结算挂点、不写任何状态；翻面 / 被增减 / 被 `og` 或地形抬到阈值 / 被摧毁 / 被移走 / 换边都立刻改变减费额。
- 下限 0 费、def 级判定（减费不改 `def.c`、不写 `card.costMod`）、与 `costUp` 叠加互不覆盖、不触发 `surv`/`phx`/`prot`/`ind`、不动区域字段与格位、没有结算时点、无“费用 ±N”演出：以上各条与 `costDown` 完全同口径（见上一段）。
- 与能量上限的关系：普通局每回合能量＝`min(回合数, 6)`，6 费牌提前上桌靠本机制——场上已有 1 张 ≥10 战力 → 4 费、2 张 → 2 费、3 张及以上 → 0 费。
- 收口：`cardCost(card)`（费用唯一读法）/`fieldPowerCount(side, min)`（紧挨 `destroyCount()`）/`costDownPNote(card)`（放大视图说明行）/`kindTags` 持续标签/`data/cards.js` 的 `costDownP=` 字段说明。
- 联动：`swapDeck`（稀神探女）读的也是 `cardCost` ⇒ 这份减费会被一起卷进费用战力交换，**牌库里的实例同样按当前减费额换**，故牌库实例必须带归属方（`buildDeckCards(curve, side)` / `buildDeckFromDefs(defs, side)` 一律写 `card.side`，与 `drawOne`/`shuffleCardsIntoDeck` 同口径——`cardCost` 在牌库里就要读得到 `side`）。

**终局离场（`leave`，卡级机制；现无使用者，作预留机制保留）**：带 `leave: true` 的卡在游戏结束时（最后一回合全部阶段后、结算胜负前）从场上消失——不是摧毁，不触发任何摧毁相关机制（`surv`/`phx`/各类摧毁文本）；永久 buff 与卡牌一起离开、不计入终局结算；若其离场使该区放满加成等实时判定变化，按既有规则自动刷新。引擎侧 `runGameEndEffects` 的 `leave` 段保留（无卡命中即为空操作），日后有卡需要可直接写 `leave: true`。

**大体积占格（`occ`，卡级机制；现仅伊吹萃香 `occ:4`）**：带 `occ:N` 的卡单卡占据 N 个格位（普通卡为 1）。`occ:4` 占满区域全部 4 格：只能放进最大可放数为 4 且己方该区没有任何卡的区域；放置/在场期间该侧视为已满（不能再落其它卡，`spawn`/移入等按占格口径判定；放满加成 `fill` 按占满 4 格计算）；卡面按整侧 2×2 放大渲染；被摧毁（含反应炉等）、移走、换边、撤回或离场后自动腾出这些格位。引擎统一用 `sideUsed`/`sideRoom` 计占格，不用 `zone.length`。交互：换边（依神紫苑 `switch`/因幡帝 `gift`）落到对方侧时按对方侧空余 ≥ 移入卡占格判定——对方侧被萃香占满（空余 0）则无法换边；`mv` 等移往另一侧同样要求目标侧空余 ≥ 该卡占格数（即对方该区已有任何卡时萃香不能被移过去）。

**放置条件（`playReq`，卡级机制；现仅 6 费 / 16 战力的大鲶鱼 `playReq: { tk: 'rock', n: 4 }`：己方场上已有 ≥4 张已翻开的石块时才可从手牌打出，见 `docs/现有人物卡牌.md` 6 费组）**：带 `playReq` 的卡只有在条件成立时才打得出来——写法 `playReq: { tk: 目标 token 的种类标记, n: 至少几张（缺省 1） }`，`tk` 与 `og.tk`/`tkBuff.tk` 同一套标记口径（现 `'rock'` ＝ 石块）。

- ① 时点＝「手牌 → 场上」这一条路径、且只查一次：`playReqCheck(side, card)` 在从手牌打出（暗出）那一刻判定；不成立就打不出来——玩家侧点区域不落牌、区域不高亮、手牌置灰并提示（`setStatus` + 一条 `sys` 日志写明「现 N 张」），不扣能量、不写 `playerMoves`；AI 走同一收口（计划阶段滤掉候选、出牌前再复核一次），不成立时不会打出。
- ② 打出后不再追踪：不是在场期间持续条件——条件依赖的 token 之后被摧毁（如 `dwc`、聚变反应炉 `purge`）、被移走（`mv`/`fly`/`gust`）、被换边到对方一侧使数量掉到 `n` 以下，这张牌照常留在场上，不移除、不变战力、不返还手牌。
- ③ 计数口径：打出方自己三个区域（左/中/右）里已翻开的卡，按 `def.tk` 匹配；暗牌不计、对方场上的同类 token 不计、不带该标记的其它 token（祖母绿巨石占位/水银/冰块）也不计（`un` 占位卡与法术本来就不带 `tk`）。只看张数，与 token 当前战力（区域加成/持续 `og`/永久 buff）无关。
- ④ 其它上场路径一律不检查：复活弃牌池（`reviveDiscard`）、变身（`morph` 复制体）、落场生成（`placeToken`/`clone`/`spawn*`/地形 `spawn`）都不受限；`give` 塞进手牌后再由手牌打出时照常检查。
- ⑤ 非摧毁/非增减/非放置类：不触发 `surv`/`phx`/`prot`/`ind`、不进 `powerLog`、不改战力、不动区域字段与格位、不进 `fieldQueue`，与区域 `cb`/`all`/`aff` 等加成无交互。
- ⑥ 落地实现：`playReqCheck(side, card)`（`js/game.js`，唯一校验收口，返回 `{ ok, need, have, label }`）+ `tokenNameLabel(tk)`；接入 `tryPlayAt`/`canPlaceP`/手牌渲染/`kindTags`；AI 侧 `aiPlanMoves`/`aiThinkLegacy` 候选过滤/`aiThinkScoreEngine` 出牌前复核/`aiReasonText` 说明。

**分身（`clone` 效果键；现仅赫卡提亚 → 赫卡提亚的分身）**：揭示时向另外两个区域（不含本区）自己一侧各放 1 张分身（该侧放满或区域未开放则跳过该区，两区都放不下则失败）。分身落地即翻开、占格位、进入放置队列；战力按本体揭示时 `cardPower`（基础+永久 buff）快照对齐（差值记在分身的 buff 上，本体随后的增减不影响分身），分身此后可被独立增减；分身无其它效果。

**换边（`switch` 效果键；现仅依神紫苑）**：揭示后立即把自己从一侧转移到对方该区域一侧——翻开时若在己方一侧则消失并落到对方该区（本规则下任何卡都在自己一侧翻开，故统一为翻开后换到对方一侧）；转移后归属对方（`card.side` 更新），作为对方已翻开卡参与结算（−7 战力计入对方该区），占对方一个格位，场上放置顺序不变；对方该区已放满则换边失败、留在自己一侧（负战力继续计入己方）。

**变身（`morph` 效果键；现仅二岩猯藏）**：揭示时从对方手牌随机取一张，把自身整体替换成该卡的复制体（原卡仍留在对方手牌；名称/费用/威力/图标/效果/配图全部变为目标卡）。变身后重新触发新卡的效果文本：若新卡带 `k`（揭示）立即按其结算一次（若新卡也是变身卡则不二次变形，防死循环）；持续 `og`/每回合移动 `fly`/时机效果 `fx`/防摧毁 `surv` 等由新 def 实时驱动自动生效。对方手牌为空则变身失败、保持原样。大体积目标限制：若随机目标是占多格的大体积卡（如萃香 `occ:4`），仅当本区域 max 恰为其占格数且己方该区（明牌+暗牌合计）有且仅有变身者这一张卡时才可变身，否则失败、保持原样。

**摧毁己方一张并复制到另两区（`delCopy` 效果键；现仅绵月丰姬）**：揭示时先按「摧毁」摧毁本区域自己一侧随机一张**已翻开**的卡（候选＝已翻开、排除自己 / 法术 / `un` 占位卡，含落场 token；暗牌不算——翻牌按放置顺序逐张进行，同区后放的己方牌此刻仍是暗牌，故只会摧毁“先于她翻开”的己方卡）。**只有它真的被摧毁离场**时，才把它的**复制体**分别落到另外两个区域自己一侧各 1 张（该区未开放或该侧空余 `< occ` ⇒ 跳过该区、不补别区）。三条边界：①本区免摧毁（`locNoDestroy`：地形 `prot`／蕾蒂）⇒ 整条失效、不选目标；②目标带 `ind` / `phx` / `surv` ⇒ 各自机制照常结算（判定失败 / 回手并翻倍 / 改降 −N），且**都不算被摧毁 ⇒ 不生成复制体**；③真被摧毁才 `recordDestroy` 进摧毁池、播「分崩离析」，因此也喂纯狐 `costDown` 的减费计数。复制体是**完整副本**（`def` ＋ `buff`/`powerLog`/`muteP`/`costMod` 照抄），与 `clone` 的白板 token 是两种东西；落地即翻开、进放置队列（`fieldTurn`＝本回合 ⇒ 其「回合开始」时机效果当回合不结算），随后立即结算其自身揭示——翻牌路径走 `applyDelCopyReveal`（摧毁 → 停 `SHATTER_CARD_MS` → 逐张 `resolveRevealInZone`，故目标区是守矢神社时照常加倍），`morph`/`fx`/落场生成等无法 await 的路径走 `applyEffect` 的 `case 'delCopy'`（一次性落场并就地结算、**不做**第二次揭示）。复制体不经 `revealRound` ⇒ 不参与地形类 `gamble`/`gust`（与 `reviveDiscard` 同口径）；但它走 `resolveRevealInZone`、按**目标区实时**判定 ⇒ 落在「守矢神社」时**照常结算两次**——⚠️ 与落场 token / `reviveDiscard` 复活牌这两类“落地即翻开”刻意不同（那两类走同步 `applyEffect`、**不**加倍）。实现收口：`delCopyCore`。

**送己方最低卡（`gift` 效果键；现仅因幡帝）**：揭示时把本区域己方战力最低的已翻开卡（不含自己；多张并列最低则随机选一张）换边到对方该区域一侧——目标占对方一个格位、归属变对方、该卡的持续效果按新归属方生效（如天子换边过去会改为给新一方石块 +2）；对方该区已放满则换边失败；本区没有其他已翻开的己方卡则无事发生。

**整体右移（`shift` 效果键；现仅八云紫）**：揭示时把己方最左侧区域（第 1 列，下标 0）已翻开的卡牌按放置顺序依次搬到最右侧区域（第 3 列，下标 2）己方一侧，直到右侧己方侧填满为止——按占格 `occ` 判定（右侧空余 ≥ 该卡占格数才搬，放满即停止）；只搬已翻开的卡（暗牌、`un` 卡不动）；不改变归属、揭示状态、场上放置顺序队列；移动后各区域总点数/放满加成实时重算；施放者本牌若在最左侧也会被一起搬。演出：正常翻牌揭示时逐张分步搬运（滑行+缩放飞行落到右侧格位），`morph`/`fx` 等其它结算路径为一次性同步搬运；间隔与形态见《动画演出与间隔.md》§4「整体右移」。

**法术（`spell`，卡级机制）**：`def.spell === true` 的卡是法术——只具有能量花费（`def.c`）与揭示效果（`def.k`）：数字侧写 `spell: true`（战力记 `p: 0`，不要再声明 `og`/`surv`/`phx`/`prot`/`occ`/`fly`/`fx`/`clone` 等其它卡级机制，也不要用 `bl`/`oc`/`switch`/`morph`/`roam` 这类对自身生效的键）。口径：

- 无战力：`cardPower`/`cardPowerIn` 对法术恒为 0；卡框不显示战力（卡面右上角战力位只显示「✦」星标）；不吃阵营 `aff`/费用 `cb`/全区 `all`/持续 `og` 任何加成；任何位置都不受战力增减（`applyPermBuff` 直接跳过，地形 `gamble`/`dice`/`grow`/`decay`/`rally` 同样不作用），故也不进战力影响历史。
- 占位（暗牌与揭示瞬间）：作为暗牌放置需要一个空位——`occ` 恒按 1 计，出牌走 `sideRoom` 判定（能把一侧堵满，也影响对方 `switch`/`gift`/`mv` 落位判定）；揭示瞬间法术本身仍占 1 格（参与该侧是否已满与放满加成 `fill` 判定，它自己的生成类效果也可能因本侧满而放不下），格位到揭示效果结算完之后才腾出；它的「已放置」照常让 `oc` 触发、照常进 `playerMoves`/`aiMoves` 与放置顺序队列。⚠️ 唯一例外：`spawnS` 的 `fill: true` 写法（法术镇守大地之石）先消散自身、再按空位铺满（`applyEffect` 的 `case 'spawnS'` 内显式调用 `vanishSpell`；把自身那 1 格让给生成的卡）。
- 消散（在且仅在揭示效果结算完之后）：`vanishSpell` 把它从所在区域移除、移出放置队列、腾出格位，并播消散演出（`playSpellVanish`/`spawnSpellSparks`）与一条日志。这不是摧毁：不走 `phoenixRevive`/`surviveDestroy`、不查 `locNoDestroy`、不播分崩离析、不触发任何摧毁类文本；不返手、不返牌库。区域「揭示后吹飞」`gust` 因该卡已不在本区而自然跳过。
- 全面免疫：`dw`/`dwh`（最弱/最强）、`mv`（对方最弱）、`gift`（己方最低）等按威力选目标的效果不选法术；`bf`/`de`/`ba` 等增减跳过法术（也不计入影响 N 张）；二岩猯藏 `morph` 不以法术为变身目标；回合末 `purge` 也不把法术列入摧毁候选；`dwc`（妖精大战争）同样排除法术。
- 两种池子：① 角色池（`POOL`）法术——可入卡组（`js/deck-page.js` 按印刷费用档展示）、可被图鉴查看、会被玩家兜底牌库与 AI 随机曲线抽到（AI 的法术估值按效果推演）；② 衍生物池（`SPECIAL`）法术——由 `give` 塞入手牌（仍需手动打出，走正常翻牌流程；如雾雨魔理沙 → 极限火花），或由 `placeToken`/`clone` 落场生成：等同手打一张，先结算它自己的揭示、随即消散（`settleFieldSpell`，同步结算、无停顿与翻牌演出）。衍生法术在开发者「🎯 指定卡牌」里可以加入手牌（其余衍生卡仍仅可查看）。
- 费用修正照常：法术有能量花费，故 `costUp`（桑尼米尔克）可以给它加费，`cardCost`/卡面费用着色与「印刷费用 → 现在」提示照旧。

**集结（`gather` 效果键；现仅法术三妖精集结）**：`def.gather = { group: 阵营键, add: 强化值 }`（现 `{ group: 'light', add: 1 }`）。揭示分两步，顺序固定：

1. 随机分配生成：从 `POOL` 里取出 `g === group` 的成员卡（去重；排除 `un` 占位卡、法术（`spell`）、大体积卡（`occ > 1`）——见 `gatherMembers`），随机排列后按区域顺序（左→中→右）分配：三个区域自己一侧各生成 1 张，故三张互不相同（成员多于 3 张时随机取 3 张；少于 3 张时靠后的区域分不到、日志写明）。生成走 `placeToken`：落地即翻开、占一个格位、进入场上放置顺序队列并播「凝聚显形」演出。
   - 「若可能」＝跳过：某区域该侧已放满（`sideRoom < 1`）或区域未开放（`locOpen`，如七夕坂第 5 回合前）→ 跳过该区、不把这一张补到别的区域，日志列出被跳过的区域与原因。
   - 生成后立即结算它们自身的揭示（与地形 `spawn.reveal` 同款）：按落场顺序同步结算（无停顿与逐张翻牌演出），故桑尼米尔克会当场让对方手牌随机一张 +1 费、露娜·切露德会当场削弱同区对方已翻开卡、斯塔萨菲雅会给施法方自己下回合 +1 能量（揭示在阶段 ④ 结算，能量在下回合 ①-2 到账）。
2. 在这之后强化己方：给自己一侧场上已翻开的该阵营卡牌永久 +add 战力（走 `applyPermBuff` 收口：±N 演出 + 战力影响历史按来源记这张法术卡名）。含刚生成的那几张（落地即翻开）；只算自己一侧（对方场上的同阵营卡不动）；暗牌不参与（同 `bf`/`de`/`ba` 口径，翻面后错过本次结算）。若己方场上没有已翻开的该阵营卡则无事发生并记日志。

**与法术占位的交互**：法术在揭示期间仍占 1 格，若这张三妖精集结正好是某区域的第 max 张（例如该区自己一侧本就 3 张、法术是第 4 张），则该区自己一侧已满 → 这一区的三妖精被跳过（法术要等揭示效果结算完才腾出格位），另两区照常；法术随后按法术口径自行消散。

**分步亮相（只在正常翻牌流程里）**：阶段 ④ `revealRound` 结算三妖精集结时走异步分步演出 `applyGatherReveal`——按区域顺序逐区推进（每区先 `renderZones()` 再结算该区揭示），三区都揭示完之后才结算第 ② 步「己方场上已翻开的三妖精 +add 战力」，随后才播这张法术的消散演出；被跳过的区域不产生演出，只在日志点名。其它结算路径（`morph` 变身、`fx` 时机效果、落场生成的衍生物法术 `settleFieldSpell`）走同步版（`case 'gather'`：一次性生成 + 结算，无分步节奏与逐步渲染），两者口径一致。中断保护同 `applyShiftReveal`：重新开局（`state.gen` 变化）时立即停止后续步骤。每区之间的间隔见《动画演出与间隔.md》§4「三妖精集结」。

**它与既有机制的关系**：生成的卡是普通人物卡实例（不是 token），有独立 `id`/`buff`/揭示，之后可被增益/削弱/摧毁/移动正常影响；`oc`/`bl`/`gamble` 等按「它们自己也是本回合落场/翻开」的既有口径处理（`gamble` 对落场即翻开的卡不追溯）；`decay`/`grow`/`dice`/`rally`/`purge` 照常作用于它们；AI 的落子估值按 `gather` 的实际生成推演：用成员平均战力代表三区各生成的那 1 张，并计入随后的「己方场上已翻开同阵营 +add」。

**帕秋莉法术池（`drawSpell`，时机效果；现仅帕秋莉·诺蕾姬）**：帕秋莉·诺蕾姬（3 费 / 2 战力，`k` 为白板、只带时机效果 `fx.turnStart`）在回合开始时从帕秋莉法术池随机把 1 张法术加入自己手牌。口径：

- 池：写在帕秋莉的 `fx.turnStart` 条目里——`{ k: 'drawSpell', n: 1, pool: [SPECIAL 键名…], t }`，卡级 `spellPool: [键名…]` 作兜底；池内现为 5 张 1 费法术（火神之光/祖母绿巨石/绿色风暴/水银之毒/金属疲劳，清单见 `docs/现有特殊卡牌.md`），只有 `spell: true` 的条目会被采用（非法术条目一律忽略）。
- 随机、可重复：每回合独立随机，同一张法术可能连续几回合都抽到（不洗池、不做不放回管理）。
- 加入手牌：由 `newCard(TOKENS[key])` 生成新的卡实例并打 `justHandAdded` 标记；手牌满 7 张则本次加入失败、无事发生（同 `give`/`phx` 回手口径，只记一条日志）。
- 归属：按牌的所属方——玩家打出给自己、AI 打出给自己；被 `gift`/`switch` 换边到对方一侧后，按新归属方抽给那边。
- 时机：`fx.turnStart` 在每回合 ①-1（全场回合开始效果）结算，早于能量结算与抽牌，故抽到的法术当回合出牌阶段就能用；帕秋莉本回合在阶段 ④ 才翻开，按「刚登场的卡跳过当回合的回合开始效果」的口径，她从翻开的下一回合起才每回合抽 1 张（与幽灵洋馆的幽灵当回合不游走同一逻辑）。
- 抽到的法术照常走「暗出 → 翻牌揭示 → 自行消散」流程（1 费能量；暗牌占 1 格；揭示瞬间仍占格；消散后腾出格位并播消散演出）。5 张法术与它们的 token 不入牌库、不出现在图鉴的人物卡档（只在图鉴「衍生卡牌池」、帕秋莉的「衍生卡牌」面板里可见；衍生卡自成一层的卡池），开发者「🎯 指定卡牌」可把法术加入手牌。
- AI：AI 抽到帕秋莉时同样每回合抽法术（双方一视同仁）；AI 对法术的估值按效果推演——影子盘面会真的结算它自己的揭示（`de`/`bf`/`dwb`/`spawnS` 等对盘面的影响都计入），故这些法术在 AI 手里不再一律滞留（只有推演结果会把局面变差时才不出，例如 `dwb` 火神之光推演出会摧毁自己那张最弱牌）。
- 5 张法术各自的效果键：`dwb`（火神之光：摧毁本区双方已翻开、战力最低的随机一张——并列最低在其中随机挑一张；排除暗牌/`un`/法术；受 `locNoDestroy`（地形 `prot`/蕾蒂）保护时整条失效；目标带 `surv`/`phx` 时按各自机制处理；⚠️ 可能摧毁己方自己的卡）、`spawnS`（祖母绿巨石：在本区自己一侧生成 1 张 1 费 / 3 战力的同名占位卡，本侧放满则失败），以及复用既有键的三张：绿色风暴＝`bf +1`（该区已翻开友方 +1）、水银之毒＝`spawnO`（1 费 / −1 战力的水银落对方一侧，口径同厄运）、金属疲劳＝`de −1`（该区已翻开敌方 −1）。绿色风暴/金属疲劳只作用于结算那一刻已翻开的卡（同 `bf`/`de` 口径），法术自身免疫战力增减故含不含自己结果相同。

**洗入卡组（`shuffleIn` 效果键）**：`def.shuffleIn = { card, n, to }`——揭示时把指定牌 n 张洗入某一方的牌库，并把该方整副牌库重新随机洗一次。这是继「进手牌」（`give`）、「落场」（`spawn`/`spawnO`/`spawnS`/`spawnMine`/`clone`）之后第三种「牌的去处」：进牌库（隐藏区）。口径：

- **写法**：`card` 先按**衍生池 `SPECIAL` 的键名**查（如 `'stone'`），查不到再按**卡名**在人物池 `POOL` 里找（如 `'琪露诺'`）——即人物卡与 token 都能引用（`findCardDefByKey`）；`n` = 张数，缺省 1，每张都是**全新的卡实例**（`newCard`，`costMod` 为 0、不继承任何既有费用修正）；`to` 缺省 `'own'` = 洗入**施放方自己**的牌库，`'opp'`（也接受 `'a'`）＝洗入**对方**牌库。
- **可作揭示，也可作时机效果**：与其它效果键一样，本键走同一条 `applyEffect` 分支 —— 既可写成卡牌的揭示（`k: 'shuffleIn'`），也可挂到 `fx` 时机效果上（如 `fx.turnStart = { k: 'shuffleIn', shuffleIn: { card: 'stone', n: 1 } }`，结算逻辑完全相同）。
- **张数无上限**：牌库不是手牌，**没有 7 张上限**，「手牌满则失败」的既有口径**不适用**；空牌库洗入后同样会变得可抽。牌库张数不影响终局结算（终局只看场上）。
- **重洗范围 = 该方整副牌库**（含原本尚未抽到的所有牌）：实现为 `shuffleCardsIntoDeck(side, def, n)` —— 逐个 `newCard` + 打 `side` 归属 + `deck.push`，最后就地 `shuffle(deck)`（Fisher-Yates）。`drawOne` 从**队尾** `pop`，所以重洗之后"下一张会抽到什么"**立刻改变**；牌序本就纯随机，重洗只改变后续抽牌分布，不引入新的公平性问题。
- **不结算被洗入卡的任何效果**：它进的是牌库——**不翻开、不占格位、不进场上放置顺序队列**（`fieldQueue`），也不触发揭示 / 持续 `og` / 时机 `fx` / `surv` / `phx` / `prot` / `ind` 等任何机制，更不进战力影响历史（`powerLog`）。日后被 `drawOne` 抽到手牌、再被**暗出翻开**时，才按该卡的常规流程结算（与开局洗牌同口径）。**带效果的卡也能被洗入**，只是效果要等它被打出才发生。
- **归属对双方一视同仁**：按**牌的所属方**（`side`）决定落进谁的牌库——玩家打出给自己、AI 打出给 AI；被 `switch`/`gift` 换边后按**新归属方**结算（与 `costUp`/`energyNext`/`drawSpell` 同口径）。
- **公开与演出**：日志点名「把 N 张「X」洗入了谁的牌库，并重新洗了一次牌（现牌库 M 张）」（洗入对手走红色 `danger` 提醒，与加费公开、摧毁类日志同款）；随播轻量演出 `playShuffleInFx`（形态、锚点与跳过条件见《动画演出与间隔.md》§3「洗入卡组」）。
- **与其它机制的边界**：非"摧毁"/非放置/非增减类 —— 与 `locNoDestroy`、`surv`/`phx`/`prot`/`ind`、区域字段（`purge`/`grow`/`decay`/`dice`/`rally`/`gamble` 等）、格位（`sideRoom`/`occ`）、放满加成全无交互；被洗入的实例也不参与 `un`/法术那套"不可操作/无战力"判定（它还没上场）。
- **预判**：`revealEffectWillChange` 的 `shuffleIn` 分支在「条目合法且 `n > 0`」时**恒为 true**（牌库张数与抽牌顺序一定会变，不像 `give` 会因满手落空），因此照常走结算前的停顿与翻牌演出；键名写错时不空等、只记一条日志。
- **使用者**：与「琪露诺」（1 费 / 2 战力）同款落地——写法为 `k: 'shuffleIn'` + `shuffleIn: { card: 'ice', n: 1, to: 'opp' }`，即**向对手的牌库洗入 1 张「冰块」**（token，1 费 / 0 战力白板，见 §3）；被洗入的冰块只**稀释对手牌库 + 占用其手牌位**（对手抽到一张 0 战力白板，其手牌满 7 张后还会因「手牌满不抽牌」卡住后续抽牌），它自身的效果要等对手把它抽出并暗出翻开时才按普通白板卡结算。**1 费 / 1 战力 · `bf +1`（同区你的其他已翻开卡牌 +1）**的款式只由「莉莉霍瓦特」保留。标签取自 `KIND_LABEL.shuffleIn`「揭示 · 洗入卡组（自己或对手的牌库，并重新洗牌）」，`kindTags` 与「衍生卡牌」面板（`tokenLinksForDef` 读 `shuffleIn.card`）都已接上。

**弃牌（`discard` 效果键）**：`def.discard = { n, to, pick, card, cost }` —— 揭示时把牌从**手牌**移出、放进该牌**归属方**的**弃牌池**（`discardPile`）。这是继「进手牌」（`give`）、「落场」（`spawn*` / `clone`）、「进牌库」（`shuffleIn`）之后的**第四种"牌的去处"**：进**弃牌池**。

- **与「摧毁」的分工（本机制最重要的一条）**：**弃牌只移除手中的牌，摧毁只移除场上的牌**——两者**互不重叠**。因此弃牌**不是**"摧毁"：
  - 不触发任何摧毁类机制与防护：`surv`（防摧毁）/`phx`（凤凰重生）/`prot`（区域免摧毁，地形「睡鼠神祠」或「蕾蒂」）/`ind`（自身不可摧毁，「佛体金刚石」）**一律不参与**——这些机制的前提都是"场上的牌被摧毁"，而弃牌连"被摧毁"这一步都没走到；也不进摧毁池（摧毁池只收 `dw`/`dwh`/`dwb`/`dwc`/地形 `purge` 真正离场的那次摧毁）；
  - 不进战力台账 `powerLog`、**不改变任何战力**（牌只是从手牌消失）、不排队 ±N 演出、不进战力影响历史；
  - 不触碰区域字段（`purge`/`grow`/`decay`/`dice`/`rally`/`gamble`/`prot`…）、格位与放满加成（`sideUsed`/`sideRoom`/`fill`），也不进场上放置顺序队列（`fieldQueue`）——手牌本来就不在场上；
  - 反向也成立：**摧毁不会弃手牌**（摧毁池与弃牌池互不写入）。
- **写法**：`{ n, to, pick, card, cost }`
  - `n`：张数，缺省 1；写 `'all'`＝命中多少弃多少；候选不足时弃掉手上有的那些（日志写明"本来要弃 N 张"）；一张都没有 → **无事发生**（只记一条日志，跳过结算前的停顿）；
  - `to`：`'own'`（缺省）＝弃**自己**手牌；`'opp'`（也接受 `'a'`/`'enemy'`）＝弃**对方**手牌。归属按**牌的所属方**（`side`）：玩家打出弃 AI、AI 打出弃玩家，对双方一视同仁；被 `switch`/`gift` 换边后按换边后的新归属方（与 `costUp`/`energyNext`/`drawSpell`/`shuffleIn` 同口径）；
  - **`pick`（取牌位置）**：`'random'`（缺省）＝在候选里**随机**取 n 张（与 `costUp` 让对方手牌随机一张 +1 费同款口径，沿用全局 `Math.random`；冒烟测试会替换成种子化 PRNG）；`'right'`＝从**最右侧**起取（即手牌最右那张／最右 n 张）；`'left'`＝从**最左侧**起取；**`'maxCost'`＝取**印刷费用 `def.c` 最高**的那些（**并列最高的多张之间随机**，口径同 `dw`/`dwh`/`dwb` 的"并列里随机挑一张"）**。候选数组**保持手牌顺序**（左 → 右＝数组顺序），故位置读到的就是玩家看到的手牌左右位置；**可与 `card`/`cost` 筛选叠加**（先按筛选缩小候选、再按 `pick` 取）；`n: 'all'` 时位置无意义（全都要）。⚠️ `'maxCost'` 比较的是**印刷费用 `def.c`**（**不是** `cardCost`）——与 `cost` 筛选、区域 `cb` 费用加成、`og.cost`、图鉴/卡组页分档同口径：被桑尼米尔克加过费只改实际能量消耗、不改变"贵贱"排序；
  - `card`：可选，按**卡名**筛选（字符串或数组，如 `'琪露诺'`；也接受 **SPECIAL 键名**，如 `'stone'` → 石块，由 `discardNameFilter` 归一成卡名）。⚠️ 同名卡（法术「祖母绿巨石」与同名占位 token「祖母绿巨石」）**会一起命中**；
  - `cost`：可选，按**印刷费用 `def.c`** 筛选（数字＝恰好该费用；`{ min, max }`＝含端点的区间，缺省端点无界）。⚠️ 用**印刷费用**而非 `cardCost`（口径同上）；
  - `card` 与 `cost` **都不写**时＝该方**整副手牌**都是候选（从中随机弃 n 张）。
- **公开（双方可见）**：弃牌**不遮掩**——① 日志点名弃了谁手牌里的哪几张（**弃对手的牌走红色 `danger`**，与加费/摧毁/洗入对手牌库同款；弃自己的走 `sys`）；② 场地中央弹出**被弃那张牌的完整卡面**（`cardFaceHTML` + `.zoom-card`，配图/费用/战力/卡名/效果文案与手牌一致）并播从右上到左下**斜切两半**的演出（见下文「弃牌演出」段）；③ 被弃的牌此后躺在该方「弃牌池」里（侧栏徽标 + 弹窗页签），对玩家而言是**明牌**。
- **入池口径**：入池的是**牌本体**（同一卡实例，不复制、不改 `def`），走 `pushToPile(side, 'discard', card, meta)` 收口 → **先进先出**、界面按入池顺序（旧 → 新）展示；元数据 `pileKind='discard'`、`pileTurn`＝弃牌时的回合、`pileBy`＝来源卡名（控制台探针记「开发者指令」）、`pileLoc=NULL`（**手牌不在场上**，故没有区域）、`pilePower`＝被弃那一刻的**手牌口径战力** `cardPower`（基础 + 永久 buff；法术恒为 0；手牌没有区域 `aff`/`cb`/`all` 与持续 `og` 加成）。被弃的牌**带着自己的一切**进池：`costMod`（本场战斗的费用修正）与 `powerLog`（永久增益台账）都随实例保留，可在弹窗里放大查看。
- **不是"离场/回手/返库"**：被弃的牌不返场、不回手牌、不回牌库、不参与终局结算（终局只看场上）；**也不影响手牌上限**——手牌上限 7 张只约束"加入/抽牌"，弃牌是**减少**手牌，两者不冲突（「手牌满则失败」这类口径对本机制不适用）。
- **与「重置暗牌」的边界**：重置只按 `playerMoves[].hi`（暗出时记录的手牌下标）把**本回合暗出的那几张**插回原位，被弃的牌不在 `playerMoves` 里、**不会被重置带回手牌**。
- **可作揭示，也可作时机效果**：与 `shuffleIn` 同口径——本键走同一条 `applyEffect` 分支，故也可写成 `def.fx.turnStart`/`turnEnd`/`gameEnd` 里的条目；`revealEffectWillChange` 也接了本键（目标方手牌里存在符合 `card`/`cost` 筛选的候选才为 `true`，否则跳过结算前的停顿）。
- **第三种入口：手牌回合结束自动弃牌（`fx.handEnd.discard`）**：写法 `fx: { handEnd: { k: 'discard', discard: { self: true } } }` —— **回合结束：若此牌依然在手牌中，则自动丢弃**（「稗田阿求」，1 费 / 4 战力）。它与上面两种入口的区别是**没有任何卡在场、也没有"施放者"**：结算发生在**阶段 ⑥ `runHandEndEffects()`**（详见下方「手牌回合结束（`fx.handEnd`）」段），逐张检查**双方手牌**里仍在手上的牌自己的 `handEnd` 条目；`discard.self: true` ⇒ 由 `discardFromHand` 的 **`onlyCard` 参数**把候选收窄到**触发的那一张实例**（**同名双卡不会互相误伤**），其余（弃进**该方弃牌池**、完整弃牌演出、入池元数据、日志）与既有弃牌**完全一致**。⚠️ 它不是揭示键、`revealEffectWillChange` **不需要**为它加分支（`k` 仍为 `''`）。
- **第四种入口的配套子句：`discard.give`（弃牌后按被弃牌的印刷费用加手牌衍生物）**：写法 `discard: { …, give: { card: 'stone', n: 1, powerFromCost: true } }` —— 弃牌**真的发生之后**，**每弃掉 1 张**就给**施放方自己**加入 `give.n`（缺省 1）张 `give.card`（**SPECIAL 键名**，如 `'stone'` → 石块）的**新卡实例**到**手牌**：
  - **触发前提＝弃牌成功**：`discardFromHand` 返回 `ok:false`（手牌为空 / 没有符合筛选的候选）时**本条完全不结算**——既不弃牌也不加任何卡，只记一条"想弃但没牌"的日志；`revealEffectWillChange` 的 `discard` 分支**无需改动**（候选为 0 时两者一起落空，不会白等结算前的停顿）；
  - **"能量"＝印刷费用 `def.c`**（**不是** `cardCost`）：`powerFromCost: true` 时衍生物战力 ＝ **那一张被弃牌**的印刷费用 —— 与 `discard.cost` 筛选、`dwc`、`og.cost`、图鉴/卡组页分档**同口径**（被桑尼米尔克加过费只改实际能量消耗、**不改变**造出的衍生物战力）；**逐张对应**：弃 n 张就产生 n 组衍生物，每组按"被弃掉的那一张自己"的印刷费用算（`give.n` 与 `discard.n` 相互独立）；缺省 `false` ＝ 用衍生物自身的印刷战力；
  - **战力差额走永久增益收口**：`applyPermBuff(新实例, pw − tk.p, srcCard, '弃牌转化')` ⇒ 卡面显示"基础战力 + **绿色 +N**"（口径同「赫卡提亚的分身」的快照对齐）、`powerLog` 台账里来源记**本卡**（放大视图可见）；衍生物本体仍是既有 token（`SPECIAL.stone`：同名「石块」、1 费 / 0 战力、带 `tk: 'rock'`）⇒ 照常被**大鲶鱼** `playReq: { tk:'rock', n:4 }` 计数、照吃天子 `og` 与「地精的起床」`tkBuff` 的强化、也会被「妖精大战争」（按 1 费印刷费用）扫掉；
  - **进的是手牌、不是场上**：`newCard` 新实例 + `justHandAdded`（`flushHandAdd` 播"滑入"演出，口径同 `give`）⇒ 仍需**手动暗出**（暗牌占 1 格、揭示时无效果）；`def` / `costMod` 全新、**不继承**被弃牌的任何修正；
  - **手牌上限 7 张照常约束**（同 `give` 口径：满则加不进、日志写明；本卡实际情形是"先弃 1 张再加 1 张"，位置一定够）；**加入目标恒为「施放方自己」**——与 `discard.to` 无关（即使弃的是对手手牌，衍生物也进自己的手牌）；
  - **非摧毁 / 非放置 / 非增减类**：与 `surv`/`phx`/`prot`/`ind`、区域字段与格位（`sideUsed`/`sideRoom`/`fill`）、`fieldQueue`、`powerLog` 全无交互（手牌本就不在场上）；
  - **使用者**：「莉莉黑」写法 `k: 'discard'` + `discard: { to: 'own', pick: 'right', n: 1 }` —— **丢弃自己最右侧的 1 张手牌**（代价型：被弃的牌进**自己**的弃牌池）；「小野塚小町」（3 费 / 5 战力，无阵营）写法 `discard: { to: 'own', pick: 'maxCost', n: 1 }` —— **丢弃自己手牌中印刷费用最高的一张**（同样是**代价型**，被弃的牌进**你的**弃牌池）；「姬虫百百世」（2 费 / 2 战力）写法 `k: 'discard'` + `discard: { to: 'own', pick: 'random', n: 1, give: { card: 'stone', powerFromCost: true } }` —— **揭示：随机丢弃你手牌中的 1 张卡，并将 1 张战力等于该卡能量消耗（印刷费用）的「石块」加入你的手牌**（代价型：弃的牌进**你的**弃牌池）。⚠️ 揭示时使用者**自己都已经不在手牌里**（暗出后被移出手牌），故"最右侧"/"最贵那张"/"随机 1 张"都按**揭示那一刻的剩余手牌**判定，不会弃到自己；手牌为空则无事发生（只记一条日志）。人物卡条目见 `docs/现有人物卡牌.md`（莉莉黑在 1 费组、小野塚小町在 3 费组）。实现收口＝`js/game.js` 的 `discardGiveTokens(side, spec, res, srcCard)`（紧挨 `discardFromHand` 之后，返回 `{ added, want, name, powers, full, missing }`；`spec.give` 缺失时返回 `null`）。为便于验证任意口径，`js/game.js` 另导出**控制台探针** `Game._discard(side, spec)`：`Game._discard('a', { n: 1 })` / `Game._discard('p', { pick: 'right' })` / `Game._discard('p', { pick: 'maxCost' })` / `Game._discard('p', { card: '琪露诺' })` / `Game._discard('a', { cost: { min: 5 }, n: 'all' })`——与卡牌结算走**同一个** `discardFromHand` 收口，流程/日志/入池/演出完全一致。

**弃牌演出（`playDiscardFx`）**：**任何一种归属组合**（自己弃自己 / 自己弃对方 / 对方弃对方 / 对方弃自己）都**双方可见**——在场地中央弹出被弃那张牌的**完整卡面**，随后**从右上到左下**斜切一刀，卡面裂成两半、分离并淡出。结构（顶部标签 / 卡面块 / 底部说明）、`clip-path` 斜切实现、斩击线与分离方向、时间轴、多张并排的错开口径、样式类名与关键帧、以及改时长要动哪几个数字，全部见《动画演出与间隔.md》§3「弃牌」。


**复活弃牌池（`reviveDiscard` 效果键，现仅 6 费「四季映姬」）**：`k: 'reviveDiscard'`（**无附加字段**）—— 揭示时把**自己一方**的**弃牌池**（`discardPile`，唯一入池来源是「弃牌」`discard`）里**所有「角色卡牌」**以**随机顺序**复活到**随机区域**。这是继「进手牌」（`give`）、「落场」（`spawn*`/`clone`）、「进牌库」（`shuffleIn`）、「进弃牌池」（`discard`）之后**第一次把牌从牌池"捞回场上"**的机制。

- **复活对象**：**只复活角色卡牌** —— 即**弃牌池里所有非法术的牌**（`def.spell !== true`）；**法术不参与复活、留在弃牌池**（日志点名说明），因此卡面文字写作"你所有被丢弃的**角色卡牌**"。⚠️ 按此口径，**落场型衍生卡（如辉夜给的「无限生命泉 / 火蜥蜴之盾 / 佛体金刚石」等神宝）属于非法术卡，照常会被复活**。
- **随机顺序**：对候选快照做一次 `shuffle`，逐张依次复活（顺序随机；不保证三区均匀分布）。
- **随机区域（关键差别）**：每张牌**只在「已开放且自己该侧放得下」的区域里等概率随机**——候选区 = `locOpen(j)` 为真 **且** `sideRoom(side, j) ≥ occOf(card)`：
  - 因此**不会出现"掷到一个已放满的区域就复活失败"**的情况（这个区满了就换别的、只要还有放得下的区就一定能复活）；
  - **未开放**的区域（`minTurn`，如七夕坂第 5 回合前）不算候选（同 `mv`/`roam`/`clone` 的 `locOpen` 口径）；
  - **大体积卡**（`occ:4` 伊吹萃香）需要该侧空余 ≥ 4（实际＝该侧完全空出的 `max=4` 区域），否则不算候选（同放置/`mv`/`switch` 的占格口径）；
  - 三区都放不下或未开放 → 该牌**留在弃牌池**（"若可能"），日志逐张点名。**逐张独立判定**：前一张占了位置导致后一张放不下是正常结果（与"随机到满区就失败"不是一回事）。
- **落地即翻开**：`revealed = true`、占格位（`sideUsed`/`sideRoom`/放满加成 `fill` 立刻重算）、进**场上放置顺序队列** `fieldQueue`（`enqueueField` 记 `fieldTurn`＝当前回合 ⇒ 其**「回合开始」时机效果当回合不结算、下回合起才结算**），并播**「凝聚显形」**演出（`justSpawned`，口径同 `placeToken`/分身 `clone`）。
- **逐张重新结算其自身「揭示」**：每复活一张就立刻按该卡**当前所在区域**结算它自己的揭示（白板跳过）——口径同 `spawn.reveal` 与「集结」的**同步结算**：无停顿、无逐张翻牌演出，但日志 / ±N 气泡 / 战力影响历史照常。连锁是**真实发生**的：复活「蓬莱山辉夜」会再抽 2 张神宝、复活「雾雨魔理沙」会再给 1 张「极限火花」、复活「鬼人正邪」会再变形本区…… 若连锁把牌挪走（`mv`/`roam`/`shift`/换边），后续结算按**挪走后的实时位置**（`fieldLocOf`）读取。**弃牌池里若还躺着另一张四季映姬**，它被复活后也会再触发一次本效果（同一条路径）；因为每张复活后**立即从池中移出**，链条**必然收敛**（循环内以 `pile.indexOf(c) < 0` 跳过已被连锁复活走的条目）。
- **牌本体保留一切**：从池中移出的是**同一个卡实例**——永久增益台账 `powerLog`、本场战斗的费用修正 `costMod`（如被桑尼米尔克加过费）都随它回到场上；离池时**清掉入池元数据**（`pileKind`/`pileTurn`/`pileBy`/`pileLoc`/`pilePower`）。复活**不是**"重新造牌"，所以不会有第二份实例。
- **不是"暗出"、也不是"打出"**：**不消耗能量**、**不写 `playerMoves`/`aiMoves`** —— 因此它**不会被阶段 ④ 的翻牌流程二次结算**（不会重复揭示），也**不会被「重置暗牌」收回**（重置只处理本回合暗出的牌）。它落地即已翻开，不存在"翻面"这一步。
- **不是"摧毁"、非增减**：与 `surv`/`phx`/`prot`/`ind`、摧毁池、战力台账 `powerLog`（除牌自身既有的台账随牌回来）均无交互；它**不写入**摧毁池（只有真正离场的摧毁才入池），也**不写入**放逐池（法术才入放逐池）。
- **与区域"翻开时/吹飞"类机制**：`gamble`（驹草赌场）与 `gust`（魔力风暴）都**只作用于"本回合在 `revealRound` 里被翻开的牌"**，复活卡落地即已翻开、不走 `revealRound` ⇒ **不参与**（与"落地即翻开的 token / 已翻开后被移入的卡"同款口径，无需额外代码）。
- **归属**：按**牌的所属方**（`side`）——玩家打出复活玩家自己的弃牌池，AI 打出复活 AI 自己的弃牌池（对双方一视同仁；被 `switch`/`gift` 换边后再被弃的牌按换边后的归属入池，故也照此复活）。
- **可作揭示，也可作时机效果**：与 `shuffleIn`/`discard` 同口径，走同一条 `applyEffect` 分支，故也可写成 `def.fx.turnStart/turnEnd/gameEnd` 里的条目。
- **预判（`revealEffectWillChange`）**：弃牌池里**存在至少一张"能落地"的角色卡牌**（＝有一个 `locOpen` 且 `sideRoom ≥ occOf` 的区域）才为 `true`，否则跳过结算前的停顿；池空、只有法术、三区全满或未开放 → 落空。

**复活节奏：逐张分步演出（只在正常翻牌流程里）**：`revealRound` 结算「四季映姬」时走**异步分步演出** `applyReviveDiscardReveal` —— **逐张推进**：**捞出一张 → `renderZones()`（播「凝聚显形」）→ 结算"这一张"自身的揭示 → `renderZones()`（让 ±N / 生成 / 摧毁等演出显示出来）→ 停一个逐张间隔后复活下一张**……全部复活完之后再打收尾日志（汇总 / 法术跳过 / 放不下）。口径：**避免一次性复活一大把牌**（连锁揭示叠加、演出互相盖住、极端情况下的渲染压力）。其它结算路径（`morph` 变身、`fx` 时机效果、落场生成等非翻牌路径）走**同步版**（`applyEffect` 的 `case 'reviveDiscard'`：一次性结算、无分步节奏与逐步渲染），两者口径**完全一致**——共用三个收口 `reviveTargetZones`（候选区＝已开放且该侧放得下）/ `reviveCardFromPile`（随机落点 + 离池 + 落地即翻开 + 占格 + 入队）/ `reviveStuckLog`（收尾三条日志）。中断保护同 `applyShiftReveal` / `applyGatherReveal`：重新开局（`state.gen` 变化）时立即停止后续步骤。⚠️ 每张牌的实际观感节奏 =「凝聚显形」入场动画 + 该张揭示的演出 + **一个固定逐张间隔**；间隔常量（`REVIVE_STEP_MS`）、「凝聚显形」时长与改节奏的落点见《动画演出与间隔.md》§4「复活弃牌池」。⚠️ **连锁例外**：若弃牌池里还躺着**另一张四季映姬**（同名卡在自建卡组里限 1 张，但哆来咪的 `gs.shuffleN` 从卡池随机洗入时可能带进第二张），她被复活后会**立即再触发一次本效果**——这次走的是**同步版**（发生在结算链内部、无法 `await`），因此那一批牌会一次性复活；回到外层循环后仍按逐张间隔继续推进，且已被连锁复活走的牌会被自动跳过（`pile.indexOf(c) < 0`）。

**揭示再触发（`retrigger`；现仅 5 费「东风谷早苗」，`k: 'retrigger'`、**无需附加字段**）**：**一句话口径**＝**把此牌所在区域里、自己一侧「已翻开」的卡牌的「揭示」效果各再结算一次**（**无法触发回合开始/结束、持续等非揭示效果**）。卡面效果写作「揭示：此牌所在区域的其他己方已翻开卡牌的『揭示』效果，各再触发一次」。收口三个：候选 **`retriggerTargets(side, locIdx, card)`**（同步版与分步版共用，返回**快照数组**）、单张 **`retriggerOne(card)`**（按**当前所在区域**重跑一张）、分步演出 **`applyRetriggerReveal(side, card)`**。逐条口径：

- **候选（四项排除）**＝结算那一刻**此牌所在区域**（`locIdx`）里**自己一侧**、`revealed`、带 `k`（`def.k` 非空）的卡牌；排除 ① **早苗自己** ② **法术**（`def.spell`——法术在**自身揭示结算完**就自行消散、根本不在场上，故天然不会被重触发）③ **`un` 占位卡**（隙间）④ **同为 `retrigger` 的卡**（另一张早苗 / `morph` 变身复制体）。第 ④ 项是**防死循环**（口径同 `morph` 的"变身目标是同样会变形的卡则不再二次变形"）：即使场上有多张早苗（自建卡组同名限 1 张，但哆来咪 `gs.shuffleN` 从卡池洗入、或 `morph` 变身都**可能带进第二张**），它们也**不会互相触发**，链条必然收敛。
- **只重触发「揭示」**：逐张调用 `applyEffect`，因此**所有**揭示键都会重跑——`bf`/`de`/`ba`/`bl`/`dw`/`dwb`/`dwh`/`dwc`/`spawn`/`spawnO`/`spawnS`/`spawnMine`/`clone`/`delCopy`/`gather`/`give`/`shuffleIn`/`discard`/`reviveDiscard`/`switch`/`gift`/`morph`/`xform`/`mv`/`roam`/`shift`/`costUp`/`energyNext`/`tkBuff`/`deAll`（**含落场 token 的揭示**，如「废弃列车」的 `dwh`）。**不触发**：`fx` 时机效果（turnStart / turnEnd / gameEnd / handEnd）、持续 `og`、`surv`/`phx`/`prot`/`ind`/`fly` 等非揭示机制；地形类 `gamble`（翻开时博彩）与 `gust`（揭示后吹飞）也**不重跑**——那两者是**地形**写的效果、不是卡面文字（本键是**卡面文字的重跑**，与地形无关）。
- **只作用于"结算那一刻已翻开"的卡**（沿用 `bf`/`de`/`ba` 的全局口径）：本区同侧**还没翻开的暗牌不吃**——暗牌翻面发生在阶段 ④ 的**翻牌顺序**里，故**排在早苗之后翻开的同区己方牌会错过**本次，之后也不会补触发（口径同 `dice`/`rally` 的"时机已过不补"）；反过来，先翻开的同区己方牌照常被重触发。**落场 token**（落地即翻开）与**已翻开后被移入本区**的卡都在候选内。
- **顺序＝本区 zone 数组顺序**（＝卡牌放入**本区**的先后；全场序 `fieldQueue` 不用于此）；每张结算**前**用 `fieldLocOf` 重读它**当前所在区域**再结算（口径同 `reviveDiscard`）：若前一张的揭示已把它挪出本区（如八云紫 `shift` 把整列搬到最右区、`mv`/`roam`/`gust` 挪位、`switch`/`gift` 换边），它**仍会被触发一次**、只是按**挪走后的新区域**结算；已不在场上（被 `dw` 摧毁、`phx` 回手）则**跳过**并记一条 `sys` 日志。⚠️ 这条是边界取舍（"本区卡牌"按**结算开始时的名单**快照认定），若日后想改成"离开本区就不再触发"，只需在 `retriggerOne` 里比对 `fieldLocOf` 与快照区域。
- **非"摧毁"/非增减/非放置**：本键**自身**不改战力、不动区域字段与格位（`sideUsed`/`sideRoom`/`fill`）、不触发 `surv`/`phx`/`prot`/`ind`、不进 `powerLog`/`fieldQueue`（**被重触发的那些效果当然各按自己的口径改盘面**——例如重触发 `de` 就照常 −N、重触发 `dw` 就照常走 `ind`→`phx`→`surv` 完整摧毁链）。
- **节奏（逐张、看得清楚）**：**正常翻牌流程走分步演出** `applyRetriggerReveal` —— 每张结算后 `renderZones()` 让 ±N / 生成 / 摧毁等演出显示出来，**相邻两张之间停一个固定间隔**（常量 `RETRIGGER_STEP_MS`，纯 JS 计时、无对应 CSS 关键帧，改节奏只改这一个数；口径同「集结」/「复活」，见《动画演出与间隔.md》§4「揭示再触发」）；`morph` 变身 / `fx` 时机效果 / 落场生成等**非翻牌路径走同步版**（`applyEffect` 的 `case 'retrigger'`：一次性结算、无分步节奏与逐步渲染）。两条路径共用候选收口 `retriggerTargets`；中断保护同 `applyShiftReveal`（重新开局 `state.gen` 变化时立即停止后续步骤）。
- **翻牌流程里的再触发走共用分派**：**翻牌流程里被再触发的每一张**不直接调同步版，而是走**共用分派** `resolveRevealInZone` → `resolveCardReveal`（收口 `retriggerOneStaged`）——因此它若是 `shift`/`gather`/`reviveDiscard` 等分步键，会**照常保留自己的分步间隔**（各键间隔见《动画演出与间隔.md》§4），而不是一次性同步结算。`retriggerOne`（同步版）只供**非翻牌路径**（`applyEffect` 的 `case 'retrigger'`：morph / fx / 落场生成——它们无法 `await`）使用；两条路径的**候选口径完全一致**，差别只在节奏。
- **与地形「守矢神社」（`repeatReveal`）的关系**：早苗**在守矢神社里翻开**时**她自己的揭示执行两次**；而**她每一次揭示所"再触发"出的那些揭示也发生在守矢神社里 ⇒ 那些揭示同样各自执行两次**。**总计 6 次**（同区另一张已翻开的揭示牌 A）：A 自身翻面 2 次 + 早苗第 1 次揭示再触发 A 2 次 + 早苗第 2 次揭示再触发 A 2 次 = **6 次**。完整口径见 §2「区域「揭示重复触发」效果」段。
- **失去卡牌文字**（封印 ∪ 静海）：早苗自己被抹除时本键**不发动**（`revealRound` 与 `applyEffect` 入口两道守卫，前者在该分步演出分支之前）；被重触发的**每张卡各自**再过一次 `applyEffect` 入口守卫 ⇒ 已失去文字的卡被重触发时同样不发动（每张牌首次拦截记一条日志，`card.muteNoted` 防刷屏）。
- **可作揭示，也可作时机效果**：与 `shuffleIn`/`discard`/`reviveDiscard` 同口径，走同一条 `applyEffect` 分支，故也可写成 `def.fx.turnStart/turnEnd/gameEnd` 里的条目（会走同步版）。
- **预判（`revealEffectWillChange`）**：接 `retrigger` 分支 —— 本区**存在**可再触发的己方已翻开卡牌（带 `k`、四项排除后非空）才为 `true`，否则跳过结算前的停顿（口径同 `gather`/`reviveDiscard`）；空转时同步版/分步版各记一条「本区没有可再触发揭示的其他己方已翻开卡牌」日志。
- **演出（简单快速、看得出"她放了一次光环"）**：本键每次结算**之前**先把演出**排进渲染队列**（调用点＝`applyEffect` 的 `case 'retrigger'` → `queueRetriggerFx`，故**翻牌分步版与同步版共用**），由 `renderZones()` 末尾的 `flushRetriggerFx()` 播出（排队与 DOM 是否已渲染无关）：① **早苗卡面一圈淡绿光环扩散**（`RETRIGGER_AURA_MS`）；② **被再触发的每张目标卡各闪一下**（`playRetriggerHit`，`RETRIGGER_HIT_MS`，**同一刻一起闪**，不是在各自那个间隔时点分开闪——这样"一组光环 + 一轮闪光"好数）。**守矢神社里打出早苗**时本键结算两次 ⇒ **光环与闪光各来一轮**，这正是"分辨她两次揭示分别何时触发"的依据（两次演出**同款、不加文字标记**）。**不额外插入任何等待**：翻牌流程每张结算后本就 `renderZones()`（排队的演出随即播出；口径同 `flushBuffFlash`），故既有节奏、守矢神社那一道停顿、以及"总计 6 次"的账**完全不变**。**纯演出、零玩法影响**（不改数据、不进日志、不参与判定；`el.animate` 不可用时整段跳过，jsdom 冒烟环境不加延时）——形态、时长常量、悬浮层 / z-index、跳过条件与已知问题见《动画演出与间隔.md》§4「早苗「揭示再触发」的可见演出」。
- **使用者**：**「东风谷早苗」（5 费 / 6 战力，无阵营，🌾，`assets/cards/sanae.png`）**。

**区域「出现时」效果（字段 `spawn`，入口 `runLocAppearEffect`）**：地形“出现”时给双方各生成卡牌：① `{ card: SPECIAL 键名, n }` 生成指定特殊卡（虹龙洞→石块、幽灵洋馆→幽灵）；② `{ cost, n }` 从 `POOL[cost]` 随机抽人物卡（妖精神社→随机 1 费卡；每张独立抽取、双方可能不同；池内 `un` 与 `occ>1` 卡排除）。均走 `placeToken`：落地即翻开、占格位、进场上放置顺序队列，播“凝聚显形”。`spawn.reveal` 缺省＝不触发揭示（只吃 `og`/`fx`/`surv` 等实时机制，同「幽灵」口径）；`reveal: true`＝生成后立即结算这些卡自身的揭示（妖精神社抽到「大妖精」当场给同区双方已翻开卡 +1），顺序＝落场顺序（先你方后敌方、同 n>1 按生成先后），按各卡当前所在区域结算，属同步结算（同 morph/fx 非翻牌路径，无停顿与逐张翻牌演出，±N 气泡/战力影响历史/日志照常）；摧毁型揭示（`dw`/`dwh`）开此开关后在生成当刻生效。时机三处：①地形揭晓（`locationRevealStage`）、②区域被 `xform` 变成该地形、③开发者「🗻 指定地形」替换该列（可勾选关闭）。

**区域「翻开时」效果（字段 `gamble`）**：区别于「出现时」（地形被揭晓/变形那一刻，一次性）——这是卡牌在地形里被翻开的那一刻逐张触发，入口 `runLocRevealEffects`，由阶段 ④ `revealRound` 在每张暗牌 `revealed = true` 之后、该卡自身揭示之前调用。现仅驹草赌场 `gamble: 1`：该卡永久随机 +1 或 −1 战力（`Math.random() < 0.5` 各半），走 `applyPermBuff` 收口（±N 气泡 + 战力影响历史按来源记地形名），记一条日志（赌涨绿色 `sys`、赌跌红色 `danger`）。①只作用于“在本区被翻开”的卡：落地即翻开的落场 token（石块/厄运/分身）与已翻开后被移入本区的卡（`mv`/`fly`/`shift`/换边）不参与，地形出现前已翻开的旧卡不追溯；②±N 先于自身揭示，故 `bl` 落后判定/`oc` 按博彩后威力算；③`morph`（变身重新触发新卡揭示）与 `fx` 时机效果不是“翻牌”，不经过本入口；④被摧毁回手后再打出（妹红 `phx`）会重新博彩，永久 buff 可累积；⑤非“摧毁”，带 `surv`/`phx`/`prot` 的卡照常参与。

**区域「回合结束崩塌」效果（字段 `collapse: { cards, to }`）**：每回合翻牌结算后，在地形类回合结束效果的最后一步（`locCollapseEffects`，早于场上 `fx.turnEnd`）检查：本区域双方总卡牌数 ≥ `cards`（按张数计：`occ` 大体积卡也算 1 张，暗牌与落场 token 都算；隙间不在 `zone` 数组故不算）则把本区域地形整体换成 `to`：`state.locs[j].def` 换新 → `refreshLocHeader` 刷新列名/图标/效果文案/配色 → 变形＝该地形在本区“出现”（立刻结算 `runLocAppearEffect`，如冥界无 `spawn` 则空操作）→ 记一条红色日志。①已放卡不移动、不增删（与地形揭晓/`xform` 一致）；②换掉后本区不再带 `collapse` 字段，只会崩塌一次；③任一方占格数超过目标地形上限则不崩塌（记日志）；④新地形从下一回合起按其规则参与（同一回合不再触发新地形的回合结束类效果）；⑤触发源是本区卡牌数量，而不是地形被揭晓/被 `xform` 指定。

**区域「揭示后吹飞」效果（字段 `gust`）**：与「翻开时」（`gamble`，在自身揭示之前）配对——入口 `runLocAfterRevealEffects`，同一张牌在阶段 ④ 里自身揭示效果结算完之后才结算：现仅魔力风暴 `gust: true`，把该牌「若可能」移动到另外一个随机区域（移动核心 `moveCardToRandomZone` 与 `roam` 效果键共用：目标区须已开放 `locOpen` 且该侧空余 ≥ 占格数 `occ`；都不可达则留在原地并记日志）。①只作用于“本回合在该区被翻开”的卡（走 `revealRound` 的暗牌）：已翻开的旧卡、落地即翻开的落场 token（石块/厄运/分身等）、被移入本区的卡（`mv`/`fly`/`shift`/换边）都不受影响，地形出现前已翻开的旧卡不追溯；②发生在自身揭示之后，本次揭示结果不受影响（与 `gamble` 相反）；③若该卡自身的揭示已把它挪出本区（八云紫 `shift` 把卡搬到最右区），则不再吹；④换边类（`switch`/`gift`）换的仍是同一区域，故照常被吹到另一区（归属已变，按新归属方该侧空位判定）；⑤移动不改变归属/揭示状态/场上放置顺序队列，移动后各区域总点数与放满加成实时重算，播“滑行+缩放”飞行演出（`flushPendingDriftFly`）；⑥非“摧毁”，带 `surv`/`phx`/`prot` 的卡照常被吹。

**回合结束结算顺序（先地形、后卡牌）**：每回合翻牌结算后先执行 ⑤-0 区域（地形）回合结束效果（`runLocTurnEndEffects`）：① 战力成长/衰减（`locTurnEndPowerEffects`：`grow` 成长 +N，如寺子屋；`decay` 衰减 −N，如间歇泉，本区双方所有已翻开卡牌永久 ±N）→ ② 定时掷骰（`locDiceEffects`：`dice: {turn,n}`，如骰子赌桌在指定回合末让本区所有卡牌各自随机永久 ±N）→ ③ 定时加成（`locRallyEffects`：`rally: {turn,add}`，如演唱会在第 5 回合末让本区双方所有已翻开卡牌永久 +add）→ ④ `purge` 回合末摧毁（`reactorPurge`，存在免摧毁 `prot` 时跳过）→ ⑤ 崩塌（`locCollapseEffects`：`collapse: {cards,to}`，如幽明结界在双方总卡牌数 ≥6 时把本区变成冥界）→ `gap` 封格（`locGapEffects`）；再执行 ⑤ 全场「回合结束」卡牌效果（`runTurnEndEffects` → `resolveTimedEffects('turnEnd')`，按 `fieldQueue` 放置顺序）。因此地形总是先改动盘面：本区先被 ±N（或被摧毁），随后结算的 `fx.turnEnd` 卡读到的是改动后的实时威力（`cardPowerIn`）。同一块地形只带 `grow` / `decay` / `dice` / `rally` / `purge` / `collapse` 其中一个字段（`grow` 与 `decay` 同带则相互抵消）；崩塌放在地形类效果的最后一步——本回合先按原地形结算，新地形从下一回合起参与。第 6 回合同样先跑 ⑤-0 / ⑤ / ⑥，再进入 ⑦ 游戏结束效果与终局结算（成长/衰减/掷骰结果计入终局点数）。

**地形揭晓系统（开局流程；代码入口 `locationRevealStage`）**：开局按 `pick` 权重抽定三块真实地形（互不相同）预存于 `state.locPlan`，三列先一律以「未揭示」占位地形（`EXTRA.unreveal`，id `unreveal`：max 4 / 无效果 / 样式同无名之丘）展示；第 t 回合开始时揭晓第 t 列（t=1/2/3 → 左/中/右）：①换上真实地形（max/加成/反转/purge/grow/decay/gamble/dice/rally/gust/collapse/prot/minTurn 等字段与列头配色即时生效）；②结算该地形「出现时」生成（`spawn`：虹龙洞给双方石块、妖精神社给双方各 1 张随机 1 费人物卡）；③此前已放卡不移动、不增删。未揭示列可正常放牌（上限 4；列下提示「🃏 第 N 回合揭晓」）。限张超限口径：若揭晓成上限 <4 的地形（迷途竹林 max 2）而某侧已放超过上限（仅第三列可能：前两回合每侧至多放 3 张），不摧毁不移走、卡保留原格位——隙间只铺在“空置的不可用格位”，数量 = 4 − max(已放数, 上限)（放 3 张 → 1；放满 4 张或大体积卡占满 → 0；见 `buildZoneChildren`），此后该侧按已满处理。换场演出：揭晓时把“未揭示”外观整列克隆到悬浮层淡出，下方真实地形随之显形（形态、时长与边界见《动画演出与间隔.md》§3「地形揭晓换场」）。

**区域「定时变形」效果（字段 `xformTurn: { turn }`，现仅「秘封俱乐部」）**：第 `turn` 回合的回合开始时结算（阶段 ①-0b：`roundStartStage` 里紧接 ①-0 地形揭晓 `locationRevealStage`、先于 ①-1 全场「回合开始」卡牌效果 `runTurnStartEffects`）——入口 `locXformTurnEffects`，逐列（左→中→右）检查本列地形是否带 `xformTurn` 且 `state.turn === xformTurn.turn`：①把该列地形整体换成随机目标地形（`state.locs[j].def` 换新 → `refreshLocHeader(j)` 刷新列名/图标/效果文案/配色 → 记一条 `sys` 日志）；②变形＝该地形在本区“出现”，立刻 `runLocAppearEffect(j, target)` 结算其「出现时」效果（无 `spawn` 则空操作，如变成冥界/无名之丘）；③调用 `renderZones()`，隙间 / 锁定遮罩 / 点数横幅随新地形即时刷新。①候选范围＝`LOCATION_POOL` 里除自身以外的全部地形，允许与另外两列当前地形重复；`EXTRA` 的非随机地形（「未揭示」）不入候选，故绝不会变成未揭示态；②不做上限防御：抽中「上限放不下本区已放卡」的地形（迷途竹林 `max:2` 而某侧已放 3 张）照常变形，口径同地形揭晓的超限处理——已放卡不移动、不增删、不摧毁，隙间只铺在“空置”的不可用格（`buildZoneChildren`：隙间数 = 4 − max(已放卡数, 上限)），该侧此后按已满处理；与 `xform`（鬼人正邪）的“任一方占格超过目标上限则变形失败”刻意相反；③只变形一次：换掉后本区地形是目标地形、不再带 `xformTurn` 字段，同一块地形一局最多结算一次；④新地形从变形那一刻起完全生效——含同一回合末的地形类回合结束效果（第 5 回合末照常跑 `grow`/`decay`/`dice`/`rally`/`purge`/`collapse`；变成「演唱会」则第 5 回合末照常 `rally +2`，变成「聚变反应炉」第 5 回合末照常摧毁最低牌）；⑤不补结算：若该地形是在第 `turn` 回合开始之后才落到本区的（`xform` 区域变形、开发者「🗻 指定地形」），该时机已过、本次不再触发（口径同 `dice`/`rally`）；⑥非“摧毁”/非增减类：不改任何卡牌的战力与格位（`sideUsed`/`sideRoom`/`fill`）、不触发 `surv`/`phx`/`prot`/`ind`、不进 `powerLog`（②中生成的 token 走 `placeToken` 既有口径：落地即翻开、占格位、进 `fieldQueue`，并跳过当回合的「回合开始」效果）。与另外两个“变形”机制的分工：`xform`＝卡牌揭示时指定目标、超限则失败；`collapse`＝回合末按本区卡牌张数达标触发、目标指定、超限则不崩塌、放在地形类回合末效果的最后一步（同一回合不触发新地形的回合末效果）；`xformTurn`＝回合开始时触发、目标随机、超限照常变形、新地形当回合即全量生效。

**区域「回合结束封格」效果（字段 `gap: N`，现仅「八云紫的家」）**：每回合翻牌结算后在阶段 ⑤-0 地形类回合结束效果的最后一步（入口 `locGapEffects`，排在 `collapse` 之后、早于场上 `fx.turnEnd`）逐列检查本列地形是否带 `gap`，再对双方分别判定：某侧在本区还有空位（`sideUsed(side, j)` < 该侧当前可用格数 `locSideMax(side, j)`）就把该侧已封隙间数 +N（缺省 1，至多封到“刚好放满”），否则本次不加并记日志例外（有牌被摧毁/移走腾出空位后，下一个回合末继续加）；两侧都无变化时不刷日志（与 `purge`/`dice`/`rally` 一致）。①容量级、不塞卡：`state.locs[j].gaps = { p, a }` 记双方各自的已封格数（`locGaps`），该侧可用格数 `locSideMax = max(0, 地形 max − 已封数)`；渲染层只把「隙间」铺在“空置的不可用格”（`buildZoneChildren` 用 `locSideMax(side, locIdx)` 判定 `i >= 可用格数`），表现是最靠后的那一格先变灰、逐回合往前推（即“从后往前”）；`zones`/`zone` 数组、`zoneTotals`、`powerLog`、`fieldQueue` 全不受影响，隙间也不会被任何摧毁/移动/换边效果选中。②所有“还能放几张”的判定统一读 `locSideMax`：`sideRoom`（放牌 / `placeToken` 落场生成 / `mv`·`fly`·`shift`·`roam`·`gust` 移动 / `gather` / 复活落点等）、`occZoneOk`（大体积卡需该侧可用格数恰为占格数，可选第 3 参 `side`；不带 side 时按两侧较大的可用格数兜底）、`zoneFillBonus`（`fill` 按可用格数判定，可用格数为 0 时恒不生效）、`morph` 变身大体积卡的合法性、`undoFlyMoves` 的回收判定、渲染层的 `N/可用` 与格位。③双方分别判定：两侧封格数可以不同（某侧放满就不再封，另一侧照封）；因封格只在“还有空位”时发生，某侧封格数恒不会超过它“曾经空着”的程度（已占格 ≤ 可用格数恒成立）。④下限 0：可封到某侧一格不剩（该侧此后在本区放不了牌、也不再生成 token；已有卡保留、照常计分、照常吃 `grow`/`decay`/`dice`/`rally`/`purge`），到 0 后条件恒不成立、自然不再加。⑤换地形即清空：`xform`（鬼人正邪）/`collapse`（幽明结界）/开发者「🗻 指定地形」/`xformTurn`（秘封俱乐部）四处换地形的收口都调 `resetLocGaps`——隙间属于「八云紫的家」这块地形，不被带到新地形上；地形揭晓时隙间从 0 开始。⑥与「限张超限隙间」的区别：超限隙间是“已放卡数 > 地形上限”的渲染结果（卡不删、隙间减少），本机制的封格是主动减少可用格数，两者共用同一渲染出口但来源不同（详见 `docs/现有地形.md` 的「隙间」两种来源注）。

**区域「免减攻」效果（字段 `noDown: true`，现仅「蓬莱药局」）**：本区域所有卡牌（双方、含暗牌与落场 token）无法被减少战力——一切“负的战力增量”在生效前被拦下：战力原封不动、不写进战力影响历史（`powerLog`）、不播 −N 演出，只记一条 `sys` 日志说明“免于减攻”。实现：唯一收口 `applyPermBuff(card, d, …)`（返回布尔：`true` = 已结算 / `false` = 被拦下）在 `d < 0` 且 `cardNoDown(card)`（该卡此刻在场上、且所在区域带 `noDown`，按 `fieldLocOf` 实时查）时直接返回 false、不动任何数据；调用方据此调整汇总日志（`de`/`deAll`/`reset` 记“另有 N 张被拦下”、`decay`/`dice`/`gamble`/`rally` 逐张跳过或标注、`surviveDestroy` 走专分支）。覆盖范围（所有会让本区卡牌战力下降的效果）：①卡牌揭示类 `de`（本区敌方 −N）/`deAll`（敌方全场 −N）/`reset`（战力归位里“往下修”的那部分）；②地形类 `decay` 衰减 / `dice` 掷出负 / `gamble` 掷出负 / `rally` 的负 `add`；③其它走同一收口的负差：`surv` 防摧毁的“替代降攻”、分身/衍生物与本体战力对齐时的负差（`hecatiaC`/`discardGiveTokens` 的差额写法若为负同样被拦）；④实时负加成也一并抹平：`locRoleBonus` / `locCostBonus` / `locAllBonus` / `cardAuraBonus` 在 `noDown` 区域把负值按 0 计（如本区带 `all:-2` 时本区卡牌不吃这 −2；当前无负值地形，属防御性兼容），且「战力影响历史」面板（`powerHistoryRows`）同口径，保证“面板合计 = 场上当前威力”。边界：①不追溯、不恢复——地形出现前已经吃到的减攻留在卡上（`buff` 里的负值照常计入战力），只拦“结算那一刻人在本区域”的卡；卡被移出本区（`mv`/`fly`/`shift`/`gust`/换边）或离场后立即不再受保护，换地形（`xform`/`collapse`/开发者指定地形/`xformTurn`）后该列也立即失去保护。②不是“摧毁”类：与 `surv`/`phx`/`prot`/`ind` 无耦合——`dw`/`dwh`/`dwb`/`purge` 照常能摧毁本区卡牌；但 `surv` 的“替代降攻”被拦下时，该卡不离场、也不降攻（两个防护叠加，日志写明“替代的 −N 也被一并拦下”）。③卡的印刷负战力不算“被减攻”：厄运（−3）/ 水银（−1）进本区照常是负战力；对方用 `spawnO` 之类往本区塞这类负战力 token 也照常（那是“放入新卡”，不是“减少已有卡的战力”）；`un`（隙间）与法术本来就免疫/无战力。④不影响区域口径：`dbl`/`inv`/`fill` 与终局结算照常；也不阻止“卡牌被摧毁导致区域总点数下降”。

**「失去卡牌文字」效果（两种来源：区域字段 `mute: true`「静海」/ 卡牌效果键 `mute`「封印」）**：被抹除的卡**卡面写的效果一律视为不存在、任何时机都不发动**；它仍是正常卡牌（照常占格、计战力、可被增减 / 摧毁 / 移动 / 换边），只是“哑巴”。两种来源：
- **区域抹除**（地形字段 `mute: true`，现仅「静海」）：本区域所有卡牌（双方，含暗牌、落场 token 与法术）失去文字。**实时读法、零状态**（同 `gap`/`noDown` 的思路，不写卡的任何数据）⇒ 静海被换掉（`xform` / `collapse` / `xformTurn` / 开发者「🗻 指定地形」）或卡被移出本区（`mv`/`fly`/`shift`/`roam`/`gust`）时文本自动恢复，不需要收尾代码。
- **卡级抹除**（卡牌效果键 `mute`，游戏内叫**「封印」**，现由 2 费法术「阴阳玉」与 3 费法术「生神停止」使用）：**永久**——标记落在**卡实例**上（`card.muteP`，同 `card.buff` 的永久口径），整局有效：被摧毁后再复活、`phx` 回手再打出、换边、`morph` 变身、`shuffleIn` 洗回牌库全都保持，**离开静海也不恢复**；不设任何免疫（目标此刻在静海内也照常结算）；目标**已被封印**时照常再抹一次（不改打下一张、不算落空）。⚠️ 封印的是**整张卡的文本**（含它自己的揭示）——被封印的卡此后连 `retrigger`（东风谷早苗）也再触发不了它的揭示（逐张重触发时每张各自过 `applyEffect` 入口守卫）。子句与目标口径见 §1 的 `mute` 行。

判定（守卫用前两个、渲染与文案用第三个，全部只读、无一处写状态）：`locMuted(locIdx)`＝该列地形带 `mute`；`cardMuted(card)`＝**卡级标记 ∪ “此刻在场上且所在区域带 `mute`”**（按 `fieldLocOf` 实时查；手牌 / 牌库 / 三池里的**同名**卡不受**区域**抹除影响，但**封印认实例**）；`cardSealed(card)`＝只认卡级永久标记（手牌 / 三池里也照样显示 ❗ 与置灰）。日志收口 `muteSkipLog(card, kindTxt)`（每张牌首次被拦截时记一条 `sys` 日志，`card.muteNoted` 标记，避免刷屏；⚠️ **两种来源同时满足时只提示一次、优先报「封印」**——不可逆的那个更该让玩家知道）。
守卫点：① `applyEffect` 入口——覆盖揭示 / `fx` / `morph` 重新触发 / 落场法术 `settleFieldSpell` / 集结与复活等所有连锁路径；② `revealRound`——含 `shift`/`gather`/`reviveDiscard`/`retrigger`/`delCopy` 五个走分步演出的键（会绕过 `applyEffect` 入口，故单列一道守卫；翻面 / 占格 / 计战力照常，只是效果不发动。⚠️ `retrigger` 逐张重触发时，被重触发的每张卡各自还会再过一次 `applyEffect` 入口守卫，故被抹除的卡被重触发时同样不发动）；③ `resolveTimedEffects`（带时机名的日志；错过的时机不补结算）；④ `revealEffectWillChange`（被抹除 → 返回 false，不空等结算前的停顿）；⑤ `cardAuraBonus` + `powerHistoryRows`（**源卡**被抹除（封印 ∪ 静海）⇒ 该 `og` 光环整条不计；两侧同口径，保证“面板合计 = 场上威力”）+ `cardZoneMul`（同一判据：源卡被抹除 ⇒ 区域倍率整条失效）；⑥ `locNoDestroy`（**卡级** `prot`「蕾蒂」被抹除后不再提供区域免摧毁；⚠️ 地形级 `prot`（睡鼠神祠）不受影响——那是地形效果、不是卡面文字）；⑦ `isDestroyable` / `indestructibleBlock`（`ind` 失效 ⇒ 照常摧毁，且不再“判定结束、不改打别的”）、`surviveDestroy`（`surv` 失效 ⇒ 不降战力替代、直接离场）、`phoenixRevive`（`phx` 失效 ⇒ 不回手翻倍、直接离场）；⑧ `uiMoveFly` / `tryMoveFlyTo` / 渲染层 `canFly`（`fly` 失效：不再显示「⇄ 移动」、点击也不进入移动模式）；⑨ 显示层（见下文口径⑦）。
口径：①只抹除“文本”：印刷费用 `def.c`、基础威力 `def.p`、阵营 `g`、`occ` 大体积占格、`tk` 标记都照常（静海里的萃香仍占 4 格、被封印的石块仍被天子 `og` 匹配）；②区域类效果不受影响（地形写的、不是卡面文字）：`aff`/`cb`/`all`/`fill`/`inv`/`purge`/`grow`/`decay`/`dice`/`rally`/`gamble`/`gust`/`gap`/`noDown`/`prot` 照常；③不追溯、不补结算：生效前已结算的永久效果留在卡上（`buff` / `powerLog` 不回滚），期间错过的揭示 / 时机效果不补（口径同 `dice`/`rally`）——**封印也不追溯**，只影响此后；④手牌 / 牌库侧机制不受影响：`costDown`（纯狐，在手牌/牌库里就生效）、`costDownP`（星熊勇仪，同上；数的是自己场上的状态，与它自己在哪个区域无关）、`gs`（哆来咪，开局在卡组即触发）、`playReq`（大鲶鱼，只在“手牌→场上”那一刻校验，打出后不再追踪）——但**封印是卡实例状态、随卡走**，被封印的牌回到手牌后再打出仍不发动揭示；⑤法术：揭示不发动，但照常消散（消散不是卡面文字，仍进放逐池）；⑥不是 `un` 占位卡：照常占格、计战力、可被增益 / 削弱 / 摧毁 / 移动 / 换边，`dw`/`dwh`/`dwb`/`dwOwn`/`dwc`/`purge` 的候选与筛选口径完全不变（按威力 / 按印刷费用照选它）；⑦显示：**封印**（卡级永久）在**场上卡面 / 手牌 / 三池面板 / 放大视图**四处叠 ❗ 并把艺术区与效果文字置灰划线（放大视图另有「☯️ 此牌已被「封印」…」提示条）；**静海**（区域实时）只改放大视图（卡面效果文字与详情说明置灰划线 + 一行「🌊 文本已被「静海」抹除…」，场上靠地形配色区分）；图鉴（`card-browser`）与卡组页（`deck-page`）按 `def` 渲染、一律不显示 ❗；⑧AI 未收录：AI 仍按“效果照常”估值，可能在被抹除的卡上高估持续效果——只影响 AI 的选牌观感，不影响玩家侧的结算正确性。

**区域「封锁揭示」效果（字段 `noReveal: true`，现仅「法界」）**：本区域双方所有卡牌（含暗牌、落场 token 与法术）的**揭示不发动**——卡面写的揭示视为没写（不发动、不产生任何变化、也不空等结算前的 400ms 停顿），但它仍是正常卡牌（照常占格、计战力、可被增减 / 摧毁 / 移动 / 换边）。**实时读法、零状态**（同 `mute`/`gap`/`noDown` 的思路，不写卡的任何数据）⇒ 法界被换掉（`xform` / `collapse` / `xformTurn` / 开发者「🗻 指定地形」）或卡被移出本区（`mv`/`fly`/`shift`/`roam`/`gust`）时不再被拦，不需要收尾代码。
- **只封揭示**：持续 `og`、时机 `fx`、防护（`surv`/`phx`/`prot`/`ind`）、`fly`、`costDown`/`gs`/`playReq`、印刷费用与威力、`occ` 占格与 `tk` 标记、区域类效果（`aff`/`cb`/`all`/`fill`/`inv`/`purge`/`grow`/`decay`/`dice`/`rally`/`gamble`/`gust`/`gap`/`noDown`/`prot`）、摧毁候选与筛选口径全部照常（与静海 `mute` 抹除**整张文本**刻意相反）；法术揭示不发动但**照常消散**（消散不是卡面文字，仍进放逐池）。
- **不追溯、不补结算**（同 `dice`/`rally` 的“时机已过不补”）：被拦下的**那一次**揭示不会在卡离开法界后补发动——“恢复”只指**此后**的揭示：被 `retrigger` 再触发、`morph` 变身、复活与回手再打出的重新结算、守矢神社重复揭示时照常发动（每张牌首次被拦记一条 `sys` 日志，`card.nrNoted` 防刷屏）。

判定（只读、无一处写状态）：`locNoReveal(locIdx)`＝该列地形带 `noReveal`；`revealBlocked(card)`＝“此刻在场上且所在区域带 `noReveal`”（按 `fieldLocOf` 实时查；手牌 / 牌库 / 三池里的同名卡不受影响）；日志收口 `revealSkipLog(card)`。守卫点：① `applyEffect` 入口的**揭示分支**（`spec` 缺省＝揭示，覆盖 `morph` 重新触发 / 落场法术 `settleFieldSpell` / `spawn.reveal` / 复活 / 同步版 `retrigger`；⚠️ `fx` 时机效果带 `spec`、**不**受影响）；② `resolveRevealInZone`（揭示收口：翻牌主路径 + 守矢神社重复的第 2 次 + `retriggerOneStaged` 再触发的每一条揭示；五个分步演出键 `shift`/`gather`/`reviveDiscard`/`retrigger`/`delCopy` 也在这里、`resolveCardReveal` 之前被拦）；③ `revealEffectWillChange`（被封锁 → 返回 false，不空等结算前的停顿）；④ 显示层：放大视图给纯揭示牌整体置灰划线 + 一行「🌑 揭示已被「法界」封锁…」（`revealBlockNoteHTML`）；场上靠地形配色（墨黑、地名纯白）区分，**不**叠 ❗（❗ 只标**封印**）——显示口径与静海一致。

**区域「出现时摧毁另外两块地形」效果（字段 `shatter: true`，现仅「天界」）**：天界在本区「出现」的那一刻，把另外两块地形连同其上的所有卡牌一并摧毁，本局此后只剩本区域可用；被摧毁的两列变成「**已破碎**」。触发时机＝与 `spawn` 完全同一套「出现时」：①地形揭晓（`locationRevealStage`，第 1/2/3 回合开始）；②卡牌 `xform`（`applyEffect` 的 `case 'xform'`）；③地形 `xformTurn`（`locXformTurnEffects`——随机候选里包含天界）；④地形 `collapse`（`locCollapseEffects`，目标带 `shatter` 时）；⑤开发者「🗻 指定地形」（`uiOnPickLocConfirm`，可勾选关闭）。收口函数：`runLocAppearEffect` 末尾调 `startShatterChain(idx, def)` 启动链条，另有 `runShatterChain`（编排）、`shatterZoneCards`（逐张摧毁某区所有卡）、`shatterZoneTerrain`（摧毁地形本身）、`awaitShatterChain`（等待）、`locShattered`（判定）、`renderShatteredColumn`（整列渲染）。节奏：逐块、左→右（按列下标升序，跳过本列与已破碎列），每块两阶段——①依次摧毁该区的所有卡（顺序＝`fieldQueue`，与其它摧结束算同口径：谁先放谁先碎；每张播 `playShatter` 的「分崩离析」演出）→ ②摧毁该地形本身（该列变「已破碎」）；两块之间再到下一块。逐张 / 逐阶段的间隔常量（`SHATTER_CARD_MS` / `SHATTER_TERRAIN_MS` / `SHATTER_NEXT_LOC_MS`）、以及“间隔短于分崩离析动画 ⇒ 相邻几张碎裂演出重叠（观感＝连续爆裂、一口气全碎）”的口径见《动画演出与间隔.md》§4「天界摧毁链」。

保护一律无视：`shatter` 对卡牌的摧毁刻意绕过全部四条防护——区域级 `prot`（睡鼠神祠）与卡级 `prot`（蕾蒂，提供区域免摧毁）、卡级 `surv`（灵乌路空，防摧毁→替代降攻）、`phx`（藤原妹红，凤凰重生回手）、`ind`（佛体金刚石，自身不可摧毁）全部不生效、不播任何替代演出（整块区域都不存在了）。因此 `shatterZoneCards` 不调用 `locNoDestroy` / `indestructibleBlock` / `surviveDestroy` / `phoenixRevive`，只走 `recordDestroy` → 移出区域 → `dequeueField`。被摧毁的卡照常进归属方的摧毁池、照常计入纯狐 `costDown` 的 `destroyCount()`。含暗牌与落场 token（石块/厄运/分身/河童…）与场上的法术，一视同仁。

「已破碎」区域：地形换成 `EXTRA.shattered`（`id: 'shattered'`、`max: 0`、`wt: 0`、无任何效果字段）并在 `state.locs[j].shattered` 上打标记（判据＝标记 ∨ 占位地形 id，`locShattered` 双保险）；渲染层把整个列元素换掉为 `.location.shattered-loc > .shatter-block`（`renderShatteredColumn`，同时把 `Game._els` 里该列的 `cols`/`oppZone`/`mineZone`/`totA`/`totP` 换成游离占位节点以免其它渲染路径报错），看不出原本是哪块地形、没有双方总点数的数字、也没有格位（只写「已破碎」）；`renderZones` 对该列整列跳过。效果上：`locSideMax` → 0、`locOpen` → false ⇒ `sideRoom`/`occZoneOk`/`zoneFillBonus`/格位全部作废，双方（含 AI，它同样读 `sideRoom`/`locOpen`）都不能再在该区放牌 / 移动 / 落场生成 / 复活；`zoneTotals` 恒 0；终局 `finishMatch` 不计入赢下的区域数与三区总点数（跳过该列并输出一行「⚡ 区域 N：已破碎（不计分、不参与胜负）」）、`playEndHighlights` 跳过该列放大高亮——只剩天界一个区域参与判定：该区不平时按其胜负定局（`pw`/`aw` 自然为 1:0 或 0:1），该区平手则 `tie > 0` 且 `pTotal == aTotal` ⇒ 整局平局（赌注不变）。

永久锁定 + 不重复摧毁：已破碎的列不会被卡牌 `xform`（`case 'xform'` 首道守卫）、地形 `xformTurn`（`locXformTurnEffects` 列首跳过）、`collapse` 崩塌（`locCollapseEffects` 列首跳过）、开发者「🗻 指定地形」（`uiOnPickLocConfirm` 弹窗内红字提示「永久锁定」）任何一条路径再换地形；`runShatterChain` 构造目标列表时跳过已破碎的列，两列都已破碎则该次「降临」无事发生（只记一条日志）。⚠️ 天界自己（存活的那一块）照常可以被任何路径换掉（换成别的地形后新地形正常生效），已破碎的两列永久保持破碎。

异步节奏与状态：整条摧毁链是一个单例 Promise（`shatterChain`；`startShatterChain` 已有链条时直接复用、不重复启动，收尾时按 `shatterChain === p` 判定再清空，避免上一局的链条在 `restart` 之后误清新一局的链条；收尾渲染自带 `try/catch`，因为本链条可能是“未被 await 的后台播”）。正常对局的四条路径一律 `await awaitShatterChain()`：`locationRevealStage`（①-0）、`roundStartStage` 的 `runTurnStartEffects` 之后（①-1）、`locXformTurnEffects`（①-0b）、`locCollapseEffects`（⑤-0），外加 `revealRound` 每张牌结算后（覆盖 `case 'xform'` 这条同步路径）、`playRound` 的 ⑤/⑥ 之后与 ⑦ `runGameEndEffects` 之后。为此 `roundStartStage` / `locationRevealStage` / `locXformTurnEffects` / `runLocTurnEndEffects` / `locCollapseEffects` 为 async，`playRound` 对应 `await`。⚠️ 开发者「🗻 指定地形」`uiOnPickLocConfirm` 是唯一例外的“不等”路径（保持同步）：它只启动链条就立刻 `renderZones()` + `setStatus()` + `closePickLoc()` 关窗，逐张摧毁的演出在后台继续（链条每摧毁一张自带一次 `renderZones`）——若在此 await，弹窗会一直挂到两块地形都拆完才消失。⚠️ 若被摧毁的那一列正是「虚假之月」，`shatterZoneTerrain` 会调 `syncRoundTotal('天界摧毁地形')` 让本局总回合数当场退回 6。

AI 侧（`js/ai.js`）：影子盘面的 `mdRoom` 按数值判定（缺 `max` 才是 4，`max: 0` 即为 0 空位）。AI 的落牌候选与提交复核分别走 `sideRoom`/`locOpen`（简单档 `aiThinkLegacy` 的候选枚举、新引擎提交前的校验），这两处已被 `locSideMax → 0` / `locOpen → false` 挡住，故 AI 不会往已破碎的区域放牌；AI 的地形投影只读 `dbl`/`inv`/`max`/`fill`/`wt` 等字段，破碎地形 `max 0`、`wt 0`、无其它字段，投影自然把该区视为「不可争夺、权重 0」。

换边演出：`switch`（依神紫苑）与 `gift`（因幡帝送己方最低卡）换边时，与移动同款播放“滑行 + 缩放”克隆飞行（`flyCardTo`，通过 `pendingSwitchFly`/`flushPendingSwitchFly` 在换边后的渲染时触发；时长见《动画演出与间隔.md》§3「飞行」）。

卡级“每回合移动一次”（`fly: true`，现仅射命丸文）：该牌已翻开且仍在己方场上时，每个出牌阶段可把它移到另一区域一次——点该卡进入"选择目标区域"，再点目标列移动；目标必须未满且已开放（不点不放能量）；每回合一次（`flyMoved` 记录），下回合重置；AI 也会使用该能力（困难 / 噩梦档：移动走同一套估值，只有确实能改善局面才走一步并播同款飞行演出；普通档仍不使用）。移动时播放与八云紫 `shift` 同款的“滑行 + 缩放”飞行克隆动画（`flyCardTo`）。

**区域「揭示重复触发」效果（字段 `repeatReveal: true`，现仅「守矢神社」）**：凡在带本字段的区域里发生的「揭示结算」都执行两次（第 1 次照常 → 停顿 → 第 2 次「重复」，间隔见《动画演出与间隔.md》§4「守矢神社」）；只针对揭示（持续 `og`、时机 `fx`、防护替代类一次都不跑）。卡面/地形文案＝「在此区域翻开的揭示牌：其揭示效果再重复触发一次」。引擎侧唯一收口 `resolveRevealInZone(side, locIdx, card, forceRepeat)`（`js/game.js`，紧邻 `resolveCardReveal` 与 `runLocAfterRevealEffects`）：先按 `resolveCardReveal` 执行第 1 次，再按 `forceRepeat`（翻牌路径＝快照）或实时读区域（再触发路径）决定是否补第 2 次。调用方两条：① `revealRound`（暗牌翻面那一次，传翻开瞬间的快照 `repeatRevealHere`）；② `retriggerOneStaged`（早苗再触发的每一条揭示）。

- 两种触发来源：㈠在本区翻面的暗牌（暗牌翻面那一刻，口径与 `gamble`/`gust` 完全一致）：落地即翻开的落场 token（石块 / 厄运 / 分身 / 龙玉…）、「复活弃牌池」落地即翻开的牌、已翻开后被移入本区的卡（`mv`/`fly`/`shift`/`roam`/换边）都不参与；地形出现前就在本区的旧卡也不追溯。白板（`k: ''`）没有揭示可执行，直接跳过（不记日志、不停顿）。㈡早苗 `retrigger` 再触发的每一条揭示——那一次揭示也发生在守矢神社里 ⇒ 也执行两次（资格实时读被再触发那张牌当前所在区域）。两层相乘正是“总计 6 次”（配方见下方「与卡牌键 `retrigger` 的分工」条）。
- 只执行两次（不是循环）：第 2 次不再递归加倍（保证有限、绝不无限递归）；重复＝对同一张牌再走一次翻牌流程的揭示分派 `resolveCardReveal` ⇒ `bf`/`de`/`ba`/`bl`/`dw`/`dwb`/`dwh`/`dwc`/`spawn*`/`clone`/`delCopy`/`gather`/`give`/`shuffleIn`/`discard`/`reviveDiscard`/`switch`/`gift`/`morph`/`xform`/`mv`/`roam`/`shift`/`costUp`/`energyNext`/`tkBuff`/`deAll`/`retrigger` 等所有揭示键照常重跑。不触发：持续 `og`、时机 `fx`（`turnStart`/`turnEnd`/`gameEnd`/`handEnd`）、`surv`/`phx`/`prot`/`ind`/`fly`；地形类 `gamble` 与 `gust` 也不重跑（那两者是地形写的、不是卡面文字）。
- 五个「分步演出」键重复时照常保留各自的分步间隔：重复「**三妖精集结**」会逐区生成 → 逐区渲染 → 逐区结算该区妖精的揭示（而不是一次性生成三只、并发结算它们的揭示）；同理重复八云紫 `shift`、四季映姬 `reviveDiscard`、东风谷早苗 `retrigger`、绵月丰姬 `delCopy`（摧毁 → 0.3s → 逐张结算复制体的揭示）也各按自己的粒度逐张 / 逐区推进。⇒ 一次重复的总耗时取决于被重复的那张牌的键（按区数 / 张数 × 各自间隔），并与本字段那一道前置停顿叠加；各键的具体间隔见《动画演出与间隔.md》§4。⚠️ 本字段与早苗的“再触发”都必须走共用的揭示分派 `resolveCardReveal`（而不是直接 `applyEffect`），否则会静默退化成同步版、把这些间隔全部吞掉。
- 含法术：法术的自身揭示结算完并不立刻消散，而是「先停顿 → 重复一次 → 才 `vanishSpell` 消散」——故调用点被刻意排在 `revealRound` 里 `vanishSpell` 之前（否则法术已不在场上、无从重复）；重复时它仍占着那 1 个格位，重复结算完才让出。
- 含早苗的 `retrigger`：早苗在守矢神社翻开时，她自己的揭示执行两次（自身翻面 1 次 + 本地形重复 1 次，每次都会把本区己方已翻开卡各再触发一遍）；而她每一次揭示所“再触发”出来的那些揭示也发生在守矢神社里 ⇒ 那些揭示同样各自执行两次。⇒ 总计 6 次（以同区另一张已翻开的揭示牌 A 为例）：A 自身翻面 2 次 + 早苗第 1 次揭示再触发 A 2 次 + 早苗第 2 次揭示再触发 A 2 次 = 6 次。
- 资格按「翻开那一刻」快照认定：`revealRound` 在翻面瞬间就把 `locDef(mv.loc).repeatReveal` 记进局部变量 `repeatRevealHere`，重复时不再重读地形 ⇒ 翻牌途中本列被卡牌 `xform` 换成别的地形（如灵乌路空 → 聚变反应炉）照样重复一次（否则变形类揭示会“吃掉”这块地形的加成）；反之，地形是在某张牌翻开之后才落到本区（如 `collapse`/`xformTurn` 到了回合末/下回合才生效），当回合已翻开的旧牌不追溯。
- 重复时按该牌「当前所在区域」结算（同早苗 `retrigger` 口径）：若它自己的揭示已把它挪出本区（八云紫 `shift` / 幽灵 `roam` / 依神紫苑 `switch`），仍重复一次、只是按挪走后的新区域读盘面（`fieldLocOf` 实时读）；已不在场上（被 `dw` 摧毁、`phx` 回手）则只记一条 `sys` 日志并跳过。
- 与 `gust`（揭示后吹飞）的先后：重复点在 `gust` 之前（并沿用翻开那一刻的资格快照）。⚠️ 实战中同一列只可能有一块地形，故「守矢神社 + 魔力风暴」不会同列共存；这个先后只在“翻牌途中本列被 `xform` 换掉”这类情形下才有可见差别。
- 节奏：重复之前先停顿（与翻牌结算前那道停顿同款，见《动画演出与间隔.md》§4「守矢神社」），重复结算完再 `renderZones()`，让 ±N / 生成 / 摧毁等演出看得出“又触发了一次”；停顿后校验 `state.gen`——重新开局即放弃本次重复（同 `applyShiftReveal` 的中断保护口径）；日志两条：`🔁 <区域名>：重复结算「X」的揭示效果 —— 第 2 次（仅重复揭示；持续与回合开始/结束等非揭示效果不重复）。`，以及“已不在场上故不重复”的例外日志。
- 失去卡牌文字（封印 ∪ 静海）：本字段不发动任何非揭示机制；被重复的牌若此刻已失去文字（被封印，或它自己的揭示把它挪进了静海），`resolveRevealInZone` 会先记一条被抹除日志并跳过（`applyEffect` 入口守卫也有一道，两道都只读实时判定）。
- 非“摧毁”/非增减/非放置：本字段自身不改战力、不动区域字段与格位（`sideUsed`/`sideRoom`/`fill`/`locGaps`）、不触发 `surv`/`phx`/`prot`/`ind`、不进 `powerLog`/`fieldQueue`（被重复的那些效果当然各按自己的口径改盘面）；不是揭示键、`applyEffect` 与 `revealEffectWillChange` 都不需要新分支。
- 与卡牌键 `retrigger`（东风谷早苗）的分工：地形是“本区每张翻开的揭示牌各自动多一次”（不需要有卡、不需要额外卡位、逐张各自判定、随回合持续生效）；早苗是“她自己翻开时主动把本区己方已翻开卡各再触发一次”（一次性、需要那张卡在场、有自己的候选与排除口径）。两者可叠加（早苗在守矢神社翻开 ⇒ 她那批再被重复一整批）。
- 使用者：地形「守矢神社」（🌾，`id: moriyashrine`，max 4，`pick: 1`）。

## 4. 绝对不可操作卡（`un: true`，目前仅隙间）

- 无能量（c=0）、无战力（p=0），不可移动、不可被摧毁、不可被任何效果修改。
- 引擎防护点：区域加成 `aff/cb/all` 对它为 0；`bf/de/ba` 不会给它加/减 buff；`dw` 不可选为目标；`purge`（反应炉）不会波及它。
- 界面层它只是灰色静态格位（≋ 隙间），本就不会进 zone 数组——`un` 是数据级的保险。
- 地形「八云紫的家」的 `gap`（回合结束封格）也不是往 `zones` 里塞隙间卡——它把“该侧可用格数”从后往前逐回合 −1（`locSideMax`），渲染层再把隙间铺出来；因此 `un` 的“不进 zone 数组”口径完好，隙间依旧不会被任何摧毁/移动/换边效果选中。

## 5. 数值与比较口径（读卡力/总点数都走这里）

- `cardPower` = 基础威力 + 永久增益（buff）
- `cardPowerIn` = cardPower + 阵营加成(aff) + 费用加成(cb) + 全区修正(all) + 持续效果(og)；un 卡恒等于自身；⚠️ 所在区域带 `noDown`（蓬莱药局）时，上述实时加成里的负值一律按 0 计（战力影响历史面板同口径）
- `zoneTotals` = （已翻开卡的 cardPowerIn 之和 + 放满加成(fill)）× 区域倍率(mul，`cardZoneMul`：己方该侧的 `mul` 来源，现仅丰聪耳神子 ×2)；⚠️ `fill` 的“放满”按该侧可用格数（`locSideMax` = 地形 max − 已封隙间数）判定，可用格数为 0（被隙间封死）时恒不生效；⚠️ 倍率整体乘在括号外 ⇒ `fill` 一起被翻倍，且不改任何单张卡的战力数字（完整口径见 §1「区域倍率（`mul`）」段）
- `zoneEff` = zoneTotals × dbl，`inv` 反转取负 —— 胜负/领先/总点数决胜统一用该口径
- 区域效果按类型区分口径：倍率 / 终局类（地形的 `dbl`、卡面的 `mul`）只乘进结算用的总战力、不改卡牌自身数字（`dbl` 双方同乘，`mul` 只乘源卡所属的一侧）；阵营 / 费用 / 全区加成型（`aff`/`cb`/`all`）算作卡牌的实时威力，会显示在卡面右上角与“战力影响历史”里；⚠️ 所在区域带 `noDown`（蓬莱药局）时，这些实时加成中的负值按 0 计（免减攻，`locRoleBonus`/`locCostBonus`/`locAllBonus`/`cardAuraBonus` 四处 clamp）
- 增减口径：永久 ±N 的唯一收口是 `applyPermBuff(card, d, srcCard, tag)`（改 `buff` + 写 `powerLog` + 排 ±N 演出），因此地形「蓬莱药局」的 `noDown` 只需在这一个入口拦 `d < 0` 即可覆盖所有“减攻”来源；该函数有返回值（`true` = 已结算 / `false` = 被免减攻拦下），供调用方调整汇总日志
- 暗牌口径：暗牌不显示不计入总点数（翻面后计入）；揭示增减（bf/de/ba）与 dw 只作用于结算时已翻开的卡牌。
- AI 估值的信息口径分档：普通 / 困难档只按已翻开的牌估值（不看你的暗牌，对暗牌取乐观口径），噩梦档才 `includeHidden` 全量可见（能读到暗牌战力）。
- 法术：`cardPower` 与 `cardPowerIn` 对 `spell: true` 的卡恒为 0（不吃基础战力以外的任何加成，也不吃增减）；它占格按 1 计（`occOf` 归一），因此影响 `sideRoom`／放满加成 `fill` 的判定，但不给本区总点数贡献任何点数。
- 费用：`cardCost(card) = max(0, def.c + (card.costMod || 0) − (def.costDown || 0) × destroyCount() − (def.costDownP ? def.costDownP.n × fieldPowerCount(card.side, def.costDownP.min) : 0))`。印刷费用 `def.c` 是唯一的“档位”口径（卡组曲线与排序、区域 `cb` 费用加成、图鉴/卡组页/「指定卡牌」筛选、`discard.cost`/`og.cost` 匹配都用 `def.c`）；实际能量消耗（出牌扣能量、能否负担、撤回返还、AI 扣能量与估值、手牌费用角标）一律读 `cardCost`。`costMod`＝本场战斗的实例级加费（`costUp`）；`costDown`＝卡级持续减费（纯狐：每张进摧毁池的牌 −N，下限 0）；`costDownP`＝卡级持续减费（星熊勇仪：自己场上每有一张已翻开、实时战力 ≥ `min` 的卡 −N，下限 0）；`destroyCount()`＝双方摧毁池合计张数、`fieldPowerCount(side, min)`＝该方场上已翻开且实时战力 ≥ min 的卡张数

  - 界面：侧栏 `#sidePanel` 第一个区块 `#pileCard`（`index.html`，「地形区域的下方、对手信息的上方」——桌面端侧栏在场地右侧，≤900px 侧栏整体排在场地下方），内含两按钮 己方特殊牌池 / 对手特殊牌池，各带合计张数徽标（三池合计，分项写在按钮 `title` 里）。弹窗 `#pileMask`：顶部三切换按钮（摧毁池 / 弃牌池 / 放逐池，标签与张数由 `buildPileTabs` 从 `PILE_KINDS` 渲染），下方按入池顺序（旧 → 新）用卡面网格列出该方该池的牌——每张下方一行「`#N` 入池序号 + 第几回合入池」小字，悬停显示完整元数据（来源 / 区域 / 入池时战力），点击复用 `showHandCard` 放大查看（关掉放大层仍回到牌池弹窗）；空池显示对应说明（弃牌池写“本局还没有牌被弃掉”）。三池卡牌尺寸完全统一：网格用固定轨道宽 `--pile-card-w`（116px，≤640px 缩为 92px）并整体居中，卡内各段固定（顶部角标行 26px、艺术区正方形、卡名预留 2 行、效果文字固定 2 行截断）——“同宽 ⇔ 同高”。关闭＝✕ / 点遮罩空白 / Esc（接入 `initOverlays` 逐层关闭链）。刷新由 `renderPiles()` 负责（侧栏徽标 + 弹窗开着时的列表），调用点＝`renderZones()` 末尾与入池收口；样式在 `style.css`（`.pile-card`/`.pile-btn`/`.pile-modal`/`.pile-cell`/`.pile-cap`/`.pile-ord`，弹窗其余复用 `.codex-modal`/`.chip`/`.codex-grid`/`.codex-empty`）。
