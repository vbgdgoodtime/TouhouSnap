## 1. 一局游戏的结构

- **主页面（首页）**：打开游戏先显示主页面（`#homeScreen`；`<body class="in-home">` 时全屏显示），不直接进对局。**七个主入口**（下列即 `index.html` 里的先后；其中「图鉴」当前隐藏，界面上看不到）：
  1. **开始对战** —— 先弹出出战卡组选择弹窗（`#battleDeckMask`）：按卡组栏同序（创建时间倒序）列出已满 12 张的卡组，卡组位只显示卡组名（12 张信息在悬停提示里）；点选一套后点「开始战斗」才隐藏主页面并调用 `Game.restart({ playerDeckDefs })` 开新对局（玩家用该组卡洗牌入局，对手仍随机；无满编卡组时提示并引导「卡组设置」）。顶部「重新开始」复用上一局所选卡组。
  2. **联机对战**（`#homeBtnNet`，🌐，`.home-btn.net`＝淡蓝渐变底 + 深蓝字，与「开始对战」同款写法：无边款 + 渐变 + 光晕投影）—— 点入口**先选一套满 12 张的出战卡组**（复用 `#battleDeckMask`），**选完才打开**房间弹窗 `#netMask`：创建 / 加入 6 位房间码，**双方都处于「已准备」**（准备是可撤销的开关，房主与加入者各自都能取消）后由房主定种子开局；房间只转发消息、对局在两端浏览器里各算一遍（每回合对账），见 `js/net.js` 与 `docs/联机对战.md`。
  3. **开发调试**（`#homeBtnDev`，🎛️，`.home-btn.dev`＝淡绿渐变底 + 黑字）—— 进入开发调试对局（`js/dev-page.js`，`window.DevTools.open()`）：不检查满编卡组、不弹出选出战卡组，直接隐藏主页面并 `Game.restart({ emptyPlayerDeck: true })`；玩家牌库为空（开场不发牌，可用顶栏「指定卡牌」等调试）；每回合能量固定 10；三块真实地形固定「无名之丘」；AI 每回合不出牌（仍抽牌）；顶栏隐藏「修改能量 / 图鉴」，提供「⇄ 切换立场」（开启后落牌进敌方区且归属对手，再点恢复）；`body.in-dev` 标记本局，回主页清除。
  4. **卡组设置** —— 进入卡组设置页面（`#deckScreen` + `js/deck-page.js`，`window.DeckBuilder`，见下条）。
  5. **图鉴**（`#homeBtnCodex`，📚，样式复用 `.home-btn`）—— **当前隐藏**：按钮带 `hidden` 类（标记与 `js/home.js` 的 `openCodex`/`closeCodex`/`isCodexOpen` 接线都保留，删掉该类即恢复），对局顶栏「📖 图鉴」不受影响。恢复后它的行为是：不进对局，只打开既有图鉴弹窗 `#codexMask`（与对局顶栏「📖 图鉴」是同一个弹窗，实现在 `js/card-browser.js` 的 `window.CardBrowser`；两层筛选「普通卡牌池 / 衍生卡牌池」与全部卡片渲染共用同一套；卡池内按费用↑ → 战力↑ → 卡名字典序排序，见 `docs/现有机制.md` §6）。点卡放大复用 `#zoomMask`；关闭＝弹窗内「关闭 ✕」/ 点遮罩空白 / Esc（Esc 逐层：先放大层、再图鉴层）；打开时先关掉新手引导 / 设置 / 出战卡组弹窗，互斥不叠层。
  6. **设置**（`#homeBtnSettings`，⚙️，`.home-btn`）—— 主入口列里紧接「卡组设置」下方（两者之间的「图鉴」格当前隐藏），副标题由 `js/home.js` 同步为「昵称 / 头像 · 对手 AI 强度：<当前档位>」；不进对局，只弹出 `#settingsMask`（两节：**玩家资料**与**对手 AI 强度**）。**玩家资料**＝联机时显示给对手的昵称与头像（昵称≤12 字、去 `<>&"'` 与控制字符；头像从**已有卡图**里挑一张，选项由 `js/home.js` 的 `avatarDefs()` 从卡池现算并复用图鉴的卡池排序），存在 `localStorage: touhou2.player.v1`，随握手 `hello` 的 `name` / `avatar` 与对手交换（对手那头还会再用本机卡图清单核对一遍，对不上退回 👤）。切换**对手 AI 强度**：四档 简单（默认）/ 普通 / 困难 / 月狂（`AI.LEVELS`），点选即生效（本局与后续对局同强度）并经 `window.AI.setLevel()` 写入 `localStorage: touhou2.ai.level`；四档的选项与逐档说明取自 `js/ai.js` 的 `window.AI.LEVELS`（`name`/`desc`/`tip` 是这几项文案的唯一数据源，只写中性难度感受；技术口径在 `LEVELS[key].tech`，仅供控制台/文档；`index.html` 只留按钮副标题静态兜底与引导页名称列举），顺序取自 `AI.ORDER`、默认档取自 `AI.DEFAULT_LEVEL`，界面只渲染 `.ai-level-opt` 按钮组（当前档加 `.on` 与「当前」徽标、默认档在非当前时带灰色「默认」徽标）。「简单」档跑贪心 AI（见 `docs/现有机制.md` §6 AI 策略条）。关闭＝「关闭 ✕」「知道了」/ 点遮罩空白 / Esc；交互在 `js/home.js`（`openSettings`/`closeSettings`/`isSettingsOpen`/`setAiLevel`/`currentAiLevel`），样式在 `style.css` 的 `.settings-modal`/`.settings-body`/`.ai-level-list`/`.ai-level-opt`。
  7. **挑战码**（`#homeBtnChallenge`，🔗，`.home-btn`）—— 主入口列的末项，紧接「设置」下方：打开挑战码弹窗 `#challengeMask` 的**导入形态**（粘贴朋友的码 →「看复盘」/「挑战同一局面」）；导出形态（把本局变成一行码）在结算弹窗的「📤 生成挑战码」上；码格式与重放口径见 `docs/联机对战.md`。
  8. **新手引导**（`#homeBtnGuide`，虚线描边的轻量按钮）—— 主页面最下方的次级入口，位于主入口列之下；不进对局，只弹出只读的机制速览弹窗 `#guideMask`（静态标记在 `index.html`，交互在 `js/home.js` 的 `openGuide`/`closeGuide`/`guideStartBattle`）：8 个小节＝目标 / 回合与能量 / 暗出→翻牌→揭示 / 地形 / 卡牌效果两类口径（揭示 vs 持续，含法术）/ 赌注与认输 / 各入口怎么用 / 小提示。关闭＝弹窗内「关闭 ✕」「知道了」/ 点遮罩空白 / Esc（Esc 优先关它，其次才是设置弹窗与出战卡组弹窗）；弹窗内「⚔️ 开始对战」→ 关掉引导后走既有的「选出战卡组 → 开战」流程。样式见 `style.css` 的 `.home-guide-btn` / `.guide-modal` / `.guide-body`。
- 首页各弹窗都由 `body.in-home …:not(.hidden)` 一条 `display: flex` 放开显示，层级：放大 214 / 图鉴 213 / 挑战码 212 / 联机房间 212 / 新手引导 212 / 设置 211 / 出战卡组 210（同层时 DOM 靠后的盖住靠前的；Esc 逐层关闭：新手引导 → 设置 → 出战卡组弹窗，联机选卡组正是这个弹窗）。
- 引擎侧 `js/game.js` 底部的启动 `restart()`：游戏在后台完成首局初始化并停在玩家出牌阶段等待输入（不自行推进），玩家点「开始对战」时再重开一局。主页面交互在独立文件 `js/home.js`（`window.Home`：`show()`/`hide()`/`startBattle()`/`openPage(key)`），页面注册表见该文件 `PAGES`；任何页面都能用 `Home.show()` 返回主页。
- **卡组设置页面**：版面为上方 1/3 卡组栏 + 下方 2/3 卡牌区（整页纵向 flex，`flex:1` : `flex:2`）。卡组栏两种形态：
  1. **浏览态（默认）** —— 动态列表：只渲染「＋ 新建卡组」位与已创建的卡组位（无固定空位），每新建一套就动态扩展出一格（新卡组位播入场动画，横向滚动）；顺序为创建时间倒序——「＋ 新建卡组」固定最左，越晚创建越靠左、越早创建越靠右（`DECKS` 内部仍按创建先后追加存储，仅渲染反序）。容量上限 20 套（`DeckBuilder.MAX_DECKS`），每套张数按牌库口径 12 张（`DECK_SIZE`）。卡组位显示卡背叠放缩略 + 名称 + `N/12`；点「＋ 新建卡组」追加一套空卡组（默认名「新卡组 N」，并自动选中）；点卡组位任意位置（含图片）直接进入编辑态；满 20 套后新建位置灰并提示。卡组位缩略图右上角悬浮 🗑️ 删除按钮（桌面端悬停 / 键盘聚焦时淡入，触屏无 hover 故常驻，隐藏时连 `pointer-events` 一并关闭）。
  2. **编辑态** —— 卡组栏换成该卡组的 12 个卡槽：已放显示卡面（点它即移出卡组），未放显示虚线「幽灵卡」空位 + 序号；顶部「✏️ 改名」「🧹 清空卡组」「💾 保存」三个按钮，标题行只显示卡组名 + `N/12`（金色区分于浏览态的「我的卡组」；满 12 张数字转绿）。改名：点「✏️ 改名」弹出 `#deckRenameMask`（输入框预填原名并全选；回车 = 确定，Esc / 点遮罩 = 取消），校验不能为空、最多 12 字、不得与其他卡组重名（不通过时弹窗内红字提示且不关闭）；确认后卡组位名称、标题行与悬停提示即时刷新并写入本地。卡槽为自适应网格：宽屏 1 行 12 格，≤1000px 改 2 行 × 6 格，≤700px 卡槽缩小（不显示效果文字，费用/战力角标与卡名同步缩小）+ 顶部按钮只留图标。空卡槽与已放卡槽尺寸完全一致（内部同为角标行 / 正方形立绘区 / 卡名行三段 `.dcs-top`/`.dcs-art`/`.dcs-hint`，边框宽度相同），卡组空或满时高度不变；编辑态上栏按内容自适应高度（`flex: 0 0 auto`，极端矮屏以 `max-height: 62%` 兜底、由卡槽区纵向滚动）。下方卡牌区：左键 = 加入卡组（已在卡组里的卡牌加灰色遮罩、不可点击；移出一律走「点上方卡槽」），右键 = 放大查看；同名卡限 1 张，满 12 张时加入会提示先移出一张。编辑中改动先留在内存；每次加入/移出一张卡后立即按费用升序 → 同费用战力升序 → 卡名字典序重排卡槽；点「💾 保存」（或 Esc / 返回主页）时经 `js/deck-storage.js` 写入 `localStorage`（键 `touhou2.decks.v1`，卡以卡名序列化）并退出编辑态。启动时自动从本地读回；新建/删除/改名即时持久化。
  3. **卡牌区（`#deckFilter` + `#deckGrid`）** —— 费用筛选条扁平一排（全部 / 0-1 费 / 2 费 / 3 费 / 4 费 / 5 费 / 6 费+ / 衍生卡牌；「6 费+」＝6 费及以上）；「全部」与费用档展示 `POOL` 人物卡（0~8 费），「衍生卡牌」展示 `SPECIAL` token（不含隙间），仅可查看、不可加入卡组（虚线描边）；浏览态左键 / 任何状态右键 = 复用既有 `showZoom()` 放大查看，编辑态对人物卡左键加入卡组。筛选档在打开/关闭页面间保留。⚠️ 游戏图鉴与开发者「指定卡牌」的筛选为两层（卡池：普通卡牌池 / 衍生卡牌池 → 池内 1~6 费档，见 `docs/现有机制.md` §6），本页筛选结构为上面这条扁平筛选条；本页卡池与 12 个卡槽的展示顺序与图鉴一致（费用↑ → 战力↑ → 卡名字典序，比较器复用 `window.CardBrowser.orderDefs`）。
- 开局预置两套占位卡组（占位卡组 A/B，`cards` 为空 → 显示 `0/12`，仅本地无存档时）。删除卡组：点 🗑️ → 确认弹窗 → 从 `DECKS` 移除、收回一格、刷新计数与「当前卡组」（删的正是选中/编辑中的卡组则改选最近创建的一套 / 退出编辑态）并写入本地。确认弹窗（`#deckConfirmMask`，`openConfirm({emblem,title,lines,okText,danger,onOk})`，删除与清空共用）复用游戏弹窗样式，z-index 50 盖在卡组页之上；文案用 `textContent` 组装；「取消」/ 点遮罩空白 / Esc 均不执行。页面层级 `z-index 45`，低于游戏弹窗（`modal-mask` 50 / `zoom-mask` 60）；进入本页与主页面一样由 `body.in-deck` / `body.in-home` 隐藏游戏区，页面内「← 返回主页」→ `Home.show()`（离开时若仍在编辑态会先保存）。
- 共 **6 回合**；地形「虚假之月」🌕 在场时为 **7 回合**，第 7 回合双方能量 **7**（实时判定、被变走退回 6、一旦进入第 7 回合则锁定打完；完整口径见 `docs/现有地形.md` 的「区域『延长回合』」段）。第 1 回合能量为 1，之后每回合 +1，上限 6（即第 6 回合能量 6；有虚假之月时第 7 回合为 7）。
- **能量分边**：敌我各自持有 `energyTotal`（本回合上限）与 `energyLeft`（剩余）；回合开始双方写入相同基数，互不影响。能量是当回合预算：一回合内可暗出任意多张牌，只要本方费用总和 ≤ 本方当回合能量；用不完的能量不累积到下一回合，也不转给对方。
- 出牌流程：玩家不断「选手牌 → 点区域」暗出（牌背显示 ?），点「结束回合」把回合交给对手；对手 AI 按估值把能量花在有价值的地方（效果估值 + 回合级束搜索，候选里含「不出牌」；见 `docs/现有机制.md` §6「AI 策略」条）。
- **翻牌先后（先手）规则**：
  - 第 1 回合**随机**决定谁先翻开；
  - 第 2 回合起按“结算胜利标准”判当前领先方（只统计已翻开的牌，判据见 §3）：当前领先（赢下区域更多，或存在平局区域时三区总点数更大）的一方先翻开；
  - 按该标准双方打平（如三区皆平且总点数相同）则继续随机决定先后；
  - 同一方内部的多张牌严格按出牌（放置）先后翻，与谁先无关。
- 每张暗牌翻面后才把战力计入区域总点数（含全部修正），总点数随翻面实时上升；终局时所有牌均已翻开，口径一致。
- **地形揭晓**：开局三块区域一律先以「未揭示」地形展示（❓，无特殊效果、max 4、中间带文案「未揭示地形」；外观用专属“随机未知”主题——淡紫灰底 + 随机散布的地形小图标）；三块真实地形已在开局按 `pick` 权重抽定（互不相同）并预存，第 1 / 2 / 3 回合开始时依次揭晓到左 / 中 / 右列——揭晓瞬间换上真实地形（上限 / 加成 / 反转 / 回合末摧毁等全部字段与列头配色即刻生效），并结算该地形的「出现时」一次性效果（如虹龙洞在揭晓时给双方各生成 1 张石块）。未揭示地形可正常放牌（每侧上限按 4 计），列下方提示「🃏 第 N 回合揭晓」；地形效果自揭晓起作用——此前已放下的牌在揭晓后按现盘面即时受其影响（不追溯撤销、不加不删）。揭晓时播放 **500ms 换场演出**（未揭示外观淡出、真实地形显形）。
- **限张地形揭晓超限口径**：若揭晓成上限 <4 的地形（现仅迷途竹林 max 2）而某侧此前在未揭示期已放了超过上限的卡（只有第三列可能：前两回合每侧至多放 3 张）——不摧毁、不移走任何卡，已放卡保留原格位；隙间只铺在“空置的不可用格位”，数量 = 4 − max(已放张数, 上限)（放 3 张 → 1 个隙间；放满 4 张或整侧被大体积卡占满 → 0 个），此后该侧视为已满、不可再放。⚠️ 另有主动减少可用格数的来源——地形「八云紫的家」（`gap:1`）每回合末双方各从后往前封 1 格隙间（下限 0、该侧放满则不加、换地形即清空）；两者共用同一渲染出口，引擎侧统一读“该侧可用格数”（`locSideMax`），详见 `docs/现有机制.md` §2 与 `docs/现有地形.md`。
- 每块区域双方最多放 4 张（特殊区域可能更少，超限口径见上条），**最后一回合**（无虚假之月为第 6 回合、有则为第 7 回合）翻面结束后立即终局结算。
- **重置暗牌（撤回）**：出牌阶段内（本回合暗牌尚未翻面时）点击底部居中的「能量：x/N」块（`#energyChip`），确认后将本回合已暗出的牌按放置前的手牌顺序放回并全额返还能量；只影响玩家自己的暗牌，不改动对手已暗出的牌。确认弹窗可按「取消」放弃，点遮罩空白或 Esc 同样关闭。
- **场地展示口径**：每个玩家区域固定为 2×2 四个格位，按「左上 → 右上 → 左下 → 右下」依次落牌，第一张牌永远占最左上格，不会因后续放牌而移动；卡牌放大铺满各自格位。所有区域（无论允许放几张）敌我两侧都会用浅灰网格线画出 2×2 格子（max=4 时空格位显示浅灰虚线框）；允许数量 <4 的区域，不允许放卡的格子（右下往后的格位）会铺灰色「隙间」占位卡——隙间由渲染层铺在空置的不可用格位（开局三列先以 max 4 的「未揭示」展示故无隙间，揭晓成限张地形后自动出现；已放卡超上限时数量自动减少，见 §1 超限口径），且不可点击/不可操作。桌面卡缩略图上：左上角为白色费用，右上角为当前战力——与基础威力相同显示白色，更高显示绿色，更低显示红色。每个区域按「对手区 → 对手总点数 → 区域效果 → 己方总点数 → 己方区」纵向排布，两个总点数横幅显示该区当前受全部效果修正后的最终战力（与终局结算同口径，含区域倍率），并随谁领先动态着色：领先方亮黄色、另一方/平点为蓝色。
- **场上卡牌检视**：已经翻开的敌我卡牌可以像图鉴一样点击放大查看：卡面左上角费用、右上角威力都是该牌受修正后的当前值，弹窗详情区不重复这两个数字与效果说明；弹窗**顶部**独立一条「战力构成」段，逐枚列出该卡当前全部战力来源——印刷威力 → 永久 buff 台账（按施加先后，来源显示为施加方卡牌，自身效果显示"卡牌效果"）→ 持续效果（分来源、实时，源卡离场即消失）→ 区域加成（阵营/费用/全区，实时），每枚「±N ＋ 来源」成一小方块、末枚为合计（＝卡面右上角的实时威力）；提高 +N 绿色、降低 −N 红色；来源多时该段左右滑动；暗牌不可点击。

## 2. 牌库与抽牌顺序

**玩家**：出战使用自建满编卡组（12 张具体卡已定）；开局把这 12 张纯随机洗牌后入牌库。无自建卡组时的兜底随机曲线为 `1×3, 2×3, 3×2, 4×1, 5×1, 6×2`（各费从卡池随机抽、同费用不重复，抽牌顺序同样纯随机）。

**对手（AI）**：玩家进入对局瞬间，按费用结构 `1×2, 2×3, 3×3, 4×1, 5×1, 6×2` 从人物卡池每种费用随机抽（同费用不重复）组成 12 张，再纯随机洗牌。

**局中牌库可变**：卡牌效果可以把牌洗入某一方的牌库（效果键 `shuffleIn`：自己或对手）——加入后该方整副牌库重新随机洗一次，“下一张会抽到什么”随之改变；牌库张数没有上限（手牌才有 7 张上限），被洗入的牌不结算任何效果，要等它被抽到手、再被暗出翻开时才按常规流程结算。机制细则见 `docs/现有机制.md` §1「洗入卡组（`shuffleIn`）」段。

每回合（**含第 1 回合**）开始时双方各从牌库抽 1 张；开局另有 3 张在开场逐张发放（附入场动画）：即玩家首回合手牌共 **4 张**，随后每回合再各抓 1 张。

## 3. 胜负与赌注

- 终局逐区域比较最终战力：战力高者赢得该区域；**「辉针城」等反转区域相反（战力低者胜，决胜总点数按负值计入）**；相等则记为平局区域。
- **胜负判定分两种情况**：
  1. 只要存在平局区域（一个或多个区域平手）→ 按三个区域的总点数（各区最终战力之和）高低决胜，总点数高者获胜；总点数也相同才是平局。
  2. 完全没有平局区域 → 直接比较赢下的区域数，3 块中赢下更多（≥2）的一方获胜（无平局时双方区域胜数不会相同）。
- 同一套判据也用于回合初判定“当前领先方”，决定翻牌先后（见 §1）；双方打平则随机。
- **赌注＝结算值 = 2 × 2^(本局加倍人数)**：无人加倍 **2 立方**、一人加倍 **4**、两人都加倍 **8**。双方**各有一次**「加倍」权、整局限用（AI 永不使用）。
- **加倍在宣布的下一回合开始才生效**，但宣布当回合侧栏就显示新值（预告）；从宣布到生效回合结束之前，撤退一律按**加倍前的值**结算——留给对手一个完整回合考虑要不要撤退。**末回合宣布加倍**没有"下一回合"可等，直接按新值结算。
- 「认输」立即判负，按上面的撤退价扣除赌注（例如对方刚宣布加倍、你在他生效前认输，只输加倍前的值）。终局赢家拿走结算值（胜利 +N，失败 −N）；平局无立方变动。
- **终局演出**：最后一回合（无虚假之月为第 6 回合、有则为第 7 回合）全部结算后，先等场上遗留的 ±N 加减动画播完，再依左→右顺序依次把每个区域的胜方总点数横幅做 **700ms 放大高亮**（金色光晕，`settle-win`；区域间隔 **150ms**；平局区域跳过），三个区域演出全部结束后才弹出结算弹窗。
